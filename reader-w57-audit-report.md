## 3. БАГ #3 (критичный, потеря данных) — storage guard

**Где:** `js/site-utils.js:785` `installHighlightStorageGuard()`, устанавливается без условий в L833.

**Механика.** Функция переопределяет `Storage.prototype.setItem`: при каждой записи в `gb-highlights-v1` она повторно дедуплицирует массив по **легаси-ключу** `canonicalPage(url) + '\n' + normalizeQuoteText(text)` (логика до 017c1ad).

**Эффект.** Две независимые пометы одной и той же фразы из разных абзацев (annotation v1, разные диапазоны; штатный `GBHighlights.dedupe` по range-ключу корректно сохраняет обе — проверено напрямую) при записи проходят через guard: `gbAddHighlight` **prepend**-ит новую запись, guard оставляет первую встреченную (новейшую) и **молча удаляет старую**, а UI показывает «Помета сохранена в библиотеке.» — ложный успех.

**Доказательства (браузер):**
- `setItem([r1, r2])` с разными range-ключами → в storage остаётся 1 запись;
- UI-поток: две пометы одной фразы → на панели одна карточка, «Пометы 1» (кадр `P1_two_marks_same_phrase.png`).

**Значение.** Исправление 017c1ad (независимые range-якоря) в реальном использовании **не работает** — guard откатывает его на каждом write.

**Варианты фикса** (все в `site-utils.js`, бюджет highlights.js 26 000 B не затрагивается):
1. **Минимальный:** в `dedupeHighlights()` пропускать записи с `annotation.version === 1` (они уже дедуплицируются на write-пути по range-ключу).
2. **Key-aware:** для v1-записей использовать тот же range-v1 ключ, что и `GBHighlights.highlightKey`.
3. **Удалить guard полностью:** highlights.js дедуплицирует и на чтении (`getAll`/`dedupe`), и на добавлении; единственная ценность guard — разовая чистка легаси-дублей при загрузке, её можно оставить только как one-time миграцию.

Рекомендация: **1** (минимальный риск) или **3** (чисто). После фикса — повторный прогон `w57-limits.mjs` (coexist + dedup-сообщения) и desktop-секции M+N.

## 4. БАГ #1 (низкий) — рассинхрон счётчика

При удалении последней пометы страницы бейдж «Пометы N» не обновляется. Причина: обработчик в bubble-фазе использует `e.target`, который уже отсоединён после ре-рендера. Фикс: capture-фаза / `composedPath()` (~48 байт) — ровно запас бюджета highlights.js (25 952/26 000). Альтернатива без давления на бюджет: перенести синк в site-utils.
