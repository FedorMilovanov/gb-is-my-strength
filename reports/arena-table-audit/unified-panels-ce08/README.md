# Единый Reader: общий движок и панели, индивидуальная стилистика

## Решение владельца и статус

Пользователь уточнил: **не одинаковый визуальный дизайн, а один движок и общие TOC, левая и правая выдвижные панели**, с разными цветами, рисунком и оформлением для серий/статей. Этот документ — архитектурный план и проверка состояния, **не Product patch и не разрешение на глобальное включение**. Нужны общие панели как компоненты/поведение, не только похожие заголовки и не отдельный контроллер на каждом оформлении. При этом «общие» не значит принудительно одинаковые данные, размеры, шрифт или тему.

## Что реально существует сейчас: панели ≠ один движок

Источник: `SeriesReaderChrome.astro` монтирует `GillSeriesRail` и нативные mobile controls; standalone `ReaderRail.astro` имеет отдельный rail/controller. W57 research `reader_universal_preview.js` создаёт `#npUOutline` и `#npUResearch`, но для series в проверенном preview показывает исходный `#gbs2Toc`, а preview `#npUOutline` скрыт; на проверенных standalone показывает W57 outline, а старый `#hrailToc` не занимает площадь. В обоих случаях правая W57 панель — `#npUResearch`. **Это не доказательство, что левая панель уже единый production-компонент**; именно здесь нужна дальнейшая общая композиция и замена дублирующих lifecycle с сохранением каждого скина.

Независимый узкий пробный запуск на ce08: Chromium 153 Linux, desktop 1440×900, реальный `preview.py`, `?paper=space&panel=open`, SW blocked, отдельные contexts. Gill II, Heart/book, Baptist chapter и Teen: один видимый `#gbs2Toc`, W57 outline скрыт; Герменевтика и Kod da Vinci: один видимый W57 outline, старый `#hrailToc` без площади. Во всех 6 правая панель последовательно видима → скрыта → видима настоящим кликом `#npUEdgeToggle`, `aria-expanded` true → false → true, pageerrors 0. [Шесть полных наблюдений](panel-results.json), [проба](panel-probe.mjs). Наличие скрытого DOM не означает второй активный контроллер; его event/focus/scroll ownership отдельно требует аудита. Это не визуальная оценка и не проверка всех interactions.

[Surface inventory probe](surface-results.json): 10 выбранных маршрутов × 390/1440 × прямой dist/preview. Direct dist не содержит `np-w57-ready` на этих примерах; preview создаёт W57 на desktop для шести проверенных article/chapter маршрутов, но не для проверенных `/articles/`, `/updates/`, `/nagornaya/chast-1/`, `/karty/avraam/`; 390 остаётся native. Проверка снимка после 700ms с закрытым по умолчанию right не доказывает видимость панелей и не является полной приёмкой; отдельная шестимаршрутная проверка выше использует `panel=open`. Проверены только перечисленные URL, без Pagefind index и функционального теста контента. HTTP 200/нет pageerror в 40 контекстах; 390 no document overflow. Страницы с `scrollWidth < clientWidth` на desktop не считать overflow.

## Целевая композиция (контракт, не новый независимый движок)

```
route ownership + profile + explicit cohort flag
  → family adapter {surface, shape, sections, capabilities, theme, editorial slots}
  → один Reader core: state / projection / anchor / preferences / overlay / actions
  → единый shell и panel lifecycle
       ├─ левая панель: общий TOC + раскрытие/активный путь/история
       ├─ центральная область: авторский article + ReaderProjection
       └─ правая панель: общая Analytics / контекстные capabilities / Library
  → темы/slots/токены конкретной публикации, без новых storage и event owners
```

1. **TOC:** единая модель `readerTocProjection` + один действующий scrollspy/history owner и один набор panel controller API. Series flat: часть→H2/H3; book: глава→статья→H2/H3 и сохранение реальных satellite routes; standalone: H2–H6 в допустимой иерархии. Ссылки, id, римские метки, исторические закладки и URL не переписываются. Один активный section и честное различие «эта статья/серия». Не генерировать догадки о несуществующих заголовках.
2. **Левая панель:** общий shell, fold/open/close, доступное имя и состояние, клавиатура/focus, восстановление после resize, прогресс и scroll контейнер. Те же функции доступны на разных темах и в mobile sheet, но визуальный компонент может принимать токены/slots; на первой фазе старый rail остаётся обратимым адаптером к общему controller, а не скрытым конкурентом. Сохранить текущий W57 layout и article text axis.
3. **Правая панель:** общий shell и единый Analytics controller; разделы Scripture/понятия/ход текста/сноски/пометы/quiz показывать по данным и разрешённым capabilities, не рисовать вымышленные разделы или пустые данные. Левое/правое раскрытие независимо, одна позиция/scroll owner; opener/focus/aria/inert/Escape и возврат после ориентации одинаковы. Desktop rail и mobile sheet — разные presentations одного state, не два quiz/notes/search owner.
4. **Скины:** семантические переменные для paper/ink/muted/accent/border, шрифты и типографика, оформление карточек/иконок/фоновых текстур/обложек и editorial slots задаются adapter/theme. Preserve samizdat, книжные и standalone отличия, light/dark/sepia; не применять blanket фильтр изображений. Контраст, читабельность, реальный 44px hit, keyboard и безопасность данных — неизменяемые инварианты. Нельзя считать замену всех тем одним стилем выполнением запроса.
5. **Остальные owners:** `GBReaderPreferences`, `ReaderActionsRuntime`/TTS, `GBReaderProjection`, Pagefind, Product Library/`GBReaderAnchors`, existing quiz и OverlayRuntime переиспользуются; migration переводит/отключает старых владельцев по одному, а не подписывает новый параллельный контроллер поверх них. Snapshot — source evidence; verified occurrence locator до навигации обязателен. Запись заметок fail-closed до cross-tab/ошибок и понятного сохранения черновика.

## План по транзакциям: что, куда и когда

**A. Реестр и карта owners, read-only.** Профили + импортный граф + page-ownership + фактический dist → одна диагностическая таблица на URL: тип источника, current renderer, left/right/mobile controller, TOC shape, theme, зависимости и владелец, flag/rollback и исключение. `mobileChromeRegistry.ts` не полон, но его `static` vs `registry` и явные `backHref`/sticky исключения существенны. **Не** генерировать по `surface → engine` вслепую и не подключать разом 31 страницу: возможны двойные верхние бары, каталоги, защищённые зоны и иные семантические роли. Сначала diff реестра против реальности и ручная классификация, затем CI на непротиворечивость; capability classification не равно разрешение injection.

**B. Общий поведенческий контракт панелей.** Source inventory для `GillSeriesRail`, `ReaderRail`, W57, mobile Analytics/TOC, OverlayRuntime: какой обработчик, state и scroll/focus owner используется в каждом состоянии; негативные тесты повторной инициализации/двух владельцев. Выделять поведение через совместимый единый API, сохраняя разметку и визуальные tokens до доказательства паритета. Пользовательский запрос требует именно общей панели **в конечном состоянии**; временный adapter — миграционный мост, не финиш.

**C. Вертикальный пилот OFF-by-default.** По [W117](https://github.com/FedorMilovanov/gb-is-my-strength/pull/2352#issuecomment-7089647252) — `/baptisty-rossii/dva-sezda-1884/` + `/articles/podrostok-za-kadrom-dvoynaya-zhizn/` (Teen согласовать с #2368), один adapter поверх Snapshot/State/Anchors и настоящий desktop-путь в production-like сборке, **без `preview.py`**. Проверить две реальные `2 Тим. 2:22` в разных Teen-разделах, одно и то же источник/вхождение в mobile и desktop; отказ на неоднозначность и изменённое содержимое. Baptist в нашей проверке не содержит этой буквальной ссылки, не добавлять ложный текст. Подход к включению: exact allowlist + global and per-cohort kill switch, no-op OFF, return к прежним панелям без потери данных. Детальная матрица сохранности в [предыдущем исследовании](../universal-reader-rollout-527/).

**D. Пилот общего TOC/панелей с темами.** На Gill flat и одном book/Teen маршруте сначала read-only данные и подмена одного UI owner с сохранением старого через флаг. Потом standalone Hermenevtika/Kod через тот же core и panel API, свой theme adapter. Доказать: слева/справа независимо open/close, 4 комбинации, поочередное быстрое переключение, Back/Forward, фокус/inert и восстановление, источники, настоящая выделенная цитата/заметка/quiz; до и после screenshot сравнение, 320/390/768/1120/1121/1440/1920, light/dark/sepia и zoom. Изменения W107/accepted UI и серия-своеобразие не переписывать без отдельного решения. Full completion = общий controller/panel composition плюс один live owner, не одинаковый screenshot.

**E. Волны остальных допустимых article families.** Для каждого семейства: авторитетный источник, shape/темы, eligibility, функциональные отсутствия, owner, SHA и tests; один-два представителя, затем остальная когорта; только после принятия предыдущей. Отдельные страницы и landing получают только подходящие capability, а не article TOC/notes по умолчанию. Не вливать NEWS/G3/JOURNAL, Нагорная, карты/immersive приложения и хабы в article-panel runtime автоматически. Для намерения общей инфраструктуры на этих владельческих поверхностях — отдельное разрешение и совместимые capability adapters; визуальные и редакционные движки остаются автономными.

**F. Релиз и rollback.** Согласованное объединение Reader/main/SYS, сохранение SYS dossier 35 min, OG **и rail cover**, final-source regeneration для индекса, assetUrl/hash/SW и проверка миграции cache. Exact final SHA CI: TTS на ce08 официально success, MapEngine install step timeout до тестов (не product failure и не pass), остальные финальные checks пересверять. Notes #2370 не разрешать до подтверждённого fail-closed и матрицы; #2349 Linux/Windows разночтение и физический Save as PDF, #577 визуальная/AT проверка остаются открытыми. Включать cohort только после принятия владельцем и физической/AT проверки; kill-switch без удаления старых данных. Live deploy SHA, восстановление и регрессы фиксируются отдельно.

## Проверяемые критерии и решения

- Panel contract: два независимых контроллера состояния **по сторонам** под единым owner, один активный TOC scrollspy, без конкурирующих click/overlay/resize listeners; не требование «одна открытая панель на страницу». Семейный data adapter не владеет жизненным циклом, theme adapter не меняет бизнес-логику.
- Тесты новых контрактов должны реально краснеть при скрытом desktop W57, нарушенном source anchor, двойном painter, неправильном focus/Escape или подмене палитры; не ослаблять guards для зелёного CI. Тема проверяется на разнообразных skins, а не только одном эталоне.
- У владельца согласовать: точный состав общих возможностей на разных типах страниц, модель responsive открытия, сохранение настройки ширины/свёрнутости, состав темы/брендинга, desktop product bootstrap, route/cohort flags и exceptions. План не обещает унификацию исключённых проектов без их владельцев.
- W130 указывает на проверяемый риск font scale и устаревших engine guards. Это гипотезы для очередной конкретной транзакции и точного нового SHA, не разрешение глобально поменять CSS, Nagornaya или брать его старые 21/293 за нынешнее состояние.

## Воспроизведение

На отдельной сборке exact ce08 запустить `node scripts/reader-toc-projection-contract-test.cjs`, `npm run surface:registry:check`, `npm run engine:contracts`; для двух browser probes нужен Playwright Chromium. Сервировать dist отдельно и запустить **новый** `research/reader-w57-pilot/preview.py`, указывающий на тот же dist; `DIST_URL`, `PREVIEW_URL`, `CHROMIUM_EXECUTABLE`, `OUTPUT` настраиваемы в скриптах. Preview инъекция исследовательская, не тест production desktop. Снимки и клики — Chromium/headless, не WebKit, AT, физические девайсы или дизайнерская приёмка.
