## Контракт общего движка: что должно быть единым

| Возможность | Единый владелец / адаптер | Инвариант для каждой принятой страницы |
|---|---|---|
| Контент и ссылки | существующий индекс Писания + `ReaderSemanticSnapshot`, `reader-projection`, `ScriptureDataProjection`; per-family data adapter | источник/версия/route/section/оригинал + canonical ID; проверенное точное видимое вхождение до действия; null/ambiguous → отказ, не догадка |
| Навигация и Analytics | один state/контроллер и одна проекция для mobile/W57 | разные skin/layout не создают второй parser; текущий раздел не смешивается со всей статьёй; одинаковые ссылки — отдельные вхождения |
| Цитаты, заметки, выделение | `GBReaderAnchors` + существующая Product Library | один writer и painter; редактирование/перемещение экрана не создаёт дубликат; старые записи и экспорт сохранены |
| Preferences, TOC, Play/TTS, search, quiz | существующие owners (`GBReaderPreferences`, ReaderActions/Floating, TTS, Pagefind, общий study controller) | один обработчик/сеанс на страницу; не плодить локальные движки; отказы и fallback честно обозначены |
| Presentation | data-only adapter темы, TOC, прогресса и редакционных карточек | Classic/W57 и серия сохраняют визуальную идентичность; 44px реальные hit targets, клавиатура, контраст, overflow и доступность — общие gates |
| Публикация | `migration/page-ownership.json`, `route-migration-matrix.json`, canonical build/index/version/SW | route eligibility задаётся allowlist и подтверждением владельца, не широким CSS/URL prefix или фактом наличия MDX |

Snapshot сегодня — библиотека `mjs` и контракт, а не доказанный подключённый runtime. Не называть продукт «единым» до actual production-like включения, consumer tests и устранения вторых владельцев.

Выход: exact-head обязательный CI, route ownership, content/URL и cache/offline checks; не объявлять release до зелёных gates и решения владельца.

**1. Стабильность до записи.** Закрыть Reader Controls red с реальным hit-test и актуальным договором без отключения проверок; отдельно воспроизвести pill edge/узкие hitbox. **2. Read-only semantic canary.** Явный OFF-by-default feature flag + список двух точных маршрутов из поручения, denylist защищённых маршрутов с проверкой каноникализации; product build без preview.py. **3. Один writer / безопасное выключение.** Перед любой записью подтвердить фазу 1; read-only/dual-read, single-write без клонирования состояния, элементов и paint. OFF → ON → OFF на двух маршрутах: старая Library и **две различимые заметки/цитаты на одинаковом тексте** остаются читаемыми, без повреждения, повторной привязки или второго painter; resize mobile↔desktop, reload, Back/Escape/focus, concurrent tabs и storage errors. Rollback выключает флаг без миграции/удаления данных; сохранённое через одобренный общий writer продолжает читаться старым UI. Проверить доступность включения и отзыв разрешения на уровне release, не через тестовый query или локальный preview.

**4. Chromium + WebKit (Firefox по согласованному контракту), физические устройства и реальная AT-проверка отдельно; видимый target и hitbox, focus trap/return/unlock, Play/rate, TOC/search, quiz singleton, selection/Library. PDF: первый и повторный cold direct + реальный Chrome «Сохранить как PDF», полный последний абзац **и** финальные блоки, разрыв atomic summary и заголовок+строка; #577 chronology/comparison/matrix 320, заголовки, keyboard, print и визуальная/AT приёмка. Скриншоты с SHA/viewport и ручным просмотром, фактические события/селекторы; тесты должны краснеть на намеренно сломанном W57 и неправильном переходе. CI зелёный — необходим, но не заменяет эти ручные проверки.

**5. Расширять только после принятия предыдущей когорты.** Сначала две явные страницы, затем одна структурно отличная обычная статья и одна историческая/биографическая глава по согласованию владельцев, затем остальные зарегистрированные eligible long-form — небольшими cohort с отдельными OFF/ON, fingerprint и доказательствами. Не автоматом все `/articles/`, не страницы-каталоги. После каждого cohort — владелец подтверждает content/visual/AT/данные; при регрессии выключать только данный cohort, не ломая уже принятую поверхность. NEWS/G3/JOURNAL, Нагорная, хабы/ленты/приложения остаются исключениями, пока не будет отдельного решения.

## Операционные стандарты / решения владельца

1. У каждого gate: конкретный владелец, сценарий, exact SHA, build, browser/device, результат, открытые исключения и обратный путь. Различать предсуществующий дефект сайта, регресс кандидата и будущий rollout риск. Никакой «полной готовности сайта» на основании одного инспектора или page count.
2. Требуются решения: совместимая модель fail-closed без Web Locks; production desktop activation и доставка; формат устойчивого occurrence identity и поведение ambiguous; редакционное подтверждение двух Teen anchor; допустимые physical/AT критерии; приоритет и отдельное владение #2349/#577; граница каждой следующей cohort.
3. Два старых свидетельства #2349 (Linux и Windows) сохраняются оба. До установления сопоставимых окружений не выбирать победителя; собирать версию браузера, fonts, timings, PDF options, raw и артефакты.
4. Пока API недоступен, этот план нельзя считать прочитавшим последующие комментарии и нельзя передавать его в PR как свежий handoff. После восстановления сначала перечитать все пропущенные комментарии и сверить SHA.

## Как воспроизвести

На изолированном checkout `52782ce...`: собрать `node scripts/astro-cli.mjs build` и `node scripts/copy-legacy-to-dist.js --production-like --no-manifest`; `node scripts/reader-semantic-snapshot-contract.mjs`. Для полного readiness использовать исходный script с совместимым Playwright Chromium; в этом окружении временно задавались путь к executable и `--no-sandbox`, `SOURCE_SHA=... READER_COVERAGE_REPORT=/tmp/...`. Для точечных DOM fixtures запустить независимый сервер dist, иметь Playwright в Node resolution и выполнить `BASE_URL=... SOURCE_INDEX=/path/to/data/scripture-search-index.json CHROMIUM_EXECUTABLE=/path/to/chromium node occurrence-probe.mjs`. Браузерные артефакты показывают только выбранную сборку и Chromium; ни один probe не меняет источники и пользовательское хранилище.
