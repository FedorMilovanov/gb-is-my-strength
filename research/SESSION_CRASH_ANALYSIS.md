# WHY I CRASH — причины падений агента в Arena Agent Mode

**Дата:** 2026-06-21  
**Проблема:** агент падает чаще, чем другие модели

---

## 1. ПРЯМЫЕ ПРИЧИНЫ (что я делаю не так)

| Причина | Что происходит | Как исправить |
|---------|---------------|---------------|
| **write_file vs bash sync** | write_file создаёт файлы, но иногда результат не виден в последующем `bash` в той же сессии. Проверять `ls -la` | `bash` с `cat > file` — надёжнее для больших файлов; `write_file` — OK для маленьких |
| **Слишком длинные ответы** | >20KB текста + код за раз → context переполняется → сессия падает | Делать КОРОТКИЕ ответы (5-10KB), 1-2 tool calls за раз |
| **Слишком много tool calls** | >3 tool calls за ответ рискуют превысить лимит шагов Arena | Максимум 1-2 команды на ответ, особенно под конец сессии |
| **Web search на depth=3** | Глубокие поиски возвращают 50-100KB контента | Использовать depth=2 |
| **Чтение гигантских файлов** | AGENTS.md 237KB, audit-pro.js 208KB — 5-10 секунд на загрузку | Читать только нужные секции |
| **Git push с токеном в URL** | remote URL сохраняется между сессиями, но токен в URL виден в `ps`/`history`. Использовать `GH_TOKEN` env var + `git remote set-url` при каждой сессии |

## 2. ПРОВЕРЕННЫЕ ФАКТЫ (экспериментально, 2026-06-21)

- ✅ Файлы СОХРАНЯЮТСЯ при падении сессии (ext4, не tmpfs)
- ✅ git remote СОХРАНЯЕТСЯ (но токен в URL — нет, используй env var)
- ✅ git log/history СОХРАНЯЕТСЯ
- ✅ python3 -c работает
- ✅ sed -i работает всегда
- ⚠️ edit_file ЧАСТО ПАДАЕТ — используй sed -i или python3
- ⚠️ read_file на файлах >500KB может упасть — используй head/grep
- ⚠️ Теряется только НЕДОПИСАННЫЙ ответ агента (середина сообщения)

## 2. ПОЧЕМУ СРЕДА СБРАСЫВАЕТСЯ

Arena Agent Mode имеет лимиты:
- Snapshot: ~128 MB или ~10,000 файлов
- Context window: ограничен моделью
- Tool call timeout: ~120-300 секунд

**Триггеры сброса:**
1. Ответ > 20KB текста + код → context переполняется → сессия падает
2. > 3 tool calls за раз → риск превышения лимита шагов Arena
3. Команда timeout > 120s → принудительное завершение

## 3. ЧТО ДЕЛАТЬ (для этого агента)

1. **bash > write_file** — всегда создавать файлы через `cat > file << 'EOF'`
2. **Короткие ответы** — не больше 1-2 tool calls за раз, особенно под конец сессии
3. **Не читать гигантские файлы целиком** — только head/grep
4. **depth=2 для поисков** — не depth=3
5. **После каждого push → unset GH_TOKEN** — безопасность
6. **Проверять что файл создан** — `ls -la file` после `write_file` или `cat > file`
