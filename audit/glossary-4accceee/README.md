# Мобильная «Аналитика»: кто получает жест, пока открыт термин?

#2352, точный `4accceeef1f01e0cc19bb0fe4f807e49758a2892`; контроль до исправления `6b7d7c353b65c669501860ef2e938549ca2097db`. Новый коммит меняет **только** обработчик фокуса в `src/runtime/article-tooltips.js`. Отдельные архивы и локальные сборки, preview.py, Gill II `?reader-pilot=1#part-controversy`. Touch/keyboard в Chromium, не физический браузер или скринридер. Проверка не предполагает, что две реализации аналитики уже объединены.

## Источник → глоссарий → переход главы

Открыть штатное оглавление → «Аналитика» → «Понятия» → «Кеннингтон-коммон» → «Показать в статье». Все 12 сценариев итоговой сборки начинают отсюда, в отдельных профилях. Ширины 320 и 390 px, высота 844. [Данные](current.jsonl) · [контроль до правки](prior.jsonl) · [снимки жеста](swipe.jpg).

| Проверка | Наблюдение |
|---|---|
| Ссылка на источник, Shift+Tab и Tab назад на термин | Теперь фокус на термине не открывает подсказку сам. На прежней сборке (390) движение Tab назад на термин переносило фокус прямо на «Подробнее» и фиксировало страницу. Сам переход из панели касанием не открывал определение и раньше. |
| Space / Enter / тап; «Подробнее»; Escape | Активация открывает определение, по «Подробнее» доступен полный текст; Escape возвращает фокус на термин, снимает блокировку и восстанавливает scrollY (13340 на 320, 10911 на 390 в итоговом прогоне с Tab). |
| Горизонтальный свайп по тексту **внутри** определения | Подсказка остаётся открытой, глава не меняется. |
| Обычный тап по затемнению **снаружи** | Закрывает определение, остаёмся в части II. |
| Тот же старт на затемнении, но 142 px влево | **Смена главы при открытом определении**: до жеста фокус на «Подробнее», `body` фиксирован; после отпускания URL части III (`chast-4-ekzeget`). Повторено в 320/390 и на 390 в предыдущей сборке. |
| ArrowRight при открытом определении | **Тоже меняет главу**, хотя активная кнопка — «Подробнее». После Escape такая же клавиша правильно ведёт дальше. Не регрессия последнего коммита. |

Механизм: мобильный фон рисуется `.gterm.is-open::before` в `css/site.css`. В точке начала жеста под карточкой на 390 `(296,464)` hit-test даёт **`abbr.gterm.is-open`**, а не отдельный фон. Элемент лежит внутри `article`, имеет `role=button`, но не является HTML `button`. Обработчики навигации в `js/floating-cluster-controller.js` смотрят на ограниченный перечень шторок и диалогов; активного слоя `article-tooltips` там нет. Попап портирован в body, поэтому начало жеста внутри карточки идёт иначе. **Критерий исправления:** общая навигация главы уступает верхнему активному слою для клавиш и touch-последовательности до её конца. Не отключать глобально навигацию по статье или касание фона для закрытия. Простое исключение `[role=button]` из touchstart не исправит клавиатурный путь.

## «Мои пометы»: уже удалённый текст остаётся на экране

390×844, две страницы одного временного профиля, без записи в хранилище тестовым скриптом. В Б создать заметку обычным редактором. В А открыть «Аналитика → Мои пометы» и увидеть эту заметку. В Б **отредактировать** или **удалить** её. Дождаться реального события `storage` в А, вернуть А на передний план, сверить карточки, счётчик и хранилище.

- После редактирования диск содержит новую строку; шторка показывает старую. После удаления диск пуст; в шторке всё ещё старый текст и счётчик 1. Свернуть/развернуть только «Мои пометы» не помогает.
- Перейти «Оглавление → Аналитика» — текст и счётчик становятся правильными в обоих сценариях. Это **устаревшее представление**, не неудачное удаление, не новая база и не потеря редакции. [Обе последовательности](personal.jsonl).
- `GillMobileMarginalia.astro:render()` получает снимок `GBReaderLibrary.getLibrary()` и строит карточки; переключение верхней вкладки вызывает render, раскрытие её `details` — нет. Для общего блока аналитики нужен один канал изменений библиотеки; при изменении перерисовывать только затронутый список/счётчик, не закрывая раскрытые разделы и не перенося фокус. Рендер всей аналитики на каждый storage event может устранить один дефект ценой другого.
