# Живые комментарии аудита — реестр

Конвенция: на каждый аудируемый PR — **один** «живой» комментарий. Он редактируется на месте (PATCH), а не дублируется новыми комментариями. История раундов — в файле отчёта, не в комментариях. Устаревшие комментарии сворачиваются (minimize, OUTDATED), не удаляются.

## Как устроен живой комментарий

- **Первый раунд:** `gh pr comment <N> --body-file ...` → ID берётся из URL в ответе (`#issuecomment-<id>`).
- **Следующие раунды:** `gh api repos/{owner}/{repo}/issues/comments/{id} -X PATCH --input body.json` — тот же комментарий, новое тело.
- **Устаревший комментарий:** GraphQL `minimizeComment` с `classifier: OUTDATED` (остаётся доступен по клику, лента чистая).
- **Чек-лист:** пункты `- [ ]` / `- [x]` в теле; основной агент отмечает выполненное правкой тела комментария тем же PATCH.
- **Идентичность:** агент пишет с аккаунта FedorMilovanov (отдельного агентского аккаунта нет) — в тексте префикс 🤖 и дисклеймер.

## Формат живого комментария

1. Заголовок: 🤖 Живой аудит <тема> · дата, раунд N. Указание, что комментарий редактируется на месте, и ссылка на файл отчёта.
2. Вердикт одной строкой.
3. Чек-лист блокеров (`- [ ]`).
4. Не блокеры — отдельные задачи.
5. Что проверено и работает.
6. Статус CI на head-коммите.
