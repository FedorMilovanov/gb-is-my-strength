# «Аналитика»: один источник, две реализации

Проверено на exact #2346 `62be8caa145fbe18aa099dff89cffa20cd626451` и отдельно #2352 `8197727986ae2b1ddae14f3061bd6905041c8d13`. Chromium 153, точные production-like dist. На каждом SHA: Gill II и «Гонения и совесть», каждое в трёх режимах. Мобильный 390×844 и opt-in desktop W57 1440×900 проверены на одном исходном якоре статьи; plain desktop 1440×900 — контроль. Swipes — trusted CDP touch по Gill II, не физический телефон или OS edge gesture.

## Прямое сравнение в браузере

Открыть одинаковый исходный якорь, прокрутить его чуть выше верхней границы, дождаться ReaderState, затем открыть «Аналитику». На W57 раскрыть правую панель через штатную кнопку. Мобильный переход по первой карточке проверен реальным тапом.

| Исходная позиция | Нативная мобила | W57 desktop |
|---|---|---|
| Gill II, `#sec-systematics`, «Полный свод богословия» | ReaderState знает правильный `sec-systematics`, панель показывает родительское «Полемика и дебаты эпохи». Первая карточка отправляет к `gill-search-p-036` про Уайтфилда; 12 терминов. | `part-controversy`, та же родительская группа; первый фрагмент тоже `gill-search-p-036`, но 20 терминов, включая не попавший в мобильный список «Свод богословия». |
| Baptist, `#ogpu-1923`, «1923: совесть становится делом ОГПУ» | Аналитика показывает «1923…»; первый фрагмент открывает `gill-search-p-041` «К 1923 году государство меняет подход…». | Показывает контекст `world-war-i`, «Первая мировая: две позиции внутри одного братства»; первая карточка указывает на `gill-search-p-023` о Первой мировой. |

В Gill II и Baptist у мобилы реальный переход по карточке закрывает шторку, снимает lock и ставит фокус на соответствующий абзац. То, что переход технически работает, не исправляет неверно выбранный диапазон в Gill. Архитектурный дефект не новый для `8197727`. На W57 значения первых карточек установлены по штатному `data-np-u-evidence-index` в DOM, не по симуляции desktop-клика.

Визуальное следствие: мобильные «Понятия» и «Ход текста» и desktop «Лексикон» / «Ход мысли» выглядят не как разные размеры одного продукта: разный порядок и состав, иной контекст и разные действия над одинаковыми типами записей. Плотность и способ размещения могут различаться; смысл карточек и их источники — нет. Дневная Baptist-шторка дополнительно оставляет фоновый текст видимым сквозь тело панели, так что два текста визуально конкурируют (замечание дизайна, не оценка контраста).

## Свайпы в мобильной «Аналитике»

390×844, Gill II, 6 жестов на SHA, нормальный масштаб. Ни один из этих жестов не показывает peek и не запускает соседнюю часть: в модальном состоянии навигация серии не владеет жестом.

- Горизонтальный по содержимому `(-158,0)` оставляет шторку открытой. Вертикальный вниз `(+0,+95)` при `scrollTop≈138` сначала прокручивает содержимое назад; шторка остаётся. С `scrollTop=0` `(+0,+96)` закрывает, unlock и фокус на исходное «Оглавление» исправны; `(+0,+64)` не закрывает.
- **AN-S1:** из верхней позиции шторки диагональ `(-157,+88)` тоже закрывает, хотя горизонтальная компонента почти вдвое больше. `initSheetSwipe` смотрит только на `dy`, без классификации оси. Это закрытие, не переход серии.
- **AN-S2:** на `8197727`, `fe5a4cd` и `6b7d7c3` настоящий `touchstart` попадает в видимую 28px ручку, но drag вниз `+95` при `scrollTop≈136` не закрывает и не двигает шторку. Хедер не различается со скроллером: `scrollerBlocked` сверяет любой вложенный scroller, даже если жест начался в ручке. Ранее подтверждённый тап по ручке закрывает; на `62be8caa` этот сценарий не подтверждает попадание в ручку, она почти нулевой высоты. Критерий: жест по телу внутри скролла принадлежит контенту; явный drag ручки закрывает независимо от scrollTop, а горизонталь не закрывает.

За пределами шторки остаются [ZM-01: переход при панораме увеличенного текста](../mobile-zoom-qa/README.md) и [свайп с края переполненной таблицы](../mobile-swipe-visual-qa/README.md). Не переносить их внутрь Analytics и не заводить для шторки второй обработчик навигации главы.

## Как сделать одну вещь, не два конкурирующих проекта

1. **Один контракт `ReaderAnalytics`, не перенос всей W57-оболочки в продукт.** На границе использовать нативный `ReaderState`/якоря как состояние точной позиции. В модели хранить отдельно `activeAnchorId` и `scopeSectionId`: например, H3 внутри H2. Если H2 — выбранная область анализа, обе панели должны явно обозначить «в родительском разделе», а не выдавать её за текущий H3. Группировка для левой desktop-рейки не определяет область аналитики. Не индексировать внедрённые UI-заголовки/обзоры как оригинал.
2. **Один экстрактор/провайдер модулей** на оригинальном корне статьи: одинаковая фильтрация скрытого UI, одинаковые ordered IDs, источники, cut-offs и маркировка `section`/`article`/`next-section`. Фрагменты должны ссылаться на устойчивые {doc, anchor}, не на позицию в списке DOM. При необходимости — отдельный слой проверенной редакционной разметки с явным provenance, не второй экстрактор. Общие карточки/семантика/действия; на узком экране можно сначала показывать меньше, но «Все» раскрывает тот же набор, не альтернативную выборку.
3. **Две оболочки, одна функция:** мобильный контейнер сохраняет доступный `gill-part-toc` и свои scroll/focus/drag; desktop — боковой `aside` с follow/fold/pin, не второй modal. Панель запросит одно действие `goToSource` с правильной семантикой: точный источник, focus/offset/reduced-motion, close только там, где нужен. Только одна интерактивная поверхность на viewport; не клонировать Play/Save/Notes. «Пометы» — отдельный модуль общего Library API, не логика экстрактора и не прямой новый редактор localStorage.
4. **Приёмка — парная, до удаления старых путей.** На одинаковом якоре снять `activeAnchorId`, `scopeSectionId`, типы/порядок карточек, `sourceId`, scope/provenance, проверить реальные переходы на Gill `#sec-systematics` и Baptist `#ogpu-1923`, пустые разделы и поздно подключаемый глоссарий. Затем mobile touch 320/390/landscape, desktop keyboard, смена breakpoint, scroll-lock, Escape/focus, TTS, TOC, Notes/Library. Прежний пользовательский JSON не должен меняться при подключении аналитического провайдера. Правила свайпов остаются в shell; отдельно проверяются текст, скроллер, ручка, zoom.

Предлагаемый первый PR — общий контракт и парные fixtures, подключить к нему нативную вкладку; вторым шагом заменить extractor W57 за opt-in, сравнить результаты и удалить дублирующий код. Не требуется сразу включать W57 на production desktop или менять внешний вид всего Reader.
