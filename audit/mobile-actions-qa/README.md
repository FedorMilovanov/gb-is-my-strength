## MA-01 — «Продолжить» может отбросить к ранее прочитанному разделу

Гилл II, 390×844, чистый профиль. Ожидаемый на этой странице контракт прямо описан в `GillPartTocOverlay.astro`: «Продолжить» закрывает оглавление и возвращает к **текущему** разделу. В действительности handler берёт `GBReaderState.getSaved()` (снапшот из хранилища, не текущий), иначе `currentAnchor` (SSR fallback). ReaderState сохраняет состояние с debounce (по умолчанию 900 мс), поэтому и старый снапшот, и его отсутствие дают неправильный раздел.

| Сценарий | Перед нажатием «Продолжить» | Куда попал |
|---|---|---|
| Доверенное колесо, быстро открыть нижнее «Сейчас читаете» и нажать «Продолжить», свежий профиль | «Дух-Применитель…», `y≈24185`, 44%; снапшота ещё нет | `#sec-hebrew`, `y≈6600`, 11%; «Раввинист…» |
| Сначала остановиться на «Песни Песней» до записи состояния; затем быстро прокрутить к «Духу-Применителю…» и нажать «Продолжить» | Снапшот `sec-canticles`, **живой** раздел «Дух-Применитель…», 44% | `#sec-canticles`, 17%; «Песнь Песней…» |
| Положительный контроль: то же колесо, пауза 1,65 с перед открытием | Снапшот уже `sec-pneumatology`, живой раздел тот же | `#sec-pneumatology`, остаётся правильный раздел; не утверждаю сохранение конкретной строки |
| Пассивное позиционирование (проверка URL/якорного сценария без указания, что это было ручное чтение), без сохранённой позиции | «Дух-Применитель…», 44% | SSR fallback «Раввинист…», 11%, в том числе при системном `reduce` |

`Escape` закрывает тот же слой и сам не требует нового поиска раздела. Критерий приёмки: для «Продолжить» использовать место чтения/живой раздел **до body lock**, не перечитывать сохранённый снапшот; при отсутствии живого раздела сохранить исходную позицию. Не перезаписывать исторический снапшот ради закрытия оглавления. Во всех режимах handler сейчас передаёт явный `scrollIntoView({behavior:'smooth'})`, в том числе при системном `reduce`; это наблюдение вызова API и отдельный повод не создавать лишнюю анимацию. `continue-before.png` и `continue-after.png` проверены глазами: фактически это две разные части статьи, а не просто изменение числа в прогресс-баре.

## MA-02 — «Слушать» в оглавлении скрыто работает как переключатель

Гилл II и «Гонения и совесть», 390. Реальный тап по нижнему TOC → «Слушать часть»/«Слушать статью» начинает воспроизведение (один вызов речи). Открыть TOC снова при активной речи: видимое и доступное имя остаётся «Слушать…» с тем же значком ▶. Тап **ставит на паузу** и закрывает оглавление. В фазе `paused` третье открытие TOC показывает точно ту же надпись и значок; тап возобновляет речь. Счётчик `speak` остаётся 1; речь не дублируется. Состояния `idle → playing → paused → playing` и оба независимых маршрута подтверждены.

Владелец тот же: `GillPartTocOverlay.astro` закрывает шторку и через 120 мс вызывает `.click()` нативного Play. Это хорошо для единого владельца, но footer не читает состояние Play. Не нужно добавлять ещё один runtime: подписать кнопку на текущую фазу и сделать видимую и доступную команды согласованными («Пауза»/«Продолжить озвучку»), или явно оставить «Слушать» только однонаправленным действием. `listen-gill.png`/`listen-bapt.png`: TOC показывает ▶ «Слушать» уже при активной фазе.

## Положительный контроль: закладка, Библиотека, Share, PDF

- Gill II в 320 и 390: один тап по верхней закладке выставляет `aria-pressed=true`, после reload состояние хранится. Book открывает единственный видимый диалог «Моя библиотека» с одним сохранённым материалом, `Escape` возвращает фокус к `#gb-hl-fab`.
- Bottom Share с заглушкой доступного `navigator.share`: одна передача текущего URL, пользовательская активация присутствует. Без `navigator.share` — одна передача в clipboard и сообщение «Ссылка скопирована». `AbortError` имитирует отмену: нет копирования или ошибочного тоста. Нативное меню ОС не проверялось.
- Bottom PDF и PDF из открытого TOC вызывают по одному `window.print` с выполненной подготовкой пагинации (`GBPrintEngine`, source `button`). При печати из TOC `data-scroll-locked` снимается; после имитированного `afterprint` тот же открытый TOC снова получает lock; `Escape` возвращает `scrollY=1550` и снимает lock. Не проверял содержимое итогового PDF.
