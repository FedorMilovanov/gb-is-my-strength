## RF-01 — точный поиск по сохранённой заметке не находит обычную пунктуацию

Создать заметку «Сравнить Ин 1:29 и Деян 20:28. Отдельная помета: историко-богословский обзор.» и отдельную контрольную заметку о предисловии. На вкладке «Все» ввести:

| Запрос, точно как в заметке | Результат | Замена разделителя пробелом |
|---|---:|---|
| `Ин 1:29` | 0 | `Ин 1 29` → 1, нужная заметка |
| `1:29` | 0 | `1 29` → 1, нужная заметка |
| `Деян 20:28` | 0 | `Деян 20 28` → 1, нужная заметка |
| `историко-богословский` | 0 | `историко богословский` → 1, нужная заметка |

Контроль `предисловии` находит только вторую заметку. Для точных запросов интерфейс сообщает «Пока ничего не найдено». Причина в `reader-library-v3.js::matchesResearch`: запрос сначала режется только по пробелам, затем удаляет знаки из токена (`1:29` → `129`), а сохранённая строка разделяется по знакам (`1`, `29`). Одинаково нормализовать обе стороны, сохранить буквы/цифры и границы слов; для ссылок проверять буквальный поиск с `:` и дефисом, а не заставлять пользователя знать обход с пробелом. Не подменять общую «Аналитику → Писание»: это поиск внутри Библиотеки.

## RF-02 — 21-я метка не сохраняется, хотя Библиотека сообщает об успехе

Открыть «+ Метка» на заметке и добавить по очереди «Тема 01»–«Тема 20». Все 20 видны на карточке и в хранилище. Добавить отличающуюся «Тема 21»: редактор закрывается и появляется **«Метка добавлена.»**, но ни карточка, ни фильтр, ни `gb-library-tags-v1` её не содержат. После reload всё ещё ровно первые 20. `safeTags` обрезает массив до 20, `setTag` не проверяет, что новая метка осталась. Не менять сам лимит без решения продукта: до записи сообщить об ограничении и не закрывать введённое значение под видом успеха.

## RF-03 — удалённая заметка оставляет пустую тему после истечения Undo и reload

К заметке A добавить «Азбука чтения», заметку B оставить без метки; включить тему → показана A. Удалить A → «Отменить» действительно возвращает тот же ID и метку (положительный контроль). Удалить A снова и дождаться конца 6-секундной отмены: заметки A больше нет, но тема остаётся активной и скрывает B. После reload и открытия Библиотеки B снова видна под «Все темы»; сама «Азбука чтения» всё ещё доступна и снова приводит к пустому списку. Ключ `note:<удалённый id>` остаётся в `gb-library-tags-v1` после reload. `getTopics()` не связывает метки с существующими записями. Формировать фильтры по живым записям, при исчезновении активной темы вернуть «Все темы». Для Undo сохранить возможность вернуть метку; не предлагать недоступные темы после истечения Undo.

## RF-04 — активация темы клавишей сбрасывает фокус в `BODY`

В открытой Библиотеке перевести реальный DOM-фокус на «Азбука чтения», нажать Enter. Тема применяется и список фильтруется, но `document.activeElement` меняется с кнопки темы на `BODY` при открытом dialog. На 320 и 390 следующий Tab возвращает на «Все темы», Shift+Tab — на «Сортировка»; Escape закрывает диалог и возвращает фокус на `#gb-hl-fab`. **Не** подтверждён выход Tab на фон; подтверждена потеря текущего видимого фокуса/позиции. `renderTopics()` пересоздаёт все кнопки. Сохранять узел либо рефокусировать выбранную кнопку после рендера (если исчезла — «Все темы»), не перетягивать фокус от поля поиска.
