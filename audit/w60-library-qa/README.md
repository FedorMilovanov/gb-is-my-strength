## Результат 8 сценариев

Общий порядок: A открывает редактор и вводит черновик → B в Библиотеке сохраняет новый текст либо удаляет ту же заметку → подтверждаем состояние B → A нажимает «Сохранить заметку» → проверяем результат и его сохранность после reload B.

| Редактор А / действие в Б | #2346 `e567400` | #2352 `8da79cb` |
|---|---|---|
| Библиотека → Библиотека обновляет | Старый черновик затирает свежий текст, тот же ID; тост успеха. | **Исправлено:** свежая правка защищена, явное сообщение о конфликте, старый черновик остаётся в открытом поле. |
| Библиотека → Библиотека удаляет | Запись не восстанавливается, но тост **«Заметка обновлена»** ложный; редактор закрывается и черновик исчезает. | **Исправлено:** запись отсутствует, сообщение об удалении, черновик остаётся доступным для копирования. |
| Десктопные «На полях» (W57) → Библиотека обновляет | Старый черновик затирает свежий текст, тот же ID и связь с цитатой. | **Не исправлено:** тот же overwrite; после reload остаётся текст из A. |
| Десктопные «На полях» (W57) → Библиотека удаляет | A сохраняет удалённую заметку заново с **другим note ID**, тем же quote ID. | **Не исправлено:** удалённая заметка создаётся заново с новым ID, тост «Заметка сохранена в библиотеке», запись переживает reload. |

**Дефект сохранности данных** не зависит от смены мобильной компоновки и отличается от B1–B4 импорта. В #2352 проверка находится в `js/highlights.js::saveNote` и защищает только сохранение из общего редактора Библиотеки. Другая кнопка сохранения живёт в `research/reader-w57-pilot/assets/reader_w57_annotations.js`: `openNoteEditor()` хранит только ID пометы, а `saveLinkedNote()` при сохранении заново читает текущую связанную заметку и без проверки исходной версии либо переписывает её, либо считает исчезновение разрешением на создание новой записи.

**Минимальный критерий фиксa:** запоминать при открытии черновика состояние связанной заметки (ID и текст/ревизию либо отсутствие) и сверять перед любой записью связки. При изменении/исчезновении, а также появлении заметки после открытия пустого редактора — явный конфликт, поле остаётся открытым, ни notes, ни quotes не переписываются; создание новой записи только через явно выбранное действие. Переиспользовать один контракт обеих точек сохранения, не добавлять новое хранилище и не обещать атомарность двух одновременных записей. Ретест D5/D6 после интеграции на точном HEAD, не закрывать пункт по одному положительному пути.
