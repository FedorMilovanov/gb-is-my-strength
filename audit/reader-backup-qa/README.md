# Мобильный Reader: восстанавливается ли его собственная резервная копия

Exact #2352 `615eff9af809177b30612f93a77cecc053c3836b` и baseline `a595629f15a2324205cbb9b1c2cb2cc936814214`. Production-like `dist`, Chromium 153, Gill II, 390×844. На каждом билде записи создавались через реальные кнопки маркера/цитаты и редактор заметки. Выделение реальной прозы задавалось браузерным `Range` (не жестом long press); тапы штатные. Для каждого восстановления — чистый профиль, скачанные самой Библиотекой байты JSON **без правок**, загрузка через её `<input type=file>`, подтверждение через «Добавить без замены». Хранилище только читалось; тестовых записей напрямую не подставляли. Нет `pageerror`.

Результаты одинаковы на обоих SHA: вновь подтверждённые дефекты, **не регрессии `615eff9a` и не приёмка типографики Classic**.

| Дефект | Действия и результат | Что изменить / как принять исправление |
|---|---|---|
| **RB-01 — длинная цитата блокирует весь импорт** | Длинное выделение реальной статьи сохраняется как цитата **40 884** символа. «Копия JSON» сообщает «Полная резервная копия сохранена». Файл всего **90 573 байта**, но на том же origin «Импорт отменён: Некорректная цитата.» ещё до подтверждения. Не восстанавливаются ни длинная цитата, ни две обычные записи и две заметки из этого файла. | `validateBackup` ограничивает `quotes[].text` 25 000, UI сохранения такого ограничения не применяет. Согласовать контракт и дать восстановить уже сохранённые данные без обрезания; недопустимо отбрасывать все валидные записи молча. Проверить на реальном скачанном файле, не на синтетическом JSON. |
| **RB-02 — «полная копия» обрезает контекст связанной заметки** | Цитата и её контекст в заметке в скачанном JSON имеют по **3 198** символов. Импорт на том же origin успешен, цитата полная, ID/`quoteId` и тело заметки сохранены, но `notes[].quoteText` уже **1 800** символов и таким остаётся после reload. Полный текст всё ещё есть в связанной цитате, поэтому это потеря снимка контекста заметки, не удаление пользовательского текста заметки. | `cap(x.quoteText, 1800)` в импорте не совпадает с редактором. Ограничивать UI-превью, а не данные резервной копии; проверять точное равенство контекста после восстановления. |
| **RB-03 — импорт не обновляет подсветку во вкладке, которая его выполнила** | Короткий файл **2 382 байта**: маркер «Гилл стал пастором» и одна связанная заметка. Импорт на том же origin успешен, в Библиотеке обе записи и связь. Через 1,2 с слой `gb-hl-amber` по-прежнему отсутствует в импортирующей вкладке, в том числе после закрытия Библиотеки (дополнительный прогон на `615eff9a`). Во второй уже открытой вкладке того же профиля и после reload импортирующей вкладки — **один диапазон**. | После успешной записи импорта нужно уведомить владельца отрисовки и в этой вкладке. Сейчас обычные операции публикуют `gb:library-committed`, `atomicImport` отправляет `gb:favorites-changed`, а browser `storage` не приходит в записавшую вкладку. Проверять слой сразу после импорта и закрытия Библиотеки без reload, не добавлять второй painter. |
| **RB-04 — копия не переносится между origin одного и того же сайта** | Тот же короткий файл без изменений: на исходном `127.0.0.1:19137` в другом профиле импорт успешен; на идентичной сборке на `127.0.0.1:19138` отказывается с «Некорректная цитата», без записей и подтверждения. Это **смена origin** (в примере другой порт), не общее утверждение, что не работает смена браузера на том же адресе. Актуально, если сайт переезжает на другой домен/адрес. | Экспорт хранит абсолютные URL, импорт требует свой origin. Нужен переносимый формат источника для внутренних маршрутов с `query/hash` и отдельная явная политика для старых копий доверенных адресов. Не разрешать произвольные внешние ссылки. Ошибка должна объяснять несовпадение адресов. |

## Запуск

```sh
node audit/reader-backup-qa/probe.mjs
QA_ROOT=/tmp/mobile-a595629f QA_SHA=a595629f15a2324205cbb9b1c2cb2cc936814214 \
  QA_PORT=19139 QA_OUT=reports/reader-backup-qa/baseline node audit/reader-backup-qa/probe.mjs
```

Нужны Python 3, Playwright/Chromium; `W58_PLAYWRIGHT`, `W58_CHROMIUM_PATH` переопределяют раннер. `QA_SMALL_ONLY=1` — только короткая копия и два origin. JSON/скриншоты в `reports/reader-backup-qa/`. Исходники продукта и desktop не менялись.
