## БЛОК 1 — ROBOTS.TXT: КРИТИЧЕСКИЕ РИСКИ

### 🔴 BUG-01: SEO-инструменты заблокированы

```
User-agent: AhrefsBot
Disallow: /

User-agent: SemrushBot
Disallow: /
```

**Что это значит на практике:**
- Невозможен внешний SEO-аудит через промышленные инструменты.
- Ни одна SEO-студия не сможет полноценно проверить сайт без доступа к GSC.
- Ahrefs и Semrush не будут формировать ссылочный профиль — обратные ссылки не собираются.

**Это намеренно?** Возможно — как защита от bulk-scraping. Но это цена: теряется возможность мониторинга позиций и ссылок.

**Рекомендация:** Если владелец не использует эти инструменты — OK. Если использует — добавить `Allow: /` под конкретным Bot-token для верифицированных краулеров.

---

### 🟠 BUG-02: `Disallow: /*?*` — блокировка параметрических URL

```
User-agent: *
Disallow: /*?*
```

**Норма:** Блокирует `/articles/?utm_source=...` — правильно.  
**Риск:** Если внутри сайта есть функциональные параметры (фильтры поиска, pagefind-параметры), они тоже заблокированы.  
**Статус:** Без доступа к логам — не проверить. Подозреваю, что OK, но надо верифицировать.

## БЛОК 2 — SITEMAP.XML: КОНКРЕТНЫЕ БАГИ

### 🔴 BUG-03: `/rodosloviye/` — страница без реального контента

URL в sitemap: `https://gospod-bog.ru/rodosloviye/`  
`<lastmod>2026-06-18T00:00:00+03:00`

**Краул показал:** страница отдаёт только заглушку:

> «Полная интерактивная версия содержит навигацию, фильтры и визуальное древо родословий; статический текст сохраняет смысл раздела для чтения и поиска.»

**SEO-проблема:**
- Google видит thin content — менее 100 слов реального текста.
- Нет `<h1>` с ключевым запросом.
- Нет структурированного контента (ни таблиц, ни списков, ни описания).
- Страница в sitemap с `priority 0.7` — Google будет краулить её и не получать ценности.

**Вероятность:** это intentional scaffold (как baptisty-rossii), но SEO-ущерб реален.

---

### 🟠 BUG-04: 5 страниц Нагорной проповеди без `<changefreq>` и `<priority>`

```xml
<url>
  <loc>https://gospod-bog.ru/nagornaya/chast-1/</loc>
  <lastmod>2026-06-25T17:24:45+03:00</lastmod>
  <!-- нет changefreq, нет priority -->
</url>
```

То же для `chast-2`, `chast-3`, `chast-4`, `chast-5`.

**Проблема:** Краулер Google не получает сигнала о приоритете. По умолчанию priority = 0.5 — это ниже, чем у `baptisty-rossii/spravochnik/` (0.6).

**Это главные SEO-активы сайта** — серия Нагорной проповеди объёмом 89+ минут. Они должны иметь `priority 0.9` и `changefreq weekly`.

---

### 🟠 BUG-05: `/karty/` — нет `<lastmod>`

```xml
<url>
  <loc>https://gospod-bog.ru/karty/</loc>
  <!-- нет lastmod -->
  <image:loc>...</image:loc>
</url>
```

Без `<lastmod>` Google не знает, когда страница обновлялась. Это допустимо, но нежелательно для стратегической страницы.

## БЛОК 3 — TITLE / META / Open Graph

### 🟠 BUG-07: OG-метаданные у `/nagornaya/chast-N/` — рендер под вопросом

Краул серии (`/nagornaya/chast-1/`) показал:

```
/images/og-nagornaya-propoved-chast-1.webpРедактор: Фёдор Милованов16БогословиеМф 5–7, Лк 6
```

Это **сырой текст из head**, отданный без разделителей — признак того, что meta-теги рендерятся частично или их структура нестандартна в legacy HTML. У Astro-страниц (Gill) — чистый title, у Nagornaya — компромисс.

**Риск:** если `og:description` пустой или технический, соцсети и мессенджеры покажут некрасивый превью.

### 🟡 BUG-08: Расхождение времени чтения между карточками и статьями

| Страница | Время на карточке | Время в статье |
|---|---|---|
| `hermenevtika...` | 50 мин | 35 мин |
| `20-antisovetov-pastoru` | 25 мин | 67 мин |

**SEO-эффект:**
- Structured data / микроразметка (если есть) даёт поисковику сигнал.
- Пользователь видит 25 мин, приходит на 67 мин — bounce rate растёт.
- Google оценивает дельту между обещанием и реальностью.

---

### 🟠 BUG-09: Двойной canonical — риск на legacy-страницах

После многочисленных миграций fc→gb и Astro-рефакторинга в репо, legacy root HTML страницы могут содержать `<link rel="canonical">` **и** Astro PageHead добавляет свой. Если оба тега есть в DOM — браузер и Google берут первый найденный. Это может быть неправильный.

**Проверено:** напрямую HEAD-запрос не делался — нужна проверка `curl -I` по конкретным legacy URL.

## БЛОК 5 — СТРУКТУРИРОВАННЫЕ ДАННЫЕ (JSON-LD)

### 🟠 BUG-14: Нет явного `Article` JSON-LD на статьях серии

На `/articles/dzhon-gill-chast-1-chelovek/` краул не показал JSON-LD в тексте. Без `Article` или `BlogPosting` schema:
- Google не показывает rich snippets с датой публикации.
- Нет `dateModified` → нельзя проверить drift.
- Нет `wordCount` → Google сам оценивает длину.

**Уточнение:** JSON-LD может быть в `<head>` через Astro — краулер-текст его не покажет. Нужна проверка через `view-source:` или Google Rich Results Test.

### 🟡 BUG-16: Непоследовательная AI-политика

```

User-agent: PerplexityBot     → Allow  ✅
User-agent: GPTBot            → Disallow ❌ (обучение)
User-agent: Claude-SearchBot  → Allow  ✅

Это **правильная стратегия** — разделять поисковые боты AI от обучающих. Но:

**Рекомендация:** Добавить `YouBot-Search` / `YouBot-Scraper` разграничение, если они появятся.

### 🟡 BUG-19: Cache-bust параметры заблокированы robots

```

### 🟡 BUG-22: Серия Gill — «Трилогия» vs «Серия» — терминологический drift

- В sitemap: Gill серия из 5 частей.
- На карточках главной: «Трилогия · Часть I» / «Трилогия · Часть II» / «Трилогия · Часть III».

Слово «Трилогия» создаёт путаницу, если серия состоит из 5 частей (Контекст + 3 части + Справочник). Это может путать краулер при понимании структуры серии.

## ВЕРДИКТ

Сайт **технически грамотен** для своего масштаба: есть sitemap, robots.txt с осознанной AI-политикой, IndexNow, cache-bust, структурированные серии. Это выше среднего для независимого богословского сайта.

**Главные SEO-риски:**
1. CI падает → деплой не проходит → контент не обновляется на проде.
2. Нагорная проповедь (главный SEO-актив) недооценена в sitemap (нет priority).
3. Thin-content страницы (`/rodosloviye/`, `/map/`, `/pastor-series/`) тянут вниз сигнал качества домена.
4. Lastmod drift у baptisty-rossii снижает частоту краулинга главной серии.
