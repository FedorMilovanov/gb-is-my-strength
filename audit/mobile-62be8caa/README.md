# Mobile Reader · #2346 · 62be8caa

Независимая сборка `62be8caa145fbe18aa099dff89cffa20cd626451`, не #2352 и не макет 19061. Предыдущая контрольная ревизия — [249bb866](../w64-reader-249bb866/README.md). Проверка показала и реальные исправления, и оставшийся риск разрыва связей при импорте. Не рекомендация к выпуску.

## Что происходит с данными

- **Импорт через интерфейс, Gill II, 390×450 и 390×844**, пустой профиль. Файл A → диалог подтверждения → файл B размером 4 МиБ + 1 байт: старое подтверждение исчезает, видна ошибка, цитаты A не записаны. Далее A импортирован дважды через выбор файла и «Добавить без замены»; проверка хранилища после reload и открытия библиотеки. Синтетический валидный backup: два разных ID с одинаковым текстом в одной статье, разный `before`, заметка с `quoteId` второй записи. **При наличии двух разных якорей v1 обе цитаты и ссылка сохранены**; без `annotation.anchor` остаётся только `first`, ссылка заметки всё ещё `second`. Это не опровержение исправления для двух диапазонов. Причина различия: `js/reader-library-v3.js:safeMerge` различает ID, но `js/site-utils.js:installHighlightStorageGuard` перехватывает запись и без якоря дедуплицирует по пути и тексту. Даже если старые записи намеренно объединяются, не следует оставлять ссылку на отсутствующий ID. На 450 px всплывающий статус временно перекрывает подтверждение: обычный tap с ожиданием проходит приблизительно через 5.2 с против <0.2 с на 844 px. Не постоянная блокировка и не проверка искусственно переставленных ответов A/B.
- **Заметка из мобильной библиотеки → настольная «Аналитика»**, «Код да Винчи», две страницы одного профиля. Маркер сделан мышью на 1440, заметка к его карточке — на 390, широкая страница перезагружена. **Одна заметка:** «Изменить заметку» открывает тот же текст; сохранение не создаёт дубль. **Две заметки**, созданные той же кнопкой «Заметка» у одной цитаты на мобильном: обе имеют нужный `quoteId`, но «Аналитика» предлагает «Добавить заметку» и пустое поле. После ввода и сохранения — три записи. Не удаление заметок: `linkedNote` намеренно не выбирает из нескольких. Стоит показать выбор из существующих, а не маскировать неоднозначность под отсутствие заметки.

## Мобильные действия

- **Библиотека:** «Новая заметка» → ввод → сохранение → reload → вкладка «Заметки» → редактор с тем же текстом: 9/9 размеров (568×320, 844×390, 390×450, 320×500/520/521/568, 390×530/844); плюс 320×844 → высота 350 при открытом редакторе. Playwright tap может подвести элемент в область видимости. Не путать с хорошей видимостью кнопки: на [320×521](boundary.jpg) центр «Новая заметка» ниже экрана, видна лишь полоска от y=518, у панели уже `overflow:clip`. Высоту системной клавиатуры на телефоне не измеряли.
- **[Настройки](settings.jpg):** выбор Cormorant вместо Lora меняет CSS-семейство абзаца Gill II и `aria-pressed`, сохраняется после reload на 320/390. Ночной режим, размер, три команды внизу работают. **[Аналитика](analytics.jpg):** доступное имя кнопки, вкладка и заголовок согласованы; Escape возвращает фокус к прямому вызову. Settings → «Обучение» → Escape всё ещё возвращает на BODY, а Shift+Tab после прокрутки — на невидимую кнопку настроек (y=−76).
- **Скорости:** на 320 лента выросла с 64 до 88 CSS px; теми же эмулированными свайпами крайние 2× / 0.75× доступны на 320/390/525 без запуска и навигации. Центр Play и удержание работают. Изменился владелец двух координат внутри прежнего 44px квадрата: +27/+32 теперь попадает на смещённый бейдж, а +43/+20 открывает скорость даже при `elementFromPoint` на Play. На всех трёх ширинах фактическое действие в обеих точках — только меню, без озвучки; прежний результат этих точек нельзя переносить на эту ревизию. Это не отказ всей кнопки.
- **Не исправлено:** «Ночь на Куре» → «Аналитика → Ход текста → Читать в статье» не раскрывает «Коротко» на 320/390, абзац `inert`; если заранее раскрыть, та же цитата видна и получает фокус. Прямой переход глубже в главе и термин из Gill II работают. В opt-in превью при 1120→1121 и 1440→390 теряется несохранённый черновик, сохранённый контроль остаётся. В пределах мобильного режима и без opt-in переход 1120→1121 черновик в соответствующих контрольных опытах остался.
