## AH-01 — клавиатурный «Показать в статье» открывает вторую шторку и съедает переход

На #2346 и `6b7d7c3`: дойти до `#sec-systematics`, открыть нижнее «Оглавление» → «Аналитика» → «Понятия» → «Кеннингтон-коммон» → фокус на «Показать в статье» → Enter. Это не повторная активация термина. Нативная «Аналитика» закрывается, но `jumpTo` фокусирует `.gterm` сразу после запуска smooth-scroll. Видимый клавиатурный фокус открывает `article-inline-tooltip` и снова блокирует прокрутку. Escape снимает lock, возвращает **старый** y=36839 / 35685; фокус находится на термине примерно на 24 380 CSS px выше экрана. Контроль настоящий тап на ту же CTA: tooltip не открывается, позиция меняется штатно.

**Исправлено в `4acccee`:** обычный Tab на `Диссентер` оставляет фокус на термине без lock; Enter и отдельный tap открывают определение, Escape закрывает и возвращает фокус и позицию. Клавиатурный «Показать в статье» теперь ведёт в то же место, что и тап (`y35685→11233`, термин на ~72–121 px), определения и lock нет. `getBoundingClientRect()` для многострочного термина объединяет строки: центральный hit попадает в абзац, поэтому не интерпретировать `focus.visible=false` как «термин за экраном» на исправленном SHA. #2346 этой правки не содержит.

## AH-02 — переход игнорирует «Спокойную» и системный reduced motion

«Аналитика» → «Ход текста» → первый «Читать в статье» из тех же `#sec-systematics` на #2346 и обоих SHA #2352. Переход закрывает шторку и фокусирует нужный абзац, но двигает viewport анимированно на ~24.6 тыс. CSS px. Это не просто значение аргумента: ряды `requestAnimationFrame/scrollY` содержат десятки промежуточных позиций примерно за 1.5 s в Chromium. `jumpTo` безусловно передаёт `scrollIntoView({behavior:'smooth',block:'start'})`. Системное предпочтение `prefers-reduced-motion: reduce` включалось в контексте; для `4acccee` отдельно проверено системное `no-preference` + настоящая кнопка «Спокойная» в настройках (`motion=reduced`): 44 изменения `scrollY` вплоть до 1546 мс. Это отдельно от ранее найденного smooth-follow TTS.

Критерий: общий `goToSource` уважает системную/встроенную настройку, доводит до читаемой позиции после unlock и возвращает фокус на нужный якорь без открытия другого окна на одном лишь focus.

## AH-03 — две допустимые заметки библиотеки скрывают друг друга в W57

На `62be8caa` и `4acccee`, настоящий desktop UI одного origin, plain Library и opt-in W57:

1. В Library импортировать JSON v3 с двумя современными позиционными записями A («Гилл стал пастором») и B («вечном завете»), привязанными к исходным абзацам. Обе переживают импорт. Написать **через карточку цитаты** одну заметку к A и одну к B.
2. Открыть W57 → «Пометы» → по очереди «Изменить заметку» у A/B. После загрузки обоих редакторов значения правильные, совпадают с сохранёнными. Это закрывает ранее не проверявшийся однозначный маршрут import → Library note → reopen W57 для современной записи, не для legacy без `annotation`.
3. Снова в обычной Library открыть у A действие «Заметка» и сохранить вторую заметку. Обе записи с `quoteId=A` остаются в хранилище, удалений нет. После повторной загрузки W57 карточка A теперь пишет «Добавить заметку» и открывает **пустой** редактор, будто связанных записей нет. Сохранение создаёт третью запись и назначает её единственной видимой через `annotation.noteId`. После reload W57 показывает третью, B по-прежнему показывает свою контрольную заметку. Исходные две заметки не уничтожены, но недоступны через редактор A в W57.

Причина: библиотечное действие `note-for-quote` позволяет законное отношение 1→N, а `reader_w57_annotations.js: linkedNote` возвращает `null` при нескольких `quoteId` без явного `noteId`. Не чинить выбором «первой подходящей» или дедупликацией заметок. Нужен один контракт: если модель 1→N, отразить все и выбирать редактируемую запись по `note.id`; если нужна одна основная, явно дать её выбрать и никогда не скрывать остальные. Это конфликт cardinality общего хранилища и двух редакторов, не сбой импорта и не выбор чужой цитаты B.

## Контроль «Аналитика → Библиотека»

`6b7d7c3` и `4acccee`, 320×568 и 390×844: «Мои пометы» → клавиатурный Enter по «Открыть библиотеку» закрывает Аналитику и ставит фокус на `#gb-hl-close`; Escape снимает lock и возвращает на видимую нижнюю кнопку `#gb-hl-fab`, y сохраняется; Tab идёт дальше на PDF. Прямой вход из той же нижней кнопки даёт тот же результат. **Не найден дефект фокуса на этом маршруте.** Library пока использует отдельный механизм локальной блокировки, поэтому пустой `OverlayRuntime.topLayer()` при открытой Библиотеке сам по себе не доказательство потери модальности.

## Запуск

```sh
node audit/analytics-handoff-qa/probe.mjs
node audit/analytics-handoff-qa/linked-notes.mjs
```

`ONLY_SHA` фильтрует префикс SHA; `AUDIT_ROOT` задаёт root выбранной сборки, `AUDIT_OUT` — папку JSON/PNG. `W58_PLAYWRIGHT`, `W58_CHROMIUM_PATH` и библиотечный путь Chromium можно задать для локального раннера. В `reports/analytics-handoff-qa/` — измерения и кадры, в `current/` — дополнительный системный/встроенный motion retest точного `4acccee`. Границы: Chromium эмуляция + Playwright keyboard; не физическая клавиатура телефона, не WebKit и не синхронизация между устройствами. Продуктовый код не менялся.
