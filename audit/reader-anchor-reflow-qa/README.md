## RA-01 — вставка абзаца скрывает существующую помету (регрессия)

1. Открыть «Джон Гилл — Часть II» на 390×844, выделить «Гилл стал пастором» (в зонде выделение задаётся через DOM Range, не long press), тапнуть янтарный маркер обычным контролом выделения.
2. На том же origin загрузить статью, в HTML которой **добавлен один абзац перед исходным**. Исходный абзац и вся его разметка, JS, CSS и пользовательское хранилище остаются без изменений. Это имитация редакторского обновления публикации, не утверждение, что в PR меняли текст статьи или что баг возникает на любой перезагрузке.
3. Сохранённый `gill-search-p-013` теперь стоит на добавленном абзаце, исходный — `gill-search-p-014`. На старом коде помета остаётся на исходнике; на новом `resolveRange → null`, мобильный слой подсветки пуст. ID записи и весь её anchor неизменны, исходный HTML сразу возвращает подсветку. Это потеря привязки, не удаление записи.

| HTML после сохранения | `a595629f` | `615eff9a` |
|---|---|---|
| Неизменная статья | исходник `p-013`, `0…18` | исходник `p-013`, `0…18` |
| Добавлен несвязанный абзац перед исходным | исходник `p-014`, `0…18` | **нет диапазона, нет подсветки** |

| В начало самого исходного абзаца добавлено «Уточнение редактора. » | исходник `p-013`, `21…39` | исходник `p-013`, `21…39` |
| Исходный абзац удалён, похожая фраза есть только в другом `p-014` | **ошибочно новый `p-014`** | нет диапазона — безопасное улучшение |
| Возвращён неизменный HTML | исходник `p-013`, `0…18` | исходник `p-013`, `0…18` |

Причина: `GillLearningSheet.astro:176–180` назначает `gill-search-p-NNN` по порядку `h2,h3,p,blockquote,li`, а `js/highlights.js:122–144` считает найденный ID стабильным независимо от происхождения. Не откатывать защиту от ложного перепривязывания целиком. Для порядковых ID искать единственный блок с **полным исходным отпечатком и совпадающим фрагментом/контекстом**, не давать текущему `NNN` победить на коротком контексте. При неоднозначности или исчезновении исходника — не рисовать на другой цитате. Проверить оба случая с вставкой и контроль удаления до принятия фикса. Редакционные ID и существующие сохранения не переписывать из-за одного просмотра.
