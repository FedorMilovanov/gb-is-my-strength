# Mobile Reader: панорама увеличенной страницы и переход по серии

Проверено на #2346 `62be8caa145fbe18aa099dff89cffa20cd626451` и отдельно на #2352 `8197727986ae2b1ddae14f3061bd6905041c8d13`. Chromium 153, 390×844, visual viewport 195×422 CSS px при масштабе 2×; штатный dist, trusted CDP touch. По пять сцен на SHA, без pageerror.

## ZM-01 — свайп для панорамы может увести в другую главу

1. Открыть Gill II `/articles/dzhon-gill-chast-2-uchenyi/` или «Гонения и совесть» `/baptisty-rossii/goneniya-i-sovest/`, прокрутить примерно до y=2400. Установить браузерный масштаб 2×.
2. Повторить горизонтальный жест по тексту от (143, 300) до (18, 300), примерно 260 мс, отпуская палец после каждого жеста.
3. Первые жесты обычно панорамируют вправо (`visualViewport.offsetLeft` до 195) и сохраняют URL; параллельно может появиться peek следующей части. На полностью или почти панорамированном экране следующий такой жест переключает серию: на «Часть III. Экзегет» или «Советская ночь». На `8197727` это третий жест в обеих сериях; на `62be8caa` — третий для Gill, второй для Baptist (старт `offsetLeft=186`, во время движения уже 195). В предыдущих прогонах число жестов варьировалось из-за остаточной панорамы.

В момент перехода на 2× скриншот Gill показывает только угол карточки внизу; её название находится на y≈451–469 при видимой высоте 422 CSS px, то есть не читается даже на пороге перехода. Это не просто поднятие карточки: меняется `location.pathname`. При первых жестах ложный peek закрывается без навигации.

Контроли: вертикальный жест при 2× панорамирует без peek/перехода; при 1× тот же класс горизонтального жеста по Gill штатно открывает следующую часть; standalone «Герменевтика» при 2× панорамируется до offsetLeft=195, без карточки и перехода даже после повторных жестов. `initSwipeNav` проверяет локальные горизонтальные контейнеры, но не учитывает масштаб visual viewport. Критерий проверки исправления: панорама при масштабе >1 не вызывает перехода и не обещает его даже на краю; обычный свайп серии при 1× сохранён.

Ограничение: `Emulation.setPageScaleFactor` устанавливает браузерный масштаб; это **не** тест pinch, WebKit или физического телефона. Два способа синтетического pinch в этой сборке Chromium не меняли масштаб, поэтому исключены из измерения. Скрины содержат фактический видимый viewport, а не DOM всей карточки.
