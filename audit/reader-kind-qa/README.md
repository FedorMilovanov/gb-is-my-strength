# Reader: тип сохранения, фокус при live update и мобильная отмена

Exact #2352 `a595629f15a2324205cbb9b1c2cb2cc936814214`, существующая production-like сборка, guards G1–G8 PASS. Прототип оформления Classic не подключён. Chromium 153, 3 desktop↔mobile сценария, 3 мобильных viewport для Undo и 2 сценария двух вкладок, без `pageerror`. Отдельные тестовые профили одного origin. W57: реальное выделение мышью. Mobile Undo: заранее заданный Range, затем доверенный tap; это не нативное long press и не физический телефон/WebKit.

## RK-01 — мобильная версия рисует подчёркивание и простую цитату как закрашенную помету

1. В desktop W57 1440×900 выбрать «Гилл стал пастором», сохранить по отдельности «Маркер», «Подчеркнуть», «Цитата» (чистый профиль на тип). Открытая до сохранения вкладка Product при ширине 390 получает обновление через storage, затем перезагрузить её. Реальная статья, один origin, те же запись и якорь.
2. Во всех случаях совпадает позиция `gill-search-p-013`, DOM offsets `0…18`, текст и ID записи. Слои до/после:

| Сохранено в W57 | Desktop W57 | Product mobile (live и reload) | «Мои пометы» на mobile |
|---|---|---|---|
| Маркер | `np-w57-marker-amber` | `gb-hl-amber` (ожидаемо) | «Помета» |
| Подчёркивание | `np-w57-underline-amber` | **`gb-hl-amber`, фон вместо линии** | **«Цитата»** |
| Цитата | ни одного слоя | **`gb-hl-amber`, хотя не просили помету** | «Цитата» |

3. Перезагрузка desktop возвращает его исходное представление. Тип **не теряется из данных** (`annotation.kind` сохранён), двойного painter в этих трёх сценариях не видно. Ошибка в выборе визуального слоя: Product `paintMarks()` отдаёт фону любой цвет, в том числе `annotation.color` при `kind=quote`/`underline`; мобильный список не различает underline. Перед рендером разрешать общий `kind` вместе с цветом: plain quote без закраски, underline с линией, marker с фоном. Не менять точные anchors и не пытаться чинить это второй записью или вторым painter.

## RK-02 — live update оставляет фокус на кнопке, которую больше не видно

Вкладка А: Product mobile 320×568 / 390×844, верхняя кнопка «Аналитика», открыть «Мои пометы» и поставить фокус на видимую «Открыть библиотеку». Вкладка Б: штатная Библиотека той же статьи, сохранить новую длинную заметку. В А количество меняется `0→1`, выбранное Писание, раскрытие группы и `scrollTop` сохраняются. Но оригинальная кнопка заменена, а новый узел фокусируется с `preventScroll:true`, когда уже находится **за пределами viewport**:

| Вид | Кнопка до / после (y CSS px) | Область прокрутки | Видимо после |
|---|---:|---:|---:|
| 320×568 | `403–447` → `874–918` | `244–489` | 0 из 44 px |
| 390×844 | `679–723` → `1069–1113` | `329–765` | 0 из 44 px |

После обновления Enter по-прежнему открывает Библиотеку — это потеря **видимого фокуса**, не блокирование действия. Сам прямой вход работает: dialog label «Аналитика · исследовательские материалы», начальный фокус `#gbrMarginaliaTab`. Критерий: не пересоздавать CTA при добавлении записи; если реально сфокусированный элемент уехал из области просмотра, либо держать CTA вне переменной части, либо аккуратно вернуть его в видимую зону. Не скроллить за пользователя, когда фокус в другом месте.

## Контроль обычной отмены пометы

На 320×568, 390×844 и 568×320 «Помета сохранена и подсвечена» + «Вернуть»: кнопка 44 px высотой, hit-test попадает в неё. Тап убирает единственную запись; после reload она не возвращается. Это только простая отмена создания, не конфликт с параллельным импортом/редактированием.

## Запуск

```sh
node audit/reader-kind-qa/probe.mjs
node audit/reader-kind-qa/live-focus.mjs
```

`QA_ROOT` — точный собранный архив, `QA_SHA` — метка отчёта, `QA_OUT` — папка артефактов. Нужны Python и Playwright; `W58_PLAYWRIGHT`, `W58_CHROMIUM_PATH` задают локальный раннер. JSON/кадры в `reports/reader-kind-qa/`. Product и desktop-стили не менялись.
