## Свайп внутри статьи — кто получает жест?

Gill II, p-068, область прозы или первая широкая таблица, а не край экрана. Отдельный профиль и загрузка для каждого жеста. DevTools `touchStart → touchMove → touchEnd` (или `touchCancel`); сохранены реальный маршрут и scroll до/после, состояние карточки **до** отпускания. Исходное положение выставлено перед жестом; ни решение навигации, ни геометрия не подменялись.

| Опыт | Наблюдение |
|---|---|
| Прямой свайп 141 px | На 390×844 оба направления работают. На 320×568 «Назад» работает, «Дальше» из того же абзаца нет, карточка не появляется. Независимый повтор ранее описанного в #2346, не новая регрессия кандидата. |
| Чтение с изменением направления, 390×844 | Начать 32 px влево, затем 69 px влево и 170 px вверх. Хотя итоговое движение преимущественно вертикальное, открывается «Часть III. Экзегет». Контроль: диагональ сразу (99 влево, 144 вверх) и чистая вертикаль прокручивают статью, главу не меняют. При 320 левый переход из абзаца подавлен, этот изогнутый жест прокручивает текст. |
| Таблица, 390×844 | Первый свайп внутри таблицы прокручивает её от 0 до 157 px без перехода. На правом пределе следующий такой же свайп **внутри ячейки** открывает следующую главу. На 320 предел 222 px, в этом опыте глава не меняется. Это не потеря содержимого, а неоднозначная передача жеста между таблицей и статьёй. |
| Смена решения, 390×844 | 130 px влево и 105 обратно → остаёмся на странице. `touchCancel` после 136 px тоже не ведёт в соседнюю главу. Удержать карточку после 135 px дольше 1.2 с, затем отпустить → перехода нет. |
| Обещание подсказки, 390×844 | На 62 и 90 px уже показывается «Отпустите, чтобы перейти», но отпускание не переводит. На 92 px — переводит. При пороге видно лишь 90–92 из 200 px карточки. Обложка имеет `background-image: url("")`; верх — пустой коричневый прямоугольник. Надпись не различает состояния «тяните дальше», «готово», «истекло время». |

Два риска (изгиб и край таблицы) подтвердились на **обоих SHA** при 390. В `js/floating-cluster-controller.js:initSwipeNav` угол проверяется только до первого выбора направления, а `finish` оценивает горизонтальную дистанцию и время. `wantsHijack` уступает только пока элемент ещё может скроллиться в нужную сторону. **Рекомендация:** отменять переход при крупном вертикальном уходе после начала жеста, оставлять жест, начатый внутри прокручиваемой таблицы, этой таблице до отпускания. Не ломать вертикальное чтение, отмену, rail скорости и осознанный переход по прозе. Для карточки — показывать честное состояние порога, а без обложки оставлять больше места названию.

## Что видно глазу

- **Действительное улучшение в #2352:** на 320 название «Часть II. Учёный» помещается в две строки вместо «Часть II. Учён…»; кикер скрыт визуально, панель остаётся 62 px. На 390 название помещается в одну строку. В заголовке библиотеки исчезла лишняя иконка ссылки, но на 320 «Моя библиотека» всё ещё ломается посреди слова рядом с Markdown и меню. Экспорт уже визуально конкурирует с названием.
- **Не пустая библиотека, а слишком маленькое окно списка.** На 320×568 сохранена одна заметка, выполнен reload, открыта вкладка «Заметки». В светлой и ночной темах на карточки осталось **17 px высоты** (контент 262 px), текст самой заметки — 46 px. Свайп двигает внутренний список на 106 px, но окно не расширяет. В то же время экран занят заголовком, двумя рядами фильтров и нижней кнопкой. На 390×844 окно — 286 px; на 320×520 вместо этой щели прокручивается вся панель. Не потеря данных. Сначала выделить место собственно списку; фильтры и экспорт можно убрать на второй уровень на тесных экранах.
- **Ночная тема:** у «Новая заметка» почти белый текст `rgb(255,250,243)` на светлом персиковом `rgb(217,169,142)` при 13 px. Контраст по относительной яркости **2.02:1** против **8.96:1** в светлой теме. Это замер плоской заливки конкретной кнопки, не заявление о контрасте всего интерфейса. Для мелкого текста ориентир 4.5:1; достаточно поменять цвет надписи в ночной теме, не переделывать всю палитру.
- Дополнительно просмотрены «Аналитика» и настройки в портрете и при 568×320. На коротком экране часть списка настроек ниже видимой области, но кнопка «Готово» достижима обычным `tap()` с автопрокруткой. Это не тест физической клавиатуры и не доказательство поломки шторки.

## Воспроизведение и границы

`git archive` каждого SHA, согласованный lockfile, Node 22; отдельная сборка кандидата через Astro build → copy-legacy → cache-bust/postbuild → heading/guards, `GB_BUILD_INSTANT` по коммиту, штатный preview.py. Локально, Chromium touch emulation, reduced motion, шрифты страницы загружены. Не тестировались WebKit, физический edge-back ОС или звук. Координаты/пороги относятся к описанным маршрутам, не ко всему сайту.

- [Кандидат, 22 жеста и 3 визуальных размера](gestures.jsonl), [порог, 4 дополнительных жеста и повтор размеров](threshold.jsonl), [контроль #2346](control-62be8caa.jsonl), [библиотека с сохранённой записью](library.jsonl).
- `READER_URL=http://127.0.0.1:19070 node research/reader-w57-audit/swipes/gesture.mjs` (опционально `CASES=next,bent,table-inside,table-at-end`). `library-visual.mjs` там же. `PLAYWRIGHT_MODULE`, `CHROMIUM_PATH` и `SHOTS` — опциональны (создать каталог снимков перед library-visual). Матрица жестов возвращает 1 при расхождении с ожидаемой навигацией; визуальный тест записывает измерения, его exit 0 не означает одобрения дизайна.
