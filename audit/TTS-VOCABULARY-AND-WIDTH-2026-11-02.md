### 2.2 Словарь ударений покрывал не все формы

`js/vosk-custom-terms.json` (156 форм) знал `христоцентричная` и `христоцентричный`, но не знал ни одной другой формы — а в статье 151 раз встречается `христоцентричной`. Так же не были покрыты `христология/христологии/христологию…`, `христотелический`, `сотериология`, `экклезиология`, `тринитарный`, `импликация`, `эйзегеза`, `межтекстуальность`.

Отдельная находка: встроенный словарь `russian-stress-marker` (721 КБ FSA) для слова `коринфянам` отдаёт **`кор+инфянам`** — неверное ударение, которое до правки попадало прямо в синтез, потому что пользовательский словарь это слово не перекрывал.

### 2.3 Данные словаря не доставлялись после обновления

`fetch(CUSTOM_TERMS_URL, { cache: 'force-cache' })` без `?v=`: браузер обязан брать копию из кэша, не переспрашивая сервер. Даже исправленный словарь остался бы у владельца старым навсегда. Это дефект доставки, а не словаря.

## 4. Ширина: измерение и что изменено

Геометрия колонки владеется тремя токенами: `--gb-reader-measure` (`css/reader-preferences.css`), `--hm-article-measure`/`--hm-article-shell` (`ReaderSettings.astro`), и ограничением рельса `--hrail-readable-space` (`ReaderRail.astro`, только ≥1200px).

| Режим | Было | Стало |
|---|---|---|
| Узкая | 36rem = **576px** | 576px (не менялось) |
| Обычная | 46rem = **736px** | 736px (не менялось, это решение #2218 от 2026-10-29 по запросу «дефолт узкий какой-то») |
| Шире | 52rem → фактически **784–832px** (упиралось в `--hrail-readable-space` и в потолок Gill-канвы 900px) | 53rem = **848px текста** на всех канвах (Gill: 896px оболочки − 48px отступов) |

На Gill-канвах (`css/floating-cluster.css`) оболочка считается как `measure + 48px` и зажата жёстким потолком 900px. Поднимать потолок нельзя: на 1440px три браузерных контракта (`engine-sweep`, `reader-controls-residual`, `standalone-reader-layout-guard`) ловят, что при оболочке 944px кнопка скорости перекрывает коридор текста. Поэтому токен «Шире» выбран **53rem**: 53rem + 48px = 896px < 900px, то есть режим честно равен своему значению на всех канвах, а не «зажимается в другой размер».

Расчёт для 1280×800: `--hrail-left` 30.7 + рельс 270 + зазор 38.4 = 339.1; максимальная оболочка 927; при 53rem оболочка = 53rem + 6rem = 944 → ограничена 927 → но текст ограничен токеном 53rem = **848px** (было 784–832).

Причина, по которой «Шире» раньше почти ничего не давало: 52rem (832) почти совпадало с 832-пиксельной оболочкой, а `--hrail-readable-space` съедал ещё 48px внутренних отступов.

Что это значит для «статья выглядит узкой»:

- если в настройках читателя стоит **«Узкая»** — это 576px, самая вероятная причина жалобы; переключатель находится в шестерёнке читателя, группа «Ширина статьи»;
- режим «Обычная» 736px — это ~80 знаков в строке, верхняя граница типографической нормы; дальше расширять по умолчанию вредно для чтения, поэтому дефолт не менялся;
- «Шире» теперь реально шире (879–896px вместо 784–832).

## 6. Что осталось открытым осознанно

1. `Захария`, `Малахия`, `Авдия` — ударение в русской традиции двоится, оставлено без маркера (`STRESS_PENDING`).
2. `греч.`, `евр.`, `лат.`, `арам.`, `англ.`, `нем.` — не разворачиваются: согласование
   прилагательного с существительным без разбора фразы даст «греческий слово».
   Замер по корпусу (2026-11-03), 542 файла: всего 392 вхождения этих ярлыков.
   254 из них стоят перед числом — это `Евр.` как книга Писания, её разворачивает
   слой цитат. Остаётся 138 «языковых» ярлыков: после 88 идёт иноязычная графика
   или латиница (`греч. καρδία`, `лат. implicatio`), которую синтезатор всё равно
   отбрасывает, а после 50 — русское слово (`евр. текст`, `греч. оригинал`,
   `Евр. нумерации`). Поэтому наречие («по-гречески») испортит 50 случаев, а
   прилагательное в мужском роде («греческий») — часть из 88; универсальной
   подстановки без разбора фразы нет, и «на глаз» выбирать между ними — костыль.
3. `г.` (год) и `в.` (век) — падеж зависит от контекста («в 1950 г.» → «в 1950 году», «1950 г.» → «1950 год»); оставлено без изменений, чтобы не порождать неверную грамматику.
4. Аббревиатура `ЕХБ` читается по буквам — для названия союза это допустимо; менять на развёрнутое название означало бы менять смысл цитат.

Каждый пункт закрывается только вместе с источником (словарь ударений / разбор фразы), а не «на глаз».

Эффект по корпусу: уникальных слов без источника ударения стало 6116 вместо 6146.
Остальные частотные «пробелы» — обычные слова (`грех`, `здесь`, `сердца`, `есть`,

`injectCustomStress` через `state.dic.has(lower)`), а маркерный слой сайта
описывает только терминологию и имена собственные. Заносить общие слова в
`js/vosk-custom-terms.json` — значит дублировать источник ударения и получить два
конфликтующих ответа; поэтому они оставлены как есть.

молча возвращает пустоту): `машина → маши'на`, `привет → приве'т`,
`человек → челове'к`; для `грех`, `здесь`, `сердца` FSA ответа не даёт — эти слова
и в самом деле приходят без маркера и остаются на модель.

она недоступна.

### 7.5 Римские номера в ссылках (найдено прогоном по корпусу)

Сплошной прогон разворачивателя по 712 исходным файлам (ранее — по 57 собранным
страницам) показал асимметрию: `гл.`/`ст.` с **арабским** числом разворачивались
(135 ссылок), а с **римским** — нет. `(гл. XIV)` оставалось как есть, и только
следующий проход превращал `XIV` → `14`, оставляя огрызок «гл. 14».

Причина в правиле: lookahead шаблона требовал `\d` и не принимал `[IVXLCDM]+`.
Исправлено в самом правиле, а не постобработкой:

```
было:  (?=\s*\d)
стало: (?=\s*(?:\d|[IVXLCDM]+\b))
```

| вход | было | стало |
| --- | --- | --- |
| `гл. XIV` | `гл. 14` | `глава 14` |
| `в гл. XIV сказано` | `в гл. 14 сказано` | `в главе 14 сказано` |
| `см. гл. III` | `см. гл. 3` | `смотри главу 3` |
| `по ст. V` | `по ст. 5` | `по стиху 5` |
| `гл. обр.` | `гл. обр.` | `гл. обр.` (не трогается) |

В корпусе таких ссылок семь: `гл. III` ×4, `гл. XIV` ×2, `гл. I` ×1. После правки
остаток по корпусу — 0 (арабских и римских), «гл. обр.» на месте.

Стресс-контракт получил пять новых случаев разворачивания и девятую мутацию —
«шаблон цитат теряет римские номера»; мутация проверена отдельно: она
воспроизводит прежнее поведение (`в гл. XIV` → `в гл. 14`) и гейт её отклоняет.

### 7.6 Остаток аббревиатур теперь проверяется по корпусу, а не по примерам

Ручные случаи доказывают только то, что кто-то вспомнил. Поэтому в
`scripts/tts-stress-dictionary-contract.js` добавлена корпусная проверка остатка:
каждая поверхность (`SCRIPTURE_BOOKS` + `CITATION_UNITS` + `SITE_ABBREVIATIONS`,
105 штук) ищется в уже развёрнутом тексте 542 файлов контента; если аббревиатура
дожила до числа — гейт падает с указанием, сколько опубликованных ссылок её несут.

Проверено, что гейт действительно ловит регрессию: при откате исправления из §7.5
он падает сразу двумя сообщениями —

```
гл.: roman-numeral reference keeps the case form — «в гл. XIV» reads as «в гл. 14»
гл.: 7 published citation(s) still carry the abbreviation before a number
```

— и снова проходит, когда правило на месте. Стоимость проверки — около 5 секунд на
весь прогон гейта.

### 7.7 Косая черта между числами

Проверка того, что реально уходит в модель, дала ещё одну тихую потерю. В прозе
корпуса 109 конструкций вида `число/число` — библиографические ссылки
(`JETS 53/4`), страницы (`pp. 587/586`), годы (`1959/1960`). `normalizeText`
превращал `53/4` в «пятьдесят три четыре»: слэш не слово, его вычищал финальный
фильтр, и два числа слипались в один поток.

Добавлено одно правило — слэш между цифрами становится паузой (запятой), а не
смыслом, которого в нём нет:

```
t = t.replace(/(\d)\s*\/\s*(\d)/g, '$1, $2');
```

| вход | было | стало |
| --- | --- | --- |
| `53/4` | пятьдесят три четыре | пятьдесят три , четыре |
| `1959/1960` | тысяча девятьсот пятьдесят девять тысяча девятьсот шестьдесят | …девять , тысяча девятьсот шестьдесят |
| `3,5` | три целых пять | три целых пять (не тронуто) |

Смысл не додумывается: правило не решает, «выпуск это или диапазон», оно лишь
не даёт двум числам слиться. Контракт получил три случая `normalizeText` и
проверку, что слэш вообще не доживает до входа модели; откат правила роняет гейт
сообщением «spoken normalization drifted for "53/4"».

### 7.8 Перекрёстная проверка ударений: наш словарь против независимого источника

«Проверить каждое слово» нельзя сделать только глазами, поэтому словарь сверен с
независимым слоем `russian-stress-marker` (`js/vosk-stress-marker.bin`): для каждого
слова, которое знают оба источника, сравнивается позиция ударной гласной.

```
записей в словаре:                        382
есть и там, и там (сверено):                6
ответа нет — только наш словарь:          376
расхождений:                                0  (после правки ниже)
```

Первая же сверка нашла настоящую ошибку:

| слово | было у нас | независимый источник |
| --- | --- | --- |
| `коринфянам` | `коринф+янам` (коринфя́нам) | `кор+инфянам` (кори́нфянам) |

Норма — «Кори́нфянам» (Кори́нфская церковь, коринфя́не так не говорят), то есть в
словаре стояло ударение на последний слог, и голос произносил так каждую ссылку
`1 Кор.`, которую разворачивает слой цитат. Исправлено на `кор+инфянам`.

Чтобы такой класс ошибок не вернулся молча, в контракт добавлено правило: там, где
независимый словарь тоже знает слово, ударения обязаны совпадать; расхождение
допускается только через явный список `STRESS_OVERRIDES` с причиной (сейчас пуст).
Плюс десятая мутация — «наше ударение противоречит маркерному словарю» — гейт её
отклоняет.

Оговорка: 376 из 382 слов в независимом словаре отсутствуют (это имена, термины и
редкая лексика), поэтому сверка подтверждает только те шесть. Для остальных
единственный источник — транскрипции, собранные в §3, и они остаются на совести
словаря, а не гейта.

### 7.9 Сокращения разворачивались внутри обычных слов

Сайтовые сокращения (`ок.`, `т.е.`, `н. э.`, `т.п.`…) подставлялись простым
`split/join` по подстроке — без границ слова. Из-за этого `ок.` срабатывал внутри
любого слова, которое кончается теми же буквами:

```
«…множество отдельных ошибок.»  →  «…множество отдельных ошибоколо»
«…законный порядок.»            →  «…законный порядоколо»
```

В корпусе 82 таких слова (`порядок.` ×16, `ошибок.` ×13, `срок.`, `ребёнок.`,
`список.`, `поток.`, `крючок.`…), и каждое озвучивалось испорченным.

Замена сделана по границам слова, а не по подстроке:

```js
var pattern = new RegExp('(^|[^\\p{L}\\p{N}])' + abbreviation + '(?![\\p{L}\\p{N}])', 'gu');
output = output.replace(pattern, function (whole, before) { return before + expansion; });
```

| вход | было | стало |
| --- | --- | --- |
| `законный порядок.` | законный порядоколо | законный порядок. |
| `без ошибок.` | без ошибоколо | без ошибок. |
| `ок. 1950 года` | около 1950 года | около 1950 года (не изменилось) |

Самостоятельных `ок.` в корпусе 61 — все продолжают разворачиваться в «около».

Контракт получил пять случаев на границы слов и одиннадцатую мутацию — «сайтовые
сокращения снова подставляются как подстрока»; мутация воспроизводит прежнее
поведение (`«Это порядок.»` → `«Это порядоколо»`) и гейтом отклоняется.
