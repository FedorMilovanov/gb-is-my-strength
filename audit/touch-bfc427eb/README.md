# Выделение → «Мои пометы» → источник: это то самое место?

PR #2352: контроль `4accceeef1f01e0cc19bb0fe4f807e49758a2892`, после touch/toast push `bfc427eb55d89dfa3c3bfed4443b39109aa49dbe`, повтор на следующем [`8d03615`](../scripture-8d03615/README.md). Не смешивать с head #2346. Отдельные git archive/локальные сборки. У bfc прошли strangler:build, postbuild guards, highlights-runtime-regression-test. Изолированные Chromium touch-профили, высота 844, программный DOM Range **только для выделения**, настоящие тапы панели/библиотеки, нет прямой записи в storage или вызова save/paint. Не тест системных ручек выделения, Safari или физического телефона.

## 1. Источник маркера перепутан ещё до первого сохранения

В опубликованном Gill II `gill-search-p-033` фраза **«Песнь Песней» встречается дважды в одном текстовом узле**. Выбрать второе место (offset 365), тапнуть розовый. Подтверждение «Помета сохранена и подсвечена»; `CSS.highlights` действительно содержит розовый Range, но **на offset 10**, в первом вхождении. Storage `before` = «Для Гилла » — это начало абзаца перед первым вхождением. Теперь выделить *первое* и тапнуть голубой: вместо двух независимых помет меняется цвет прежнего ID. «Вернуть» восстанавливает цвет, но не правильное место. После reload и отложенного paint та же неправильная позиция. «Мои пометы» показывает одну запись.

Это **не** случай desktop W57 v1 → mobile или гонка двух вкладок: чистый мобильный профиль, один продуктовый painter. Причина видна в `js/reader-library-dock.js:contextFromSelection`: берётся начало абзаца и `full.indexOf(text.slice(0,80))`, не фактический offset Range. Цвет определяется по тексту+контексту, так что дальше уже нечем восстановить исходное различие. В том же абзаце уникальный контроль «последовательная» (offset 28) сохраняет правильное место, меняет цвет той же записи, Undo и reload восстанавливают розовый на 28. Править идентичность места при захвате выделения, а не только поиск при покраске. Критерий: оба места имеют собственные ID и диапазоны даже при одинаковом тексте/цвете. [Снимки](selection.jpg).

## 2. Ссылка записи на текущую статью меняет hash под открытым модальным окном

Сохранить цитату или заметку к выделению штатной панелью. После загрузки с начала статьи: «Аналитика → Мои пометы → Открыть библиотеку → название статьи» у записи. Текст и тип записи верны; у заметки сохранена цитируемая фраза. Ссылка содержит адрес статьи, нужный id абзаца и `:~:text=…`. На обычном URL без query после тапа **hash уже `#gill-search-p-033`, библиотека остаётся открытой, body фиксирован**. Даже ручное закрытие оставляет страницу на y=0, целевой абзац в 11885 px от верхнего края (320) или 9814 px (390). Одинаково для цитаты и заметки. В `reader-library-presenter.js:renderItem` это обычный `<a href=item.url>`: для перехода внутри того же документа не случается перезагрузка, которая автоматически убрала бы модальное окно. Закрывать слой до перехода и не перетирать целевой скролл восстановлением исходной позиции.

Контроль: с `?reader-pilot=1` та же ссылка без query загружает другой документ. Первый замер через 1,1 с нестабилен, id абзаца генерируется в рантайме. После ожидания появления id и ещё 1,4 с в **6/6** повторов 320/390 окно закрыто, `sourceTop=144`. Ранний промах этого контроля не считаем отдельным дефектом.

## Что изменилось и что осталось

- На bfc 320/390 тапы «Цитата», «Заметка», цветов и «Вернуть» сработали. На 390 уведомление стало **359×64** вместо **219×93** ранее, на 320 — 294×64. В центре Undo попадаем именно в кнопку. На старом SHA действия при таком способе выделения тоже работали — восстановление нативного long-press этим сравнением не доказано.
- Повтор старых проверок на bfc, 390: Tab сам определение не открыл, Escape вернул фокус/скролл (допуск округления 1 px). ArrowRight при открытом глоссарии и свайп по его фону по-прежнему меняют главу. Изменение/удаление заметки в соседней вкладке всё ещё не обновляет открытую группу.

`research/reader-w57-audit/analytics/selection-source.mjs`: `READER_URL` — origin сборки, `WIDTHS=320,390`, `MODES=repeat,unique,quote,note,quote-cross`, `SHOTS` — существующий каталог; `PLAYWRIGHT_MODULE` и `CHROMIUM_PATH` опциональны. Код 1 — расхождение; `*.jsonl` рядом содержат offsets, ID, координаты, состояние слоёв и контрольные повторы. Ошибка преждевременного чтения DOM в одном раннем cross-run не входит в подтверждённые дефекты.
