## #2346 — новые/оставшиеся проблемы

**MB-01 — уплотнение снова сломало область нажатия Play и добавило перекрытие настроек.** В Gill II 320/390/431/700/961 доверенный тап `(Play.left+27, Play.top+32)` открывает скорости вместо Play (`idle`), хотя в `249bb866` эта точка запускала озвучку на сопоставимых ширинах. Теперь и левая часть **самой кнопки настроек** открывает скорости: тап на `Settings.left+4.5, Settings.top+22.5` воспроизводится на всех пяти ширинах. Центры Settings и видимого chip работают; не утверждаю, что перехвачен нарисованный значок Settings. Из 1936 точек её прямоугольника badge перехватывает 352–528; у 320 это вся полоса 12×44. Причина — группа 44px, speed badge начинается с x=12 и прозрачный pseudo hit выходит за правый край группы. Центр прямоугольника самого badge теперь принадлежит Play. На exact сборке неизменённый штатный Chromium a11y-контракт (адаптирован только launcher в `/tmp`) падает по timeout `locator.click('.mobile-spdbadge')` с `Play intercepts pointer events`; до изменений было 155/155. Зафиксировать фактические непересекающиеся действия, не лечить один тест нажатием только на центр видимого chip: иначе gear-edge остаётся сломанным.

**MB-02 — импорт старого формата всё ещё теряет одну из двух цитат и оставляет осиротевшую заметку.** Через реальный UI в пустую Библиотеку Gill II 390 загружена небольшая синтетическая JSON-копия v3: две цитаты с одинаковым текстом «вечном завете», ID A и B, разные `url#…059/#…068` и контекст, без `annotation` (допустимая старая форма), заметка с `quoteId=B`. Диалог подтверждения сообщает о двух цитатах; после подтверждения в store **только A**, заметка по-прежнему ссылается на отсутствующий B, UI сообщает «Импорт завершён без замены существующих записей». `safeMerge()` теперь сохраняет разные ID, но глобальный `Storage.prototype.setItem` guard в `js/site-utils.js::dedupeHighlights()` для старой формы всё ещё режет по пути страницы + тексту. Устранить конфликт двух владельцев хранения и гарантировать целостность ссылок перед публикацией успешного результата. Не утверждаю, что по этому входу теряются текущие W57 записи со схемой `annotation` — контроль ниже.

## Что подтвердилось в #2346

- **Современная структура с `annotation.version=1`:** две однотекстовые записи на разных позициях с разными ID переживают импорт; из карточки A через Библиотеку создаётся заметка с `quoteId=A`. Реальный JSON, скачанный из UI, повторно импортируется без потери обеих ID или ссылки. Это проверка Библиотеки, не desktop W57 открытия той же заметки.
- **Гонка B4:** задержанный `File.text()` для A не заменяет B (в store после подтверждения только строки B сверх прежних), `Escape` не даёт позднему чтению показать подтверждение. Подменён только тайминг чтения конкретного файла; форма и запись настоящие.
- **Короткая Библиотека:** при 568×320, 390×450, 320×500, 320×520 Locator tap с прокруткой реально открывает редактор и сохраняет заметку. Resize 320×500 → 320×350 не блокирует сохранение: submit прокручивается в достижимую область. На 320×521 сразу за CSS breakpoint снова `overflow:clip`: «Новая заметка» y=518.4–562.4, сверху торчит ~2.6 px; синтетический `locator.tap()` всё-таки срабатывает, поэтому **не объявляю полной блокировки**, но это непригодная видимая цель. На 320×568 центр цели доступен, нижние ~2 px обрезаны. Стоит проверить контракт видимой высоты действия по обе стороны 520, а не только факт клика.
- **Типографика/«Аналитика»:** 320×568 Cormorant Garamond имеет локальный кириллический face, применяется к абзацам, выбор и `aria-pressed` переживают reload, сброс возвращает Lora. Триггер, визуальный H3 и вкладка называются «Аналитика», слой один `gill-part-toc`, Escape возвращает фокус триггеру. Имя диалога по ARIA по-прежнему «Часть II · Учёный» (общее для обеих вкладок); не выдаю это за потерю доступности/фокуса.
