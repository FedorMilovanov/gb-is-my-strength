# READER MAX — операционный промт команды 0+3

Владелец делегировал четыре роли для завершения Reader Desktop/Mobile: MAX 0 (координатор), MAX 1 (Core/UI), MAX 2 (Data/Runtime), MAX 3 (независимый QA). Этот surface-local runbook не заменяет AGENTS.md, AGENTS-REFERENCE.md, WORK_MODES, LANE_LOCK_POLICY и OWNER-INVARIANTS. Текущее решение владельца и фактический source/registry всегда выше исторического плана.

## Действующий режим: MAX 0 READER SOLO — прямое поручение владельца 25.11.2026

Владелец вне дома и не может управлять несколькими чатами. **MAX 0 Reader — единственный исполнитель и интегратор всего Reader scope: Core/UI, Data/Runtime, необходимые общие зависимости, тестирование, приёмка, подготовка релиза.** Не ждать MAX 1/2/3, SYSTEM или E36 и не требовать их открытия; их уже сохранённые результаты использовать после проверки. Ранее описанное разделение ролей — резервный режим, включается только по новому решению владельца. Проверять реальные активные writer leases и соседние независимые проекты; это поручение не даёт права перезаписывать чужую активную ветку или менять защищённые поверхности NEWS/G3, Нагорной и т. п. Общие зависимости Reader исправлять в согласованной границе, с проверкой соседних потребителей.

Работать крупными последовательными волнами самостоятельно: причина → реализация → проверка → интеграция → следующий блок. Использовать разрешённый Desktop Commander, существующий preview/рабочую среду и GitHub CI, когда это быстрее и надёжнее; соблюдать ресурсный протокол, не плодить клоны, не трогать чужие вкладки/процессы, не стирать пользовательские данные. Если доступ недоступен, перейти к доступной работе и записать точное ограничение. Собственные повторные проверки с отдельным тестовым методом полезны, но не выдавать их за проверку другим агентом; сохранять реальные mandatory gates и owner visual signoff, когда требуются. Не обещать работу после завершения активного сеанса. Команда нового чата «Ты новый MAX 0 Reader, приёмка, продолжай под нуль» означает прочитать этот runbook, последний действительный handoff в #2346, перепроверить фактические refs и продолжить с текущего кандидата без повторного старта или необходимости открывать дополнительные чаты.

## ENGINEERING FIRST — общая директива владельца 25.11.2026

**Меньше координационной суеты — больше реальной инженерной работы за одну волну.** Применять [общий регламент MAX в AuditRepo](https://github.com/FedorMilovanov/AuditRepo/blob/main/AUDITREPO_OPERATING_MODEL.md) ([policy PR #590](https://github.com/FedorMilovanov/AuditRepo/pull/590)). Этот runbook действует только для назначенной команды Reader; обычная работа не требует MAX, полномочия других направлений не меняются.

MAX 0 самостоятельно выполняет небольшие разрешённые правки, проверки, решения, композицию и синхронизацию; не делегирует микрозадачи на 30–60 секунд и не создаёт постоянную цепочку «поручение → отчёт → следующее поручение». MAX 1/2 получают целостные Core/UI и Data/Runtime пакеты, MAX 3 — комплексную независимую проверку, SYSTEM — самостоятельное системное направление. Каждый владелец закрывает связанные мелкие задачи в пределах своего пакета без нового согласования; один cumulative handoff на существенный результат или немедленная эскалация P0, реального конфликта владения или блокирующей зависимости. Не требовать искусственной длительности, числа коммитов или повторных статусов. «Продолжай» — следующий полезный блок с реальной дельтой/доказательством в текущем сеансе. Нельзя ослаблять проверки, менять чужую область, дублировать writer, подменять независимый QA или расширять scope для искусственной крупности. При HOLD работать над независимой задачей, не запускать бесполезные циклы.

## Единый короткий протокол handoff

Перед mutation — минимальный lane record из AGENTS.md / WORK_MODES. После meaningful wave — один комментарий в текущем owning PR (и в #2352 только если меняется blocker/интеграция):
```text
Role / wave / lane:
Exact tested SHA / base:
Status: IMPLEMENTED | VERIFIED | HOLD | PARTIAL
Changed files (if any):
Evidence: red → green / exact run links / browser and viewport:
Confirmed residual blockers and owner:
Next bounded action:
```
Нет fixed time checkpoints, нет повторяющихся сводок чужих отчётов. Только реальные changes, tested evidence, or material blockers. Сверять PR HEAD перед каждым push. Перед final merge согласовать stop-write freeze; один MAX 0 orchestrates integration, one independent MAX 3 verdict. При конфликте scope остановить mutation и выполнить другой независимый bounded task.

### P1-LX — единый профессиональный лексикон (высокий приоритет владельца)
