## 1. Нейминг URL (решено, не менять)

| URL | Что это | Почему так |
|---|---|---|
| `/karty/` | Хаб библейских карт | Кириллический транслит = SEO под русские запросы («карта пути Авраама», «карта исхода»). Основной поисковый интент здесь. |
| `/karty/<slug>/` | Конкретная карта (avraam, ishod, pavel…) | Слаг = имя героя/события, короткий, без дефисов где можно. |
| `/map/` | Служебная карта связей статей | НЕ переименовывать в /karta/: (а) служебная страница без поискового интента; (б) смена URL = редиректы без выгоды; (в) разные имена (karty/map) полезно разводят два разных типа карт. |

## 2. Главный принцип: ОДНА базовая карта + маршруты как ДАННЫЕ

Вариант «каждой карте — своя рисованная карта» отвергнут: N карт = N несовместимых
систем координат, N стилей, N мест для багов; любое улучшение базы (рельеф, тени,
новый город) пришлось бы повторять N раз.

Выбрано: **один мастер-макет географии Ближнего Востока** (Месопотамия → Египет →
Малая Азия → Греция/Рим покрывает Авраама, Исход, Давида и Павла) в одной системе
координат SVG. Поверх него страницы накладывают свои слои данных.

### Слои (от нижнего к верхнему)
1. **base-geo** — береговая линия, моря, реки, рельеф (общий для всех карт).
2. **era-labels** — топонимы ЭПОХИ (данные, не часть базы): для Авраама «Ур Халдейский»,
   для Павла на той же территории — «Вавилония/Парфия». Города существуют/не существуют
   по полю `era` в данных.
3. **route** — маршрут конкретной карты: массив точек {id, name, hebrew/greek, coords,
   verses, text, context}, сегменты пути (solid/dashed = достоверный/предполагаемый).
4. **ui** — кинотур, панель остановки, легенда, зум — ОБЩИЙ движок.

### Что это значит практически
- Новая карта = новый JSON маршрута + страница-обёртка. База и движок не трогаются.
- Координаты ВСЕХ маршрутов в одной системе → карты можно накладывать друг на друга
  (будущая фича: «все пути на одной карте», сравнение маршрутов).
- Исправление географии (залив, река) автоматически чинит все карты.

## 3. Текущее состояние и путь миграции (без срочности)

`/karty/avraam/` сейчас — самодостаточный файл (inline SVG+CSS+JS, ~150KB).
Для ОДНОЙ карты это правильно (нет лишних запросов, страница автономна).
Триггер рефакторинга — НАЧАЛО ВТОРОЙ карты:

1. Вынести базовую географию в `karty/_base/geo.svg` (или JS-модуль с path-данными).
2. Вынести движок (зум/тур/панель/маркеры) в `karty/_base/map-engine.js`
   — это НЕ нарушает контракт «11 JS» сайта: раздел /karty/ автономен от site.js
   (своя страница-приложение), как nagornaya имеет tw.min.css.
3. Маршрут Авраама перевести в `karty/avraam/route.json` (данные уже структурированы
   в JS-объектах — перенос механический).
4. Топонимы пометить полем `era: ["bronze","iron","roman"]`.

Правило: НЕ выносить заранее («а вдруг пригодится») — выносить при второй карте,
когда видно, что реально общее.

## 4. Чего НЕ делать
- ❌ Отдельный «сайт»/поддомен на карту — раздел один, хаб /karty/ единая точка входа.
- ❌ Копипаст avraam/index.html под новую карту с правкой координат — только через
  вынос базы (п.3), иначе через 3 карты будет 450KB дублированного кода.
- ❌ Растровые подложки (тайлы, спутник) — SVG-вектор держит зум, темы и вес.
- ❌ Внешние карто-библиотеки (Leaflet/MapLibre) — оверкилл для стилизованной
  исторической карты, ломает эстетику и оффлайн-автономность.
