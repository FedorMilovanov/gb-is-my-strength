# Атлас исследований — UX и interaction specification

Статус: рабочая спецификация внедрения  
Публичный маршрут: `/map/`  
Пользовательское название: **Атлас исследований**

## 1. Продуктовая задача

Атлас не является декоративной схемой. Он должен помогать:

- увидеть тематические кластеры;
- найти конкретный материал;
- приблизить нужную область;
- понять ближайшие связи;
- открыть контекст узла;
- перейти к статье;
- переключиться на доступный список.

## 2. Три масштаба

### Overview

Видны:

- крупные тематические кластеры;
- хабы;
- основные мосты между темами;
- минимальное количество подписей.

Мелкие статьи отображаются точками и не создают шум.

### Cluster

При приближении:

- раскрываются названия материалов;
- видны внутренние связи кластера;
- крупнеют узлы;
- появляются типы наиболее важных линий.

### Detail

При сильном приближении или выборе узла:

- читаются все ближайшие названия;
- показывается окружение глубины 1;
- в панели доступно описание и связанные материалы;
- нерелевантная сеть приглушается.

## 3. Управление картой

Обязательно:

- wheel / trackpad zoom;
- drag pan;
- pinch zoom на touch;
- кнопки `+`, `−`, «Центрировать»;
- кнопка «Показать всё»;
- ограничение минимального и максимального zoom;
- отсутствие бесконечной физической дрожи.

Zoom происходит относительно позиции указателя, а не только центра экрана.

## 4. Desktop layout

Три зоны:

1. Левая панель — темы и типы связей.
2. Центральный canvas/SVG/WebGL — карта.
3. Правая detail panel — выбранный материал.

Панель не является modal и не закрывает выбранный кластер.

Верхняя строка содержит:

- название;
- поиск;
- `Карта / Список`;
- фильтры;
- сброс состояния.

## 5. Mobile layout

- полноэкранный canvas;
- компактный top bar;
- нижний sheet выбранного материала;
- плавающие кнопки zoom/center;
- переключатель `Карта / Список`;
- фильтры открываются отдельным sheet;
- labels показываются только для ближайших узлов.

Bottom sheet имеет состояния:

- collapsed — заголовок и тип;
- medium — описание и основные связи;
- expanded — полный список и действия.

## 6. Focus mode

При выборе узла:

- активный узел получает главный акцент;
- соседние узлы остаются хорошо читаемыми;
- связанные линии усиливаются;
- остальные узлы приглушаются;
- камера плавно центрирует окружение;
- URL получает `focus=<id>`;
- detail panel открывается;
- в списочном режиме выделяется тот же материал.

Повторный клик или Escape снимает focus.

## 7. Фильтры

### Темы

- Джон Гилл;
- Нагорная проповедь;
- Баптисты России;
- Трудные тексты;
- Библейские карты;
- Биографии;
- другие реальные кластеры из данных.

### Типы отношений

Переходный этап:

- внутри темы;
- структурная связь;
- тематический мост.

Целевой этап:

- исторический контекст;
- цитирование;
- объяснение;
- сравнение;
- применение;
- карта/справочник;
- структура серии.

Фильтр действительно меняет видимый граф и синхронный список.

## 8. Поиск

Поиск работает по:

- названию;
- короткому названию;
- тегам;
- описанию;
- теме.

Результат:

- фокусирует узел;
- показывает клавиатурную выдачу;
- поддерживает Enter;
- не требует точного совпадения регистра.

## 9. Detail panel

Содержит:

- relation/type label;
- заголовок;
- аннотацию;
- время чтения;
- тему или серию;
- до пяти ближайших связей;
- человекочитаемый тип связи;
- кнопку «Читать материал»;
- действие «Показать только окружение».

URL берётся только из канонического реестра/данных, никогда не строится по ID догадкой.

## 10. List mode

List mode является равноправным представлением.

Он содержит:

- те же фильтры;
- те же результаты;
- те же counts;
- те же связи;
- настоящие `<a href>`;
- heading hierarchy по темам.

Карта может не загрузиться, а список остаётся полностью работоспособным.

## 11. Визуальный язык

Образ: **ночной музейный богословский атлас**.

- глубокий чернильно-синий фон;
- тёплое золото активного фокуса;
- приглушённые тематические цвета;
- очень слабое зерно;
- линии почти незаметны вне focus;
- крупные cluster labels;
- спокойная типографика;
- отсутствие sci-fi неона и SaaS-dashboard эстетики.

## 12. Motion

Разрешено:

- плавное центрирование;
- мягкое раскрытие панели;
- короткое усиление линии;
- изменение opacity при фильтрации.

Запрещено:

- постоянная пульсация всех узлов;
- бесконечное движение layout;
- яркие бегающие линии;
- motion, мешающий чтению labels.

При `prefers-reduced-motion: reduce` переходы становятся мгновенными.

## 13. URL state

Поддерживаемая схема:

`/map/?focus=<id>&view=graph&group=<group>&relation=<type>&depth=1`

Back/Forward восстанавливает:

- focus;
- view;
- фильтры;
- detail panel.

Canonical остаётся `/map/`.

## 14. Доступность

- граф имеет текстовый эквивалент;
- узлы доступны Enter/Space;
- поиск имеет label;
- фильтры имеют `aria-pressed` или checkbox semantics;
- detail panel сохраняет логичный focus;
- Escape закрывает focus/panel;
- drag имеет кнопочную альтернативу;
- контраст labels проверяется в светлом и тёмном окружении браузера;
- touch targets не меньше 44px для управляющих кнопок.

## 15. Переходная реализация

Первый production шаг допускает SVG engine без внешней зависимости, если он обеспечивает:

- реальные данные;
- unique edges;
- zoom/pan;
- semantic zoom;
- focus mode;
- фильтры;
- panel;
- list mode;
- deep links.

Целевой масштабируемый engine: Graphology + Sigma.js после стабилизации relation compiler.

## 16. Критерии приёмки

- карта использует реальный data source;
- counts вычисляются;
- URL каждого узла канонический;
- labels не образуют постоянную кашу;
- zoom раскрывает детализацию;
- focus сохраняет видимость соседей;
- фильтры меняют карту и список;
- desktop panel не перекрывает центр;
- mobile имеет отдельную модель;
- JS failure не уничтожает навигацию;
- visual tests покрывают 390, 768, 1440 и 1920 px.
