**Дата:** 2026-07-10 · **Статус:** принято владельцем как направление («мы к такому стремимся», по 5 GPT-макетам: Царства, Павел, Исследовательский режим, Иерусалим-план, Сравнение) · **Подчинён:** `ATLAS-CONTRACT-2026-07-10.md` (§2.1 эстетика, §2-бис позиция) и `MAPS-DESIGN-CONTRACT.md` (токены эпох).

## 3. Что берём БУКВАЛЬНО (契约 для KA-4/KA-6)

1. **Палитра (draft-токены, финализация в KA-6):**
   - пергамент карты `#f2ead8`…`#e9dfc8` (внутри SVG; UI-фон светлее и нейтральнее `#faf7f0`);
   - вода `#bcd6e4` с подписями морей serif-курсивом вразрядку;
   - королевский синий `#1e3a63` (заголовки, активные чипы) + светло-синий `#8fb0cf` (Израиль/полигоны);
   - золото `#b98a2f`/`#d9b36a` (Иудея, акценты, короны) — согласуется с токеном bronze `#e8c879`;
   - статусные: маршрутные цвета путешествий Павла (зелёный/синий/фиолетовый/оранжевый) — уже почти STAGE_COLORS движка.
2. **Типографика:** serif (география, заголовки, стихи) + sans (элементы управления, микротекст); иврит-подписи остаются (уже в данных `he`).
3. **Компоновка десктопа:** верх — название+иконки-вкладки; слева — слои (сворачиваемые); справа — инспектор (место/Писание/события); снизу — таймлайн/этапы; на карте — компас-роза, зум, масштабная линейка, миникарта-локатор. ВСЁ уже есть в движке или в данных, кроме правой панели-инспектора нового образца.
4. **Чипы периодов над картой** (макет 1) — становятся стандартным паттерном political-карт (`capabilities.periodSelector`).
5. **Карточки-«корабли» путешествий внизу** (макет 2) — паттерн route-карт с несколькими маршрутами (наши stories), включая цветовое кодирование.
6. **Легенда-карточка в углу карты** с полигонами царств — паттерн для melachim/shvatim.
7. **Иерусалим-план** (макет 4) — прямой референс city-jerusalem: слои стены/ворота/вода/рельеф + шкала эпох снизу + «связанные события» справа.
8. **Сравнение** (макет 5): два полотна + синхронизация + «Сводка сравнения» (общие места считаются из реестра) + честные «Примечания» под картой («маршруты основаны на традиционных интерпретациях…» — формулировка в духе наших §3/§4!).

## 4. Что АДАПТИРУЕМ (не копировать буквально)

1. **Не все панели разом.** Макеты 1 и 3 на 1366×768 задушат карту. Действует правило аудита — три режима глубины: «Обзор» (карта+чипы+легенда), «Изучение» (+правый инспектор), «Исследование» (+слои-менеджер, версии, датасеты). Правый инспектор по умолчанию закрыт, открывается кликом по месту.
2. **Исследовательский режим (макет 3)** — это витрина ПОЗДНЕЙ волны; его блоки «История версий», «Наборы данных» соответствуют нашему AuditRepo/Research-конвейеру, но публичный UI для них проектируем после возврата всех карт. Аватары/«Пользователь» — у нас нет аккаунтов; «Заметки» — localStorage, без сервера.
3. **Мобайл на макетах отсутствует** — действует контракт ТЗ §5 (полноэкранная карта + bottom sheet; чипы периодов — горизонтальная лента; правый инспектор = нижний лист).
4. **Иконки-эмодзи маркеров** (короны/щиты в макетах) — заменяем авторским SVG-sprite (§7 аудита: единый набор символов в гравюрной манере, а не набор разноцветных пиктограмм).
5. **Мини-иллюстрации персон** (Давид/Соломон с портретами, макет 4) — только если появятся авторские изображения; заглушки-аватары не ставим.

## 8. Политика генеративных изображений (GPT Image и др.)

**Принцип: генеративное изображение НИКОГДА не касается географии, фактов и уверенности.**
GPT Image уверенно выдумывает береговые линии, микротекст, «археологические находки» и подписи — это прямо противоречит фирменной честности Атласа (§3 контракта) и богословской аккуратности сайта (§2-бис). Сгенерированная «библейская сцена» или «находка» мгновенно обесценивает доверие, ради которого весь проект и строится.

### 8.1 ЗАПРЕЩЕНО генерировать (использовать проверенный конвейер вместо):
| Нельзя генерировать | Правильный источник |
|---|---|
| Сами карты, береговые линии, маршруты, границы, подписи | QGIS + AWMC/Natural Earth (реальные данные) → SVG (KA-6) |
| Рельеф / hillshade | Copernicus GLO-30 DEM → QGIS/Blender/Eduard (реальная высота) |
| Превью-миниатюры карточек карт | resvg-рендер настоящей карты (конвейер §5 аудита) |
| Фотографии археологии/мест | Wikimedia verified-media (реальные фото, атрибуция) |
| Портреты библейских личностей (Давид/Соломон и т.п.) | по умолчанию НЕ ставим; только авторские изображения, если появятся |
| Иконки-символы как ФИНАЛ | авторский SVG-sprite (рисуется/векторизуется, не растр) |

### 8.2 РАЗРЕШЕНО генерировать (декор, не-факт, растр→в дело):
1. **Бесшовная текстура пергамента/веленя** — заливка `<pattern><image>` под вектором (приём Stamen/LOTR: текстура делается один раз, картография — вектором поверх).
2. **Гравюрный орнамент**: компас-роза, картуш-рамка для легенд/панелей, угловые виньетки, разделители — ПОСЛЕ генерации векторизуются (Illustrator/Inkscape trace), чтобы масштабировались без потери резкости.
3. **Атмосферный фон hero-экрана хаба** — намеренно размытый/низкоконтрастный, НЕ читаемая карта (иначе фейковая география); в CSS дополнительно приглушается.
4. **Концепт-референсы** для набора символов (верблюд, шатёр, менора, корабль…) — чтобы иллюстратор/векторизатор рисовал по ним авторский SVG; НЕ финальные ассеты.

### 8.3 Правила для любого генеративного ассета:
- В промпте всегда `no text, no letters, no labels, no words` (GPT Image добавляет мусорный текст).
- Растр остаётся растром только для текстур; орнамент → в SVG.
- Палитра §3 (пергамент `#f2ead8`–`#e9dfc8`, сепия-линия, сдержанное золото), приглушённо, «серьёзное справочное издание», не фэнтези.
- Ассет проходит owner-review перед вводом; лицензия генерации фиксируется в NOTICE.

Готовые промпты для разрешённых категорий — в чате сессии (KA-4a) и переносятся в дизайн-систему KA-6.
