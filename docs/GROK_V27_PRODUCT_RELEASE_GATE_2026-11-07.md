# Grok V26 → реальный сайт: контролируемое внедрение V27

Дата: 2026-11-07. Цель — увидеть лучшие элементы на реальных страницах, не заменить существующие владельцы функций демонстрационным движком.

## Проверенная архитектура

- **Структура текста и ссылки:** прежние `ReaderState`, `SeriesConfig`, `partToc`, реальные заголовки и якоря, включая Gill. Новая графика лишь представляет данные.
- **Поиск:** `GBSearch` и его индекс. Фильтр в меню — только локальная фильтрация шести уже выведенных ссылок (без индекса, подмены URL и нового владельца).
- **Меню:** единственные `SiteSectionsMenu.astro` и `SiteSectionsMenuRuntime.astro`; открытие, закрытие, блокировка прокрутки и возврат фокуса принадлежат `OverlayRuntime`.
- **Настройки, TTS, сохранение, печать:** `GBReaderPreferences`, `PlayEmber`, `GBReaderLibrary V3`, исходные средства печати. Их не дублировать и не переносить из Arena.
- **Мобильные устройства:** старые шесть ссылок, старый backdrop и тот же runtime. Дополнительные подписи, группировка и фильтр доступны только при ширине >=1360px (85em, совместимый порог Gill + ReaderRail) в rich-варианте.
- **No-JS:** прежний `noscript` с шестью рабочими ссылками.

## Этап A — безопасный общий компонент Product

Из AuditRepo V26+ (PR #537) отобран фильтр меню. Реализован прямо в Product в отдельной рабочей ветке без React и изменения Article/Reader/GBSearch. Фокус на поле при открытии десктопного меню; Enter/стрелка вниз — первый пункт; стрелка вверх — обратно; Escape — прежний OverlayRuntime. При смене размеров мобильный вариант восстанавливает все шесть ссылок. Содержание URL не изменяется.

**Stop-ship для этапа A:** чистый git diff, Astro 0 ошибок, production-like dist, реальные браузерные тесты Chromium/WebKit (Firefox дополнительно локально), 1440×900/1440×300/390×844, сохранение всех шести реальных URL, отсутствие горизонтального переполнения и pageerror, штатный site-sections-menu-visual-contract и reader-controls-residual-browser-contract. Убедиться, что global navigation и No-JS не деградировали. Любое несовпадение — не выпускать.

Выкатка: PR в Product → exact-head CI → merge main → действующий релизный workflow и проверка конечного production SHA. Отсутствие готовой сборки в CI **не заменять** скриншотом прототипа. Откат — предыдущий проверенный release commit; static/no-JS ссылки не менять.

Состояние в начале этой итерации: 33 SUCCESS, 3 SKIPPED, 1 CANCELLED (Search Modal Contract остановлен по лимиту 50 минут во время скачивания пакетов Ubuntu/WebKit). Ранее 638/638 локальных браузерных проверок, **но это не полный CI**. Ручной повтор инициирован, финальный результат требует повторной проверки.

Не объединять PR #2285 и не включать pilot в production, пока не получен зелёный точный head; затем отдельно проверить Layout/ReaderState, Back/Forward, H2–H6, Gill anchor, Library V3 после перезагрузки, TTS, global/scoped search, три темы/125%, A4 print и mobile parity. Настоящий флаг должен быть установлен только в production build на согласованном релизном коммите, а не через скрытый клиентский JavaScript. Откат пилота — сборка с флагом OFF.

## Точное определение «готово»

**Прототип зелёный ≠ код в Product ≠ merge main ≠ опубликованный production.**

Статус «видно на сайте» допустим только после проверки конечного SHA по публичному URL и ручной браузерной сессии на нескольких маршрутах. Пока такой свидетель не снят, указывать только реальную пройденную ступень.

## Owner override — V27 опубликован, но визуальный дизайн НЕ принят (2026-11-07)

**Обязательный визуальный источник**: [AuditRepo / Grok Reader owner visual acceptance](https://github.com/FedorMilovanov/AuditRepo/blob/main/projects/gb-is-my-strength/prototype/grok-desktop-reader/OWNER-VISUAL-ACCEPTANCE-2026-11-07.md) рядом с исходным интерактивным [V26 REFERENCE-V26.html](https://github.com/FedorMilovanov/AuditRepo/blob/main/projects/gb-is-my-strength/prototype/grok-desktop-reader/v26/REFERENCE-V26.html), решениями V26 и handoff. Эти документы фиксируют **текущую волю владельца**, а не достаточную для релиза реализацию.

Новый факт: [Product PR #2287](https://github.com/FedorMilovanov/gb-is-my-strength/pull/2287) и Pages [run #42337941226](https://github.com/FedorMilovanov/gb-is-my-strength/actions/runs/42337941226) успешно выпущены как `main / releaseSha / controlPlaneSha = 547f0ec6e0c9ec3abd151bc6972948600bb8aacd`. Реальная V27 страница функционально работает. **Но владелец отклонил визуал на собственном скриншоте**: оглавление выглядит автономным большим закруглённым прямоугольником, колонка чтения отделена от него пустым полем, слабая иерархия и микротипографика, библиотека висит отдельно справа внизу. Эти дефекты не выявляются простым тестом наличия дерева / верного SHA; **НЕ писать «всё идеально, готово»**.

### Стоп-критерии следующей дизайнерской волны

1. Перенести **архитектуру композиции V26, а не только данные дерева**: левая встроенная в общую сетку навигация **без отдельной карточки**. Реальное раскрытие/сворачивание до узкой рейки с переходом, стабильным положением переключателя и сохранением scroll/focus. В Product нельзя просто применить размеры прототипа: учитывать его существующие breakpoint, анимации, CSS/cascade, reader width и route owners.
2. Упорядочить **библиотеку** в согласованной зоне инструментов; устранить визуально случайный lower-right пузырь. Реальное окно библиотеки/настроек/меню должно возникать рядом с триггером внутри viewport и пользоваться действующим `GBReaderLibrary V3` / `OverlayRuntime`. Правая вертикальная группа из 4 *действующих* иконок должна сохранять семантику и аккуратную геометрию, не дублироваться.
3. Премиальная типографика/отступы/фокус/прогресс/активные маркеры, читаемое вложенное TOC, достаточный контраст и композиция текста на 1200, 1440, 1920; крайние экраны 1440×300 и 320×760. Исключить обрезания, неуместную пустоту, наложения, скачки и горизонтальный скролл. Три темы Day/Sepia/Night. Два подтверждённых mobile-дефекта отдельно задокументированы в [issue #2288](https://github.com/FedorMilovanov/gb-is-my-strength/issues/2288); не терять их при переработке общей композиции.
4. **Screenshot-gated acceptance**, прежде чем объявлять визуал завершённым: зафиксировать реальные фото автономного V26 baseline, рабочего V27 production *before*, изолированного кандидата *after*, и после merge — **нового реального live production** при одинаковых viewport, теме, позиции прокрутки и состоянии. В обязательной матрице 1200×800 / 1440×900 / 1920×1080 / 1440×300 / 768×900 / 390×844 / 320×760, развернутая/свернутая рейка, чтение внутри длинной статьи, Day/Sepia/Night, библиотека открыта/закрыта. Chromium + WebKit; стрелки/Tab/Escape, reduced motion, print и cross-route parity.
5. **Владелец должен увидеть сравнительные скриншоты и явно принять дизайн**. Одних зеленых 192/192 release/browser assertions, successful deploy или слов «премиально» недостаточно. Если остался квадратный box TOC / висячая библиотека / отсутствует fold/unfold, считать результат непринятым даже при зеленом CI.
6. Использовать **отдельный headless браузер**, не открывать и не переключать браузер пользователя; снимки и временные артефакты вне Product git и на диске со свободным местом (C: был переполнен, E: доступен), без автоматического удаления пользовательских данных. Не переписывать `v26/REFERENCE-V26.html` ради подгонки визуала под Product.
7. Продолжение: один узко ограниченный Product lane → source-owned дизайн → реальные сравнительные скриншоты → owner signoff → exact-head CI → merge → публичный SHA и live-визуальная приёмка. Не расширять на Gill/Baptists самовольно. Держать инварианты `ReaderState`, реальных URL/H2–H6, GBSearch, ReaderPreferences, PlayEmber, GBReaderLibrary, OverlayRuntime и прав на статью.

**Последняя инструкция владельца:** «Там во многом по-другому же было, в нашем ГРОК, там не в отдельном прямоугольнике оглавление было… библиотека справа криво … только через скриншоты приёмка премиально вылизанные качественные! Доводим до идеала». Это актуальный открытый критерий, не ещё один исторический wishlist.
