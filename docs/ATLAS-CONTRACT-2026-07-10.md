## 2. Решения по открытым вопросам (утверждены 2026-07-10)

1. **Эстетика базовой географии:** основной стиль — **«пергамент-гравюра»** (бумажная фактура, feTurbulence-край суши, hachures-рельеф, авторские SVG-символы, серифная типографика подписей). Рельефная «спутниковая» подложка — опциональный слой ПОЗЖЕ (KA-6+), не блокирует ничего. Правило: пергамент живёт ВНУТРИ карты; UI-хром остаётся современным и спокойным.
2. **Legacy-Авраам** (`karty/avraam/index.html` + `avraam-app.js`, 684 KB): статус — **исторический артефакт, НЕ production** (production `/karty/avraam/` = Astro + MapEngine). Файлы сохраняются до до-извлечения ценных декоративных фич (караван-анимация тура, ночной режим/звёзды — в опциональные signature-слои движка), затем удаляются отдельным PR с owner-review. До того — не редактировать и не подключать.
3. **Порядок больших циклов:** «Цари и пророки» (KA-7) → «Даниил» (KA-8). Пророки переиспользуют melachim-базу; Даниил требует новых координатных семейств.
4. **Двуязычие подписей:** на карте по умолчанию — русский; иврит/греческий появляются на close-зуме (semantic zoom bucket) и всегда — в панели места. Полей `he` в данных достаточно; поле `gr` добавляется для НЗ-карт.
5. **Печатный режим** (PNG/PDF карты для проповедей/уроков): в KA-6 через resvg-конвейер (превью-генерация всё равно строится). До того — не обещать в UI.

## 2-бис. Богословская позиция сайта (утверждена владельцем 2026-07-10)

Сайт стоит на **младоземельном креационизме**: творение за шесть буквальных дней; потоп — **глобальный, не локальный**; Писание достоверно в истории. Для Атласа это означает:

1. **Хронология сайта — консервативная библейская** (ранняя датировка Исхода 1446 г. до н.э. по 3 Цар 6:1; патриархи от ~2166). Реестр `data/atlas/periods/*` ведётся в этой хронологии; она — `siteDefault`. Академические альтернативные датировки (поздний Исход, минималистские схемы) могут УПОМИНАТЬСЯ в исследовательском слое как интерпретации с явной маркировкой — но никогда не подаются как «факт по умолчанию». Движок уже так работает (`yec_position` в данных Авраама; археология Исхода привязана к ранней дате).
2. **Карта «Начало истории» (Быт 1–11)**: потоп подаётся как глобальный; Арарат — место остановки ковчега (с вариантами локализации внутри региона Урарту); расселение народов — от Вавилона (Быт 10–11). Формулировок «локальное месопотамское наводнение» как позиции сайта не существует; критические теории — только как маркированные интерпретации, если вообще упоминаются.
3. **Геологические/эволюционные датировки** («миллионы лет», слои как эпохи эволюции) в контенте Атласа не используются. Археологические периодизации (бронза/железо) применяются как общепринятые ярлыки материальной культуры БЕЗ привязки к глубокой хронологии — это ярлык слоя, не утверждение о возрасте земли.
4. **Честность остаётся**: спорность ЛОКАЛИЗАЦИЙ (где Синай, где Содом) — показываем открыто со статусами; позиция сайта по БОГОСЛОВИЮ — едина и не «одна из моделей». Модель интерпретаций §4 обслуживает пророческие схемы и датировочные альтернативы, а не размывает основание.

## 3. Словарь уверенности (обязательный для всех данных Атласа)

Единый словарь статусов идентификации/локализации — **как в движке v0.46** (не изобретать новых):

```
consensus | primary | candidate | alternative | caveat | minor | rejected
```

- `consensus` — общепризнанная локализация; `primary` — основная в академической литературе; `candidate` — серьёзный кандидат; `alternative` — меньшинство; `caveat` — с существенной оговоркой; `minor` — маргинальная версия; `rejected` — отвергнутая (хранится для истории вопроса).
- Каждая идентификация в реестре несёт: `status` (словарь выше), `sources[]` (с уровнем A/B/C по Research/AGENT_RULES), опционально `score` (0–1000, модель декадных голосов OpenBible — см. аудит §8) и `sameAs` (OpenBible slug / Pleiades URI / Wikidata QID).
- Совместимость: OpenBible `time_total ≥ 500` ≈ `consensus/primary`; Pleiades `association_certainty: certain/less-certain/uncertain` мэпится на `consensus/primary/candidate`. Точность позиции — отдельное поле `accuracyMeters` (модель Pleiades `accuracy_radius`).
- **UI-правило:** всё, что не `consensus`, обязано визуально отличаться (пунктир/бейдж/знак ~) и иметь панель «Варианты локализации». Спорность — фирменная честность проекта, не мелкий шрифт.

## 4. Факт ≠ интерпретация (железное правило)

- **Факт** (география, археология, датировки событий с источниками) живёт в `places/persons/events/polities`.
- **Интерпретация** (соответствия пророчество↔история: Дан. 2/7/8/11, Откровение и т.п.) живёт ТОЛЬКО в `interpretations/*` с явным полем `model`: `traditional | historicist | preterist | futurist | historical-critical`. UI показывает интерпретации переключателем с явной маркировкой, никогда — как географический факт.
- Позиция сайта может быть выражена полем `siteDefault: true` у одной модели, но остальные не скрываются.

## 5. Архетипы карт и capabilities

| Архетип | Что это | Примеры |
|---|---|---|
| `route` | маршрут(ы) с этапами, направлением, туром | avraam, ishod, pavel, Илия/Елисей, Давид, Иаков-Иосиф, Александр |
| `political` | границы/царства с тайм-переключателем периодов | melachim, Четыре царства, Ирод, диадохи |
| `territorial` | полигоны территорий | shvatim (уделы), Таблица народов |
| `city` | план города со слоями эпох | Иерусалим, Вавилон |
| `thematic` | распределение объектов по теме | пророчества о народах, чудеса, археология |
| `overview` | вход/обзор (не гео-повествование) | Земля Библии, хронология Атласа, сравнение |

`route.json` каждой карты объявляет `archetype` и `capabilities` (stages, timeline, multipleRoutes, periodSelector, compare, cityInset, interpretations…). Shell показывает только соответствующие элементы UI.

|---|---|---|---|
| `levant` | Сирия—Ханаан—Синай | **0 0 1900 1430 (текущее, НЕ менять)** | действующее; 8 карт (avraam, ishod, shvatim, shoftim, melachim, maccabim, yeshua, early-church) |
| `mediterranean` | Средиземноморье: Рим—Иерусалим | 0 0 1900 1430 (номинально тот же, **география другая**) | действующее; pavel, revelation (собственная художественная развёртка) |

| `ane-wide` | Средиземноморье—Иран | — | Даниил (империи), Александр, Есфирь |
| `city-<slug>` | план города | — | jerusalem — первый; babylon — второй |

Правила: (1) у каждого места в реестре — реальные `lat/lng`; SVG-размещения per-семейство генерятся из координат фиксированной проекцией семейства (d3-geo, build-time) + ручная картографическая поправка `manualOffset`; (2) проекция семейства фиксируется в `data/atlas/coordinate-spaces.json` и НЕ меняется после публикации первой карты семейства; (3) кандидат проекции для `ane-wide` — Equal Earth или equirectangular с центром ~35°E; (4) **одинаковый номинальный viewBox ≠ одно пространство**: `placements` пишутся строго под ключом семейства карты-источника (дефект «Рим под ключом levant» пойман мини-картой 2026-07-11 и закрыт по-семейным конвейером + перекрёстными проверками atlas-data-check: полнота placement для семейства каждой карты места и запрет координат-«сирот»).

## 7. Реестры данных (`data/atlas/**`, вводятся волной KA-2)

```
data/atlas/
├── coordinate-spaces.json      # проекции/viewBox семейств
├── places/*.json               # id, имена (ru/he/gr/периодные), тип, lat/lng,
│                               # identifications[] (§3), placements{семейство:{x,y}},
│                               # sources[], license-происхождение геометрии
├── persons/*.json              # пророки/цари/апостолы: период, роли, связи, sameAs (TIPNR id!)
├── periods/*.json              # эпохи: диапазоны, цветовые токены (bronze/iron/roman/…)
├── polities/*.json             # царства/империи: контуры по периодам (геометрия отдельно)
├── events/*.json               # битвы/депортации/соборы: дата, placeId, участники, sources
├── routes/*.json               # канонические дороги (Via Maris, Царская дорога, Itiner-e-выборки)
├── sources/*.json              # библиография: тип, уровень A/B/C, ссылки
├── interpretations/*.json      # интерпретационные утверждения (§4)
└── geometry/                   # GeoJSON: контуры политий, дорог (с полем license!)
```

- Валидация: JSON Schema 2020-12 + Ajv, скрипт `atlas:data:check` (KA-2) — в CI.
- Первичные источники данных и их лицензии — по таблице аудита §8 (OpenBible CC BY 4.0, Pleiades CC BY 3.0, AWMC ODbL, Cliopatria CC BY 4.0, Itiner-e CC BY 4.0, TIPNR CC BY 4.0, Theographic CC BY-SA 4.0 — share-alike учитывать; NC-источники: только сверка, в данные не вшивать).
- `karty/<slug>/route.json` остаётся видом карты; поле места получает `placeId`-ссылку (резолвится движком, обратная совместимость сохраняется).

## 8. Гейты публикации карты (формализация чипов хаба)

Карта возвращается на витрину ТОЛЬКО через `atlas:gate` (все 9 зелёные):

| # | Гейт | Проверка |
|---|---|---|
| G1 | initial viewport | стартовый кадр = сцена сюжета, не «весь мир» |
| G2 | label collision | 0 пересечений подписей на 360/768/1440 (после KA-3 — автотест) |
| G3 | desktop и mobile | 360×640 живой: листы, таргеты ≥44px, INP<200ms |
| G4 | слои и controls | каждый объявленный слой переключается; легенда соответствует |
| G5 | читаемость маршрута | линии различимы на far/mid; направление читается |
| G6 | контент-паритет | счётчики `atlas-inventory` ≥ базовой линии (ничего не потеряно) |
| G7 | источники | каждое место ≥1 источник; спорное — варианты со статусами |
| G8 | a11y | keyboard-обход, roles/names, reduced-motion, no-JS список этапов/мест |
| G9 | owner review | «да» владельца по скринам (в AuditRepo `verification/atlas/<slug>/`) |

Базовая линия G6 — `data/atlas-inventory-baseline.json` (скрипт `scripts/atlas-inventory.js`, волна KA-0; человекочитаемый отчёт — локально в `reports/atlas-inventory.md`). Любая миграция данных обязана не уменьшать счётчики без явного объяснения в PR.

## §13-бис. ЗАКОН РЕФЕРЕНСОВ (решение владельца, 2026-07-11 — обязательно к чтению каждой сессией)

1. **Витринные карты делаются ЗАНОВО по референсам владельца** (светлые пергаментные
   листы: обложки `images/atlas-*-scene-*.webp` + одобренная мини-карта превью).
   Тёмный интерактив движка v0.5x («кружки, подсветки, тёмные карты») — НЕ витринный
   вид. Его НЕ восстанавливаем и НЕ полируем; он остаётся источником ДАННЫХ
   (route.json, label-раскладка, этапы) и логики.
2. **Одна карта за раз, вдолгую.** Работаем над одной картой до состояния «супер-топ»
   и не переходим к следующей, пока владелец не сказал «ДА» (личный G9 по каждой).
   «Сделали и пошли дальше» — запрещённый паттерн.
3. **Архитектура с выносом движка с первого дня.** Рендер листа — переиспользуемый
   модуль `scripts/lib/sheet-engine.js` (чистое API: route + opts → SVG/HTML).
   Карта = данные + конфиг, НЕ код. Монолиты в 10к+ строк на одну карту
   (ошибка прод-Авраама) — запрещены; любой общий код сразу живёт в движке листа.
4. Прод-страницы /karty/<slug>/ переводятся на sheet-движок только после «ДА»
   по листу и решения system-lane (ownership).

### Исходное взвешивание (для истории)

Вопрос владельца (2026-07-11): референсы показывают карты ВНУТРИ атласа
(выбор других карт, инструменты, много функций) — или отдельные полноэкранные
карты без потери места, полное погружение? Взвесить до дальнейшей стройки.

**Вариант А — «Атлас-оболочка»** (приложение-книга): постоянная рамка с
навигацией по 10 картам, шкалой времени, поиском, панелями.
Плюсы: продукт ощущается ЕДИНЫМ атласом; кросс-навигация (место → все его
карты); функции всегда под рукой. Минусы: рамка съедает экран (особенно
мобайл); лист никогда не дышит на всю ширину; сложнее «вау» погружения.

**Вариант Б — «полное погружение»**: каждая карта — полноэкранный лист,
никакой постоянной рамки; функции — по вызову. Плюсы: максимум карты,
атмосферность референсов; мобайл честный. Минусы: «атласность» теряется —
карты выглядят набором отдельных страниц; переключение карт спрятано.

**Вариант В — ГИБРИД «Атлас-читалка» (рекомендация)**: лист ВСЕГДА
полноэкранный (sheet-engine, погружение как в Б), поверх — тонкая
автоскрываемая рамка-инструментарий читалки (как в читалках книг):
корешок-переключатель карт (обложки-сцены как страницы книги), этапы,
слои (арх-точки/дороги/спорное), клик по месту → панель-досье (контент
уже в route.json: story/bible/arch/фото), поиск, зум/пан. Панели
прячутся — и остаётся чистый лист (Б); открываются — и это атлас (А).
Технически: sheet-engine остаётся единственным рендером; интерактив —
отдельный тонкий слой «Atlas Reader» поверх SVG (§13-бис: без монолитов).

Поэтапность гибрида: R1 — лист + зум/пан + этапы + корешок карт;
R2 — панель-досье мест; R3 — слои, поиск, сравнение эпох; R4 — перевод
прод-/karty/ на читалку (system-lane, ownership).

## §15. ЭТАЛОН ЛИСТА — правила минимализма (владелец, 2026-07-11: «делаем эталоны, а только потом другие»)

Выведены девятью скрин-итерациями по листу Авраама. Обязательны для КАЖДОГО
нового листа; отступление — только по слову владельца. Лист Авраама — образец.

**Запрещено на листе (источники «громоздкости»):**
1. Кружки/бейджи вокруг вех, «поля фона» и ореолы вокруг объектов
   (dotShadow, ruin-halo и любые подложки-подсветки маркеров).
2. Залитые глифы: все пиктограммы — только контур (fill:none, ~.85 op),
   мельче кегля подписи; глифы лишь у мест с уникальным смыслом
   (зиккурат Ура, пирамида Египта, руина Содома, пиния Мамре, колодец
   Беэр-Шевы — 3–6 на лист, не больше).
3. Подписи верифицированных wp-точек на статике — только на зуме
   (svg.zoomed); сами wp — мелкие ромбы без обводки.
4. Жирные маршруты: нить — пунктир ~2.1/точечный, подложка route-under
   не шире 3 и не плотнее .3 (иначе издали читается «рекой/водой»).
5. Треугольник-гора у точки — только для type mountain, регэкспы по
   имени запрещены («Шалем · гора Мория» — город, точка).

**Обязано быть:**
6. Вехи этапов — тонкие римские курсивные цифры в терракоте этапа
   (~10k), без плашек; у мест с глифом цифра уходит вниз-влево; точная
   посадка — mileDx/mileDy в данных места (единицы сетки).
7. Каждый этап ленты имеет веху на карте (stage мест = индекс stages[]),
   иначе клик по этапу в читалке мёртв. Проверять соответствие ленты
   и вех при каждом изменении stages.
8. Нить маршрута — только по main-станам в хронологии сюжета; упомянутые
   границы/ориентиры (Кадеш и Сур в Быт 20:1) — noRoute:true. Порядок
   мест в массиве = порядок нити.
9. Узлы подписей разбираются анкерами labelAnchor (8 сторон) +
   микролидерами leader{dx,dy} (линия-выноска появляется сама только
   при |leader|>8k — микросдвиги линий не рождают).
10. Точки городов у воды стоят на берегу, не в воде (глиф можно сместить
    glyphDx/glyphDy); цифра вехи НА воде допустима, если этап о воде
    (VI «Катастрофа Содома» на глади Сиддима).
11. Базовые контекст-слои на листе приглушаются CSS-ом листа, не правкой
    донора: торговые дороги ~.32, глоу пойм ~.22.
12. Иерархия кеглей: вехи/глифовые места 13k, прочие 11k, регионы —
    разрядка; гало подписей .17em, лидеры .75/.45.

**Процедура сдачи листа:** скрин всего листа + кропы каждого узла
(×3–×4) → проход правок → снова скрины, до чистоты; пиксельные споры
решать probe-ом elementsFromPoint/getScreenCTM (playwright), не на глаз.
Лист считается эталонным только после «ДА» владельца (§13-бис).
