# SERIES-ENGINE-GUIDE — как встраивать контент в движок серий

**Для агентов, пишущих статьи.** Прочитай целиком (5 минут) — и ты не сломаешь
дизайн и не будешь гадать. Движок один на все серии; уникальность серии —
в её КОНФИГЕ и ТЕМЕ, не в копировании компонентов.

## 0. Железные правила (нарушение = провал ревью)

1. **НЕ трогай файлы движка**: `gill-series/*.astro`, `_shared/ReaderRail.astro`,
   `_shared/ReaderSettings.astro`, `css/floating-cluster.css`,
   `js/floating-cluster-controller.js`. Твоя зона — конфиг серии, данные,
   тело статьи, страница-маршрут.
2. **Конфиг только через `defineSeriesConfig({...})`** — он проверит тебя на
   сборке и скажет по-русски, что не так. Ошибка сборки = читай сообщение,
   правь конфиг, не движок.
3. После любого изменения прогони: `npm run engine:contracts` (секунды) и
   перед сдачей — полный `npm run engine:guard` (сборка dist обязательна:
   `npx astro build && node scripts/copy-legacy-to-dist.js && cp css/series-samizdat.css dist/css/`).
4. Обнови `data/series.json` (тот же порядок/минуты, что в конфиге) — иначе
   audit-pro красный.

## 1. Модель серии: три яруса материалов

| Ярус | mark.kind | Пример | Где виден | В счёте «Часть N из M» |
|---|---|---|---|---|
| Часть | `roman` | I, II … | рельс, лист «Части серии», аккордеон, prev/next | ДА |
| Форзац | `label` | Введение, Справочник, Пролог | там же (вертикальное слово, без пилюли) | нет |
| Спутник | `letter` + `tier:'satellite'` + `parent` | Движение А, Экскурс Б | ТОЛЬКО аккордеон «Оглавление части», строкой под родителем | нет |

**Форзацы необязательны и свободны.** Серия может быть вообще без Введения и
Справочника, с одним из них, с несколькими, с любым словом (`mark.value` —
свободный текст). Движок ничего не предполагает.

**Спутники** — дополнительный ярус (углубления, приложения к части). Читатель
находит их в аккордеоне под родительской частью и по ссылкам из тела статьи.
Они не раздувают рельс и счёт частей. У страницы-спутника тот же полный chrome
(рельс/бары/настройки/PLAY) — аккордеон подсветит спутник и раскроет родителя.

## 2. Добавить статью в СУЩЕСТВУЮЩУЮ серию (чек-лист)

1. **Данные серии** (`heartSeriesData.ts` / `baptistSeriesData…` — у каждой
   серии свой data-файл): добавь item. Для части — `kind:'roman'`, следующая
   римская. Для спутника — `mark:{kind:'letter',value:'А'}, tier:'satellite',
   parent:'<id части>'`.
2. **Конфиг** (`_shared/series/<серия>SeriesConfig.ts`): добавь
   `pages['<id>']` — label/title/cover/минуты/`partToc` (все H2/H3 тела с
   `#якорями`, у ОДНОЙ строки `current:true`).
3. **Тело статьи**: компонент `<...>Body.astro`, внутри —
   `<SeriesReaderChrome pageId="<id>" config={<СЕРИЯ>}><article>…</article></SeriesReaderChrome>`.
   Смотри соседнюю часть той же серии как образец 1-в-1.
4. **Маршрут**: `src/pages/.../<slug>/index.astro` (копия соседнего, поменяй
   импорты). PageHead — по образцу соседнего (canonical/og/JSON-LD).
5. **Реестры**: `data/series.json` (часть/минуты; спутники в series.json НЕ
   вносятся — там только ядро), `editorial-metadata`: `node
   scripts/editorial-metadata-registry.js --write` после сборки dist.
6. **Гейты**: `npm run engine:contracts` → `node scripts/audit-pro.js` →
   `npm run engine:guard`. Всё зелёное = сдавай.

## 3. Новая СЕРИЯ

1. Data-файл + `<имя>SeriesConfig.ts` c `defineSeriesConfig({...})` по образцу
   `hardTextsSeriesConfig.ts`; зарегистрируй в `SERIES_CONFIGS` (seriesConfig.ts).
2. Уникальность серии = `theme`: положи `css/series-<theme>.css` (образец —
   `series-samizdat.css`: ТОЛЬКО переопределение токенов `--gb-*` и атмосферные
   слои под `[data-series-theme="<theme>"]`). Дизайн-геометрию движка тема НЕ
   меняет — только цвета/фактуры/акценты. Без `theme` серия выглядит как
   Гилл/Сердце (дефолт) — это нормально.
3. Форзацы — по желанию (см. §1). Если хочешь уникальный вид форзаца серии —
   стилизуй его В ТЕМЕ через `[data-series-theme="…"] .gbat-part--label …` и
   `…​ .gbs2-part--label`, не в общем CSS.
4. `data/series.json` + registry cache-bust не забудь; страницы — §2.

## 3.5. КНИГА-СЕРИЯ (`shape: 'book'`) — когда и как выбирать

Референс: auditrepo `ZIP GBS` → `GBS_ENGINE_RESEARCH_2026-07-15` («книга — не
четвёртый движок, это `series.shape='book'`»). Живой пример: серия «Сердце»
(`hardTextsSeriesConfig.ts`).

**Выбор формы (решение агента при создании серии):**

| Форма | Когда | Структура |
|---|---|---|
| `shape` не указан (flat) | Обычная серия: 3–10 самостоятельных частей | форзацы + римские ЧАСТИ-статьи (+ спутники) |
| `shape: 'book'` | Крупный труд: главы-разделы, внутри каждой 3–6 статей | форзацы + римские ГЛАВЫ-заголовки + арабские СТАТЬИ |

**Правила книги (валидатор проверяет всё на сборке):**

1. Глава: `tier: 'chapter'`, `mark: {kind:'roman'}`, `href` → первая статья,
   `readingTime` — свободная строка («6 статей»). Для главы НЕТ `pages[id]`.
2. Статья: `mark: {kind:'arabic', value:'1'|'2'|…}` (строго подряд),
   `parent: <id главы>`, обязателен `pages[id]` с непустым `partToc`.
3. Плоская серия НЕ может содержать глав (и наоборот) — красная сборка.
4. Рендер ветвится сам: рельс покажет главы строками («N статей»), карточка
   текущей — блок «В этой главе»; аккордеон — три уровня глава → статья
   (шеврон) → её H2; счёт «Глава N из M». Никаких новых компонентов не нужно.

## 4. Почему это безопасно при смене дизайна движка

- Все серии рендерятся ОДНИМ набором компонентов → смена дизайна движка
  меняет все серии сразу; темы поверх токенов переживают это автоматически.
- `defineSeriesConfig` валидирует каждый конфиг на каждой сборке.
- `npm run engine:contracts` — 20+ статических контрактов (AST CSS, изоляция
  движков, реестры) за секунды.
- `npm run engine:sweep` — 87 функциональных Playwright-проверок (деск+мобила,
  все серии, живой PLAY). Меняешь движок → добавь проверку на новое поведение.
- Прецеденты регрессий и их уроки: auditrepo
  `references/gb-ui-canon-2026-07-13/` (ENGINES_ARCHITECTURE.md, BRANCH_AUDIT).

## 5. Частые ошибки агентов (уже случались)

- ❌ Копировать компоненты движка «под свою серию» → форк, который отстанет.
- ❌ Менять `floating-cluster.css` под одну серию без `[data-series-theme]`.
- ❌ Часть добавлена в конфиг, но не в `data/series.json` (audit-pro красный).
- ❌ `partToc` с якорями, которых нет в теле (битые ссылки в аккордеоне).
- ❌ Минуты чтения в конфиге ≠ в series.json ≠ на хабе. Один источник: конфиг.
- ❌ Сдача без `engine:guard` со скринами деск+мобила.
