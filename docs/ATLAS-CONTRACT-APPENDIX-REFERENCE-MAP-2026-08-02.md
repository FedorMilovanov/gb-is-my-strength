# ATLAS CONTRACT — приложение: эталонная карта и долговременная архитектура

**Дата решения владельца:** 2026-08-02  
**Статус:** нормативное owner-approved приложение к `docs/ATLAS-CONTRACT-2026-07-10.md`  
**Применяется к:** `/karty/**`, `karty/_engine/**`, `scripts/lib/sheet-engine.js`, Atlas Shell, map data, browser/visual/print evidence  
**При конфликте:** текущее прямое решение владельца → `docs/OWNER-INVARIANTS.md` → основной Atlas Contract → это приложение → исторические отчёты.

---

## 1. Главное решение

1. **Авраам (`/karty/avraam/`) — эталонная карта Атласа и лаборатория общих возможностей.**
2. Карта «Начало» остаётся хронологическим прологом, но не первой reference-map для route-архитектуры.
3. «Исход» остаётся важным контрольным потребителем и отдельным доказательным пакетом, но не заменяет Авраама как текущую карту, которую доводят до owner-approved уровня.
4. Работа идёт **одна карта за раз**. Общая способность движка выделяется только после доказанного качественного решения на Аврааме.
5. До личного owner-решения «ДА» Авраам не считается визуально завершённым, даже если source build, schema и smoke green.

Формула работы:

```text
Авраам как данные и продукт
→ глубокое исследование и фактический аудит
→ макро- и микро-геометрия
→ интерактивность и доступность
→ owner golden set
→ только доказанные общие примитивы движка
→ следующая карта как контроль переиспользования
```

---

## 2. Продуктовый образ Атласа

Атлас — единый спокойный полноэкранный продукт, а не коллекция перегруженных мини-сайтов.

### 2.1 Постоянно видимо

На карте постоянно остаются только:

- сама география;
- маршрут и ключевые места текущего смыслового уровня;
- компактный ненавязчивый вход в Atlas Shell;
- минимальные средства ориентации, которые действительно нужны в текущем состоянии.

### 2.2 По требованию

Следующие поверхности открываются контекстно и не закрывают карту без необходимости:

- карточка места;
- подробное досье;
- источники и права;
- археологические версии;
- настройки слоёв;
- хронология;
- поиск;
- легенда;
- варианты локализации;
- режим сравнения;
- переход к другой карте Атласа.

Допустимые формы: умный popover, нижний mobile sheet, боковой drawer, command/search palette, компактное контекстное меню. После закрытия карта возвращается к чистому состоянию без визуального мусора.

### 2.3 Запрещено

- постоянно занимать значительную часть экрана панелями, карточками и настройками;
- складывать все функции в одну непрозрачную «панель управления»;
- помещать важный контент только в hover;
- создавать отдельный UI-язык для каждой карты;
- добавлять legacy floating controls или route-specific mini-shell;
- считать полноэкранность оправданием для отсутствия доступного текста и навигации.

---

## 3. Один движок, одна эффективная правда

1. Карта хранит **данные, семантику, источники и допустимую конфигурацию**, но не собственный движок.
2. Shared engine владеет:
   - проекцией и viewBox;
   - pan/zoom;
   - semantic zoom;
   - collision/declutter;
   - слоями;
   - карточками, drawers и focus management;
   - общей Atlas-навигацией;
   - responsive/touch/keyboard поведением;
   - no-JS и print projection;
   - instrumented evidence hooks.
3. Запрещены исправления вида `if (slug === 'avraam')` в общем движке, если это не временная диагностическая ветка, удаляемая до merge.
4. Запрещены CSS-скрытие ошибочных объектов, DOM-mutation данных после загрузки, отдельные route-specific SVG renderers и другие способы существования двух истин.
5. Dark runtime, light sheet, no-JS, search, print/PDF и source drawer должны читать один immutable effective-route/effective-atlas projection.
6. Доказательство на Аврааме не даёт права автоматически переписывать все `route.json`. Следующая карта подключается отдельным bounded lane и обязана доказать переиспользование без регрессии Авраама.

## 4. Качественная географическая база

### 4.1 Координатная система

- У каждого coordinate family есть один канонический viewBox, масштабная модель и источник базовой географии.
- Реки, береговые линии, озёра, горы, пустыни, границы и подписи не рисуются независимо в каждой карте.
- Изменение канонической базы — отдельный SYSTEM lane с side-by-side доказательством всех затронутых карт.
- Маршрутные координаты, context points и декоративные объекты не должны подменять реальную географию.

### 4.2 Геометрические инварианты

Обязательны машинные проверки:

- все path/polygon/text bounds находятся в разрешённом canvas или осознанно clip-ятся;
- реки не выходят из суши и не пересекают берег по ошибке;
- водные пути связны там, где должны быть связны;
- маршрут не перескакивает через unrelated candidate/context nodes;
- label leader ведёт к своему объекту;
- hit target соответствует видимому объекту;
- ни один текст, картуш, легенда или control не выходит за safe viewport;
- clipPath не скрывает обязательную часть маршрута;
- stroke и hit area не становятся непригодными на min/max zoom;
- координатные семейства не смешиваются без явной проекции.

### 4.3 SVG

SVG Атласа должен быть многослойным и семантическим:

```text
base geography
→ hydrography
→ terrain and regions
→ historical/context overlays
→ semantic routes
→ places/features
→ labels and leaders
→ selection/focus state
→ non-map UI projection
```

Требования:

- стабильные `data-*`/ARIA идентификаторы объектов;
- `vector-effect="non-scaling-stroke"` только там, где экранная толщина должна сохраняться;
- screen-pixel sizing для интерфейсных целей и читаемости;
- semantic zoom buckets вместо простого масштабирования всего SVG;
- label collision solver с deterministic output;
- декор не имеет приоритет над географией и текстом;
- каждый SVG-объект либо интерактивен и доступен, либо явно декоративен.

## 5. Смысловые уровни и отсутствие мусора

На общем обзоре показываются только главная нить, ключевые места и крупные географические ориентиры. При приближении постепенно появляются:

1. второстепенные места;
2. иврит/греческий и древние названия;
3. археологические объекты;
4. варианты локализации;
5. локальные маршруты, колодцы, алтари, ворота, руины и иные детали;
6. дополнительные подписи и contextual evidence.

Нельзя выводить все подписи, все источники и все значки одновременно. Скрытая информация остаётся доступной через поиск, keyboard navigation и досье.

## 6. Источники, археология и честность

### 6.1 Три слоя

Любое содержательное утверждение маркируется как один из слоёв:

- **библейское повествование/текст**;
- **историко-археологический факт или наблюдение**;
- **локализация, реконструкция или интерпретация**.

Эти слои не смешиваются в одном утвердительном предложении без явного перехода.

### 6.2 Консервативные и неконсервативные позиции

- Позиция сайта сохраняется согласно основному Atlas Contract и `OWNER-INVARIANTS`.
- Академические, минималистские, поздние, альтернативные и критические модели допускаются как справочные версии с ясной маркировкой.
- Альтернативная версия не выдаётся за нейтральный факт.
- Консервативная версия также не получает статус `consensus` только потому, что соответствует позиции сайта.
- Reader должен видеть: что утверждает текст, что найдено, как это датируется, что из этого выводят разные школы и где остаётся неопределённость.

### 6.3 Источниковая запись

Для серьёзного археологического или хронологического утверждения сохраняются по возможности:

- author/institution;
- title;
- publication/report;
- year;
- page/figure/catalog/locus;
- URL/DOI/identifier;
- access date;
- source tier и verification status;
- evidence use;
- rights/license для изображения;
- краткая причина, почему источник поддерживает именно это утверждение.

Агрегаторы, apologetic summaries и популярные статьи могут быть навигацией, но не заменяют первичный excavation report, официальный музейный каталог, peer-reviewed публикацию или институциональный dataset.

## 7. Радиоуглеродное датирование: осторожный контракт

Радиоуглеродная дата никогда не выводится как одна безусловная календарная точка.

Для каждого использования фиксируются, если доступны:

- material/sample и archaeological context;
- lab code;
- uncalibrated BP value и uncertainty;
- calibration curve/version;
- calibrated interval(s) и confidence level;
- reservoir effect или marine/freshwater correction;
- contamination, old-wood, intrusive sample и reuse risks;
- stratigraphic relation;
- Bayesian model/priors, если применялись;
- публикация лаборатории или excavation team.

UI обязан различать:

```text
измерение образца
≠ датировка слоя
≠ датировка разрушения
≠ датировка библейского события
≠ доказательство идентификации места
```

Формулировки «углеродный анализ доказал» запрещены без узкого объяснения, что именно измерено и какие предпосылки связывают образец с событием. При спорной выборке показывается диапазон и competing interpretation, а не искусственная точность.

---

## 8. Atlas Shell и переключение карт

1. Переключение карт происходит через одну оболочку Атласа, а не через отдельные случайные меню.
2. Shell знает архетип, coordinate family, capabilities, publication/readiness и owner approval каждой карты.
3. При переходе между картами сохраняются только совместимые пользовательские состояния: theme, preferred UI density, доступность и разрешённые global layers.
4. Map-specific zoom, selected place и route story не переносятся на несовместимую карту.
5. Переключатель показывает статус честно: опубликовано, на аудите, reference approved, research hold.
6. Shell не должен занимать карту постоянно; он открывается намеренно и закрывается полностью.
7. URL каждого meaningful состояния остаётся понятным и восстанавливаемым там, где это оправдано: карта, story, place, layer preset.

---

## 9. Owner golden set

Авраам получает immutable набор owner-approved состояний. Минимум:

- desktop full overview;
- desktop Fertile Crescent / Ur–Harran;
- desktop Canaan core;
- desktop Lot/Sodom variants;
- desktop war route;
- desktop Akedah/Moria;
- one dense archaeology/source dossier;
- mobile overview 390 px;
- mobile selected place;
- mobile source drawer;
- keyboard focus state;
- 200% browser zoom;
- no-JS text projection;
- print/PDF projection.

Golden set — не единственная проверка. Он дополняется geometry assertions, interaction tests и exploratory marathon. Новый baseline нельзя принимать автоматически только потому, что изменился рендер.

---

## 10. Правило длинной работы

Карта не выпускается после одного прохода и нескольких скриншотов. Обязателен цикл:

```text
research/reverify
→ implement one bounded hypothesis
→ geometry checks
→ macro screenshots
→ micro screenshots
→ click/keyboard/touch sweep
→ defect log
→ repair
→ repeat on exact current head
```

Агент не останавливается после первого видимого улучшения и не перекладывает обычный поиск дефектов на владельца. Owner получает материал на meaningful decision gates, а не сырые кадры вместо проверки.

---

## 11. Запреты до owner approval Авраама

- не проводить массовую миграцию остальных карт;
- не объявлять новый shared primitive доказанным без Авраама и одной контрольной карты;
- не заменять source truth визуальным adapter-слоем;
- не принимать «нет horizontal overflow у страницы» как доказательство отсутствия SVG overflow;
- не считать один desktop viewport достаточным;
- не считать static audit заменой browser geometry;
- не считать browser smoke заменой visual review;
- не считать source merge production witness;
- не полировать декор поверх нерешённой географии, типографики и фактической базы.

---

## 12. Definition of done reference-map

Авраам получает статус `reference-approved` только когда одновременно выполнены:

- фактическая и источниковая матрица закрыта или имеет явные HOLD;
- effective data projection едина для всех поверхностей;
- macro/micro geometry suites green на final SHA;
- обязательные browser/viewports/zoom/input modes green;
- нет неподтверждённых baseline updates;
- no-JS, search, accessibility и print projections проверены;
- Atlas Shell и переходы не ломают immersion;
- owner golden set принят личным «ДА»;
- production claim имеет отдельный same-SHA live witness.
