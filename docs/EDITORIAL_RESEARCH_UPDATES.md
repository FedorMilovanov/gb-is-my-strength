# Редакционная хроника: существенные обновления исследований

## Назначение

Существующая статья сохраняет прежний canonical URL и дату первой публикации. Новые документы, изменения фактологии и аргументации вносятся непосредственно в соответствующий раздел статьи. Не создавать отдельную новостную статью лишь для анонса правки — роль ленты выполняет `/updates/`.

## Четыре вида редакционных событий

- `new-evidence`: новый проверяемый источник, ранее неизвестный документ или свидетельство, существенно расширяющее картину.
- `correction`: исправленная фактическая ошибка, неверная атрибуция, датировка или ошибочный вывод из источника.
- `expanded`: содержательное расширение источников, исторического контекста или аргумента.
- `revised-conclusion`: изменённая оценка, сформулированная открыто с указанием оснований.

Опечатки, переносы, технический рефакторинг, верстка и обновление зависимостей не являются редакционными событиями. Нельзя искусственно повышать `updatedAt` или менять дату первой публикации ради видимости активности.

## Единый порядок публикации

1. Проверить первоисточник, дату события и дату публикации сообщения; разграничить факт, пересказ, оценку, спорные версии и неизвестное.
2. Изменить СУЩЕСТВУЮЩУЮ статью и добавить у нового существенного подраздела постоянный уникальный HTML-якорь. Сохранить контекст статьи и поправить ранее противоречащие факту формулировки.
3. Добавить источники в существующий реестр с классом доказательности, явным `proves` и `boundary`. Не объявлять журналистский пересказ верифицированным первоисточником без оснований.
4. В `data/editorial-updates.json` создать одно событие на самостоятельное значимое изменение; заполнить `id`, `status`, `articleUrl`, `date` с явным часовым смещением, `kind`, `anchor`, `headline`, `summary` и HTTPS `sourceUrls`. В архиве показываются только `published`; статус `draft` исключает элемент из ленты.
5. Исправить `updatedAt` реальной публикации, `modifiedTime` соответствующей записи `data/search-manifest.json`, затем выполнить канонический `sitemap-policy-normalizer.js --write`. Сохранить `publishedAt`/`publishedTime` без изменений.
6. Выполнить `npm run editorial:lint`, `node scripts/check-route-profiles.js --strict`, `node scripts/sitemap-policy-normalizer.js --check`, полный production-dist build и browser smoke по главной, архиву, статье, тёмной и светлой темам и мобильной ширине.
7. Публиковать только после проверки CI, редакционного согласования и отправки изменений на боевой сайт. Внутренний статус `published` у записи означает, что запись будет открыта при выпуске соответствующего коммита; это НЕ утверждение о фактическом состоянии production до релиза.

## Вывод на сайте

- Главная `HomeSections/Updates.astro`: последние 5 содержательных изменений, без имитации нового материала; на мобильном — горизонтальная листалка с фильтрами и клавиатурной навигацией.
- `/updates/`: полный архив по дате события (не по Git mtime). На мобильном — свайп с индикатором, стрелками, фильтрами, сохранённой возможностью прямого перехода к статье; на десктопе — сетка. Для доступности страницу можно листать клавишами ←/→.
- `ArticleLayout.astro`: заметный блок «Что изменилось в статье» возле шапки статьи с переходом к абзацу по хешу.
- `HomeSections/Publications.astro`: только реально новые публикации, ранжирование по `publishedTime`, а не по `modifiedTime`.
- События связаны с существующей canonical-статьёй через `data/search-manifest.json` — никаких ручных копий названий и обложек.

## Иллюстрации и контроль интерфейса

- Поле `artwork` каждой записи указывает на `archive-01.webp` … `archive-10.webp` из `public/images/editorial/`; существование файла проверяется `scripts/editorial-updates-contract.mjs`. Иллюстрации художественные — не воспроизведения и не доказательства исторических документов. Первая запись использует `archive-01.webp`, исправление по Бахманну — `archive-04.webp`; остальные восемь доступны для будущих содержательных обновлений.
- На главной и на `/updates/` используются **одни и те же данные**, без копирования новости вручную. Мобильная навигация использует native scroll-snap, а не жесты, отбирающие вертикальную прокрутку.
- После production-like сборки проверять `node scripts/editorial-updates-browser-smoke.mjs`: 320, 390, 1280 px; главную и архив; 2 изображения; стрелки, фильтры, тёмную тему, JavaScript-ошибки, горизонтальное переполнение. Скриншоты сохраняются в `reports/editorial-updates-browser/`.
- Не объявлять выпуск завершённым, пока обязательные GitHub Actions на точном HEAD PR не зеленые. Статус `published` в реестре не является доказательством фактического релиза на production.

## Особая осторожность для спорных случаев

По письму старейшин Stephens Valley Church (25 ноября 2025, публикация Protestia 11 ноября 2026): не подменять «пригоден для возможных служений» назначением на пасторскую должность, не подменять сообщение о письме заверением его подлинности самим советом, не утверждать мотивов непубликации и не считать наблюдения старейшин прямым свидетельством жены. Связанные интервью и решения прежней церкви раскрывают разногласия, но не позволяют судить о внутреннем состоянии человека. Поправка по апелляции Джима Бахманна должна оставаться отдельно видимой.

## Совместимость

Первая опубликованная запись относится к native MDX статье. `src/lib/editorial-updates.ts` связывает архив с реестром опубликованных материалов, не создавая копий. При добавлении событий к статическим legacy-страницам необходимо обеспечить одинаковые стабильные якоря, даты и публичные маршруты и расширить контракт-валидатор для их реального источника; нельзя помечать unsupported-страницу опубликованной, пока она не проходит те же проверки.
