# GENEALOGY MASTERPLAN — «Родословие от Адама до Христа» (шедевр)

**Статус:** Стратегия (research-фаза, июнь 2026) · **Дата:** 2026-06-18
**Видение:** Мощнейший интерактивный отдел — генеалогическое древо от Адама до Христа (и далее), с семантическим зумом, поиском имён, отображением возрастов, пропусков в родословиях и связей. Позиция young-earth креационизма (замкнутые, «плотные» генеалогии). 2D SVG. Tailwind + современный стек.

---

## 1. Evidence-base (research июня 2026, с источниками)

### Технологический лидер: React Flow + Dagre / Entitree Flex
- **React Flow** (июнь 2026) — лидер для интерактивных деревьев: pan/zoom из коробки,
  **встроенная виртуализация** (рендерит только видимую часть → масштабируется до сотен узлов),
  кастомные ноды/рёбра как React-компоненты, `fitView()`, `setCenter()`, `fitBounds()`.
  [tva.sg ReactFlow family tree, 2025](https://www.tva.sg/insights/reactflow-family-tree-visualization)
- **Entitree Flex layout** (март 2026) — layout специально под family-tree с братьями и
  узлами разного размера. [reactflow.dev/.../entitree-flex](https://reactflow.dev/examples/layout/entitree-flex)
- **Dagre** — классический DAG-layout: `rankdir:'TB'` (время сверху вниз), `ranksep`/`nodesep`
  для межпоколенных/межбратских отступов. Ограничение: spouse-рёбра не нативны → layout по
  parent-child, spouse рисуются отдельно горизонтально.

### Семантический зум: академический фундамент (ZMLT)
- **Zoomable Multi-Level Tree (ZMLT)** — De Luca, Hossain, Kobourov, Börner, EUROGRAPHICS 2020.
  [arxiv 1906.05996](https://arxiv.org/abs/1906.05996). Семь желательных свойств:
  representative, real, persistent, overlap-free labeled, planar, compact. **Это и есть
  требование «при приближении общая схема превращается в детальную».**
- **d3-hierarchy** — `tree()` (Reingold–Tilford «tidy», линейное время) + `cluster()` (dendrogram,
  листья на одной глубине) + `collapse()/expand()` (как ggtree: треугольная свёртка клады).

### Mobile UX (паттерн MyHeritage 2025)
- Вертикальные профиль-карточки (умещают больше на узком экране), pinch-to-zoom, swipe-pan.
  [MyHeritage blog 2025](https://blog.myheritage.com/2025/03/new-improved-family-tree-on-the-myheritage-mobile-app/)
- Рекомендация: vertical-cards default на мобильном, горизонтальная лента поколений.

### Библейская хронология (для young-earth позиции)
- **Масоретский текст (MT):** патриаршие возраста → Авраам ~1948 AM от Сотворения, Потоп ~1656 AM,
  ~4000 лет Адам→Христос. Основа Уссера (4004 до н.э. сотворение).
- **LXX vs Самарянский:** отличаются в патриарших возрастах (LXX длиннее на ~600 лет).
  Young-earth креационизм обычно держится MT-хронологии (наиболее «плотной»).
- **«Замкнутые vs открытые генеалогии»:** AiG (Sarfati) и Midwest Apologetics защищают
  **замкнутый** взгляд (без значимых пропусков; даже если пропуск есть — это десятилетия,
  не тысячелетия). [answersingenesis.org/.../are-there-gaps](https://answersingenesis.org/bible-timeline/genealogy/are-there-gaps-in-the-genesis-genealogies/)
- **Ключевая апологетическая проблема:** Каинан в Лк 3:36 (Sarfati: только в поздних LXX,
  старейшие тексты его не имеют). Должно быть отражено как «спорное место».

### Две родословные Христа (Матфей vs Лука)
- Матфей (1:1–17): 3×14 поколений, царственная линия через Соломона (Иосиф).
- Лука (3:23–38): линия через Нафана, до Адама (Мария / другой Иосиф по различным теориям).
- **Ключевые апологетические узлы:** проклятие Иехонии (Иер 22:30; снято в Агг 2:23 через Зоровавеля);
  14-я «пропущенная» генерация в Мф 1 (Иоаким). Это — отдельные interactive-ноды с пояснениями.

## 2. Архитектурное решение (стек)

| Слой | Технология | Почему |
|---|---|---|
| **Дерево-визуализация** | React Flow + dagre layout | Лидер июня 2026, виртуализация, кастом-ноды, mobile-ready |
| **Layout** | Entitree Flex / dagre TB | Поддержка братьев + spouse-рёбер |
| **Семантический зум** | Кастом: 3 уровня детализации по zoom-порогам | Реализация ZMLT-принципа |
| **Стили** | Tailwind (route-scoped, как maps-policy) | По разрешению владельца |
| **Данные** | JSON генеалогии (верифицированный dataset) | Источник правды, отдельный от движка |
| **Поиск** | fuzzysort / lunr по именам + прыжок `setCenter` | Мгновенный find-as-you-type |
| **Хостинг** | Astro island (`client:load`) | Как konfessii-3D: iframe/island, не грузит остальной сайт |

**Где живёт:** НЕ в `/karty/` (другой тип данных). Предположительно `/rodosloviye/` или `/genealogiya/`.

## 3. Революционные фичи (что делает это шедевром)

### 3.1. Трёхуровневый семантический зум (ядро UX)
| Уровень зума | Что видно | Аналогия |
|---|---|---|
| **L0 «Космический»** (далеко) | Эпохи-блоки: Сотворение→Потоп→Авраам→Давид→Плен→Христос. ~6 мега-узлов с числами поколений | карта мира |
| **L1 «Континент»** | Линии патриархов (Сифова линия), ключевые ветви (Израиль/Иуда), generations-полосы с датами AM | карта страны |
| **L2 «Улица»** (близко) | Каждый человек: имя, возраст рождения сына, срок жизни, библейская ссылка, биография | городская карта |

Переход между уровнями — **плавный (animated morph)**: блок раскрывается в поддерево (как ggtree
`expand()` треугольной клады → реальные узлы). Это и есть «общая схема превращается в детальную».

### 3.2. Поток времени как вертикальная ось
Не просто древо — древо **с хронологической шкалой** слева (AM-годы по MT). Узлы позиционируются
по реальным датам рождения → видно **наложение жизней** (Авраам жил при Симе/Арфаксаде; Метушалах
почти дожил до Потопа). Это мощнейший инсайт, которого нет в статичных таблицах.

### 3.3. Возраст как визуальная переменная
- Длина «жизненной полосы» узла ∝ срок жизни (долгожители — Methuselah 969, Adam 930 — длинные
  золотые полосы; после Потопа жизни резко короче → **визуально очевидный драматический спад**).
- Цвет/свечение ∝ значимость (патриархи-предки Христа — золотая нить).

### 3.4. Золотая мессианская нить
От Адама (Быт 3:15 «семя жены») → Сиф → ... → Давид → Христос — **подсвеченная золотая траектория**
сквозь всё древо. Toggle on/off. Это превращает генеалогию в **визуализацию обетования**.

### 3.5. «Пропуски» как честный научный слой
Young-earth позиция: генеалогии «плотные», но честно показываем дискуссионные места:
- Каинан Лк 3:36 (LXX-вариант) — отдельный «призрачный» узел с пометкой «спорный» + sources
- «Открытые/замкнутые» toggle: показать альтернативные хронологии (MT/LXX/Самарянский) как
  переключаемые слои — пользователь видит разброс (~4000 vs ~5500 лет Адам→Христос) и понимает,
  почему мы держимся MT

### 3.6. Поиск + «фокус» как в IDE
Cmd/Ctrl+K → fuzzysort по именам (рус/транслит/иврит) → `setCenter(node)` с плавным zoom-in.
«От этого предка» — кнопка: подсвечивает всех потомков до Христа.

### 3.7. Две генеалогии Христа рядом
Split-view: Мф 1 (Соломон-Иосиф) слева, Лк 3 (Нафан-Мария) справа, общая точка — Христос.
Клик по узлу-проблеме (Иехоний/проклятие) → callout с апологетическим разбором.

### 3.8. Mobile-first fallback
На тач-устройствах: вертикальный «лестничный» режим (как MyHeritage 2025) — одна ветвь поколений
в виде карточек, pinch-zoom, swipe. Глобальная карта-древо сворачивается в читаемую ленту.

## 4. Данные: верифицированный dataset (источник правды)

Структура `genealogy.json` (каждый человек):
```json
{
  "id": "methuselah",
  "name": { "ru": "Мафусал", "he": "מְתוּשֶׁלַח", "translit": "Metushelach" },
  "father": "enoch",
  "mother": null,
  "spouse": [],
  "children": ["lamech"],
  "chronology": {
    "ageAtFirstSon": 187,
    "lifespan": 969,
    "birthAM": 687, "deathAM": 1656,
    "textualTradition": { "MT": {...}, "LXX": {...}, "Samaritan": {...} }
  },
  "biblicalRef": { "ref": "Быт 5:25-27", "parallel": "1Пар 1:3; Лк 3:37" },
  "lineage": "sethite-messianic",
  "significance": "Долгожитель; умер в год Потопа (AM 1656)",
  "disputed": null,
  "sources": ["Быт 5", "Уссер, Анналы"]

```
**Coverage:** Быт 5 (допотопные патриархи), Быт 10 (таблица народов), Быт 11 (от Сима к Аврааму),
родословия патриархов, Руфь 4 / 1Пар (к Давиду), Мф 1 + Лк 3 (к Христу). ~75–120 узлов (НЕ тысячи
— young-earth «плотная» позиция, как просил владелец).

## 6. Принципы (преемственность с AGENTS)
- **Данные отделены от визуализации** (genealogy.json ≠ движок), как route.json в картах.
- **Tailwind — route-scoped** (в этом island), не глобально (политика §2.1).
- **Все факты с источниками** (EDITORIAL-SOURCE-POLICY); спорные — помечены, не поданы как уверенные.
- **Young-earth позиция задокументирована** явно: MT-хронология как основная, LXX/Самарянский как
  toggle-альтернативы для полноты; пропуски — «плотные» (десятилетия, не тысячелетия).
- **Производительность:** React Flow виртуализация + lazy-load поддеревьев → держит 100+ узлов.
- **a11y:** keyboard-nav (стрелки по дереву), prefers-reduced-motion, ARIA-дерево.
