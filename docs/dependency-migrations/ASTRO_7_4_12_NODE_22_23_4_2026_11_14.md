# Astro 7.4.12 / Node 22.23.4 — security closure

Дата контрольной миграции: 14 ноября 2026 года.

## Основание

При точном lock-файле Astro 7.3.8 аудит npm выявлял одну уязвимость moderate (Astro) и одну low (fast-xml-parser). Исправленные версии Astro 7.4.7+ требуют Node >=22.23.4, поэтому нельзя менять только package-lock или понижать строгость security contract.

## Единая матрица

- Node: **22.23.4**, точный релизный pin в `data/release-toolchain.json` и GitHub workflows.
- npm: **10.9.9**, версия, входящая в официальный дистрибутив Node 22.23.4; закреплена тем же контрактом.
- Astro: **7.4.12**, прямой devDependency с точной версией.
- `@astrojs/mdx`: **8.1.6**, поддерживает встроенный Satteri `^0.4.10`.
- `@astrojs/markdown-satteri`: **0.4.10**, прямой точный devDependency, один модульный экземпляр для Astro и MDX; никаких Unified / markdown-remark overrides.
- `fast-xml-parser`: **5.12.1** (транзитивная версия в lock).
- Исходная ветка: существующий Dependabot PR #2268, без новой ветки. PR #2293 обновляет действия GitHub независимо и не должен незаметно менять логику текущей миграции.

## Контракт диагностического компилятора

Независимый сравнительный прогон на **побайтно одинаковых** исходниках выявил:

- Astro 7.3.8 / @astrojs/check 0.9.10 / @astrojs/language-server 2.16.13 / @astrojs/compiler 2.13.1: **655 файлов, 0 ошибок**.
- Astro 7.4.12 / @astrojs/check 0.9.12 / @astrojs/language-server 2.17.3: **651 файл, 464 ошибки в 59 неизменённых компонентах «Нагорной проповеди»**. Это ранее извлечённые HTML-фрагменты со структурой, пересекающей границы компонентов.
- Astro 7.4.12 с прежними версиями проверочного пакета и компилятора: **651 файл, 0 ошибок**.
- Непосредственная генерация Astro 7.4.12 без TypeScript-диагностики: **111 страниц**, включая пять частей «Нагорной проповеди», успешно.

Поэтому диагностические версии закреплены точно: `@astrojs/check@0.9.10`, `@astrojs/language-server@2.16.13`, `@astrojs/compiler@2.13.1`. Все три проверяются через `astro7-satteri-contract.mjs`, а не скрываются за пропуском проверки. Контракт специально останавливает несанкционированное обновление анализатора, пока не будет проведена самостоятельная контентная миграция исторических фрагментов с визуальным/DOM-паритетом. Полное `astro check` **остаётся обязательным**. Важно: этот pin — документированная совместимость инструментов, а не подтверждение корректной отдельной HTML-структуры каждого старого фрагмента.

## Необходимые проверки

1. `npm ci` при Node 22.23.4 / npm 10.9.9, с абсолютной воспроизводимостью lock-файла.
2. `node scripts/node-toolchain-pin-contract-test.mjs` — все workflow используют один точный Node; версия npm соответствует канонической.
3. `node scripts/astro7-satteri-contract.mjs` и `npm ls @astrojs/markdown-satteri --all` — установлен единый совместимый 0.4.10 и доступен нативный API.
4. `node scripts/check-workflows.js` — ни один релизный, охранный и кандидатный job не остался с устаревшим Node.
5. `npm audit --json` плюс `node scripts/npm-security-contract.mjs` — без уязвимостей; оценивать полный отчёт, не только код завершения.
6. Полная production-like сборка, типизация Astro, публикационные контракты и browser smoke по соответствующему HEAD.
7. GitHub Actions и mergeability **на окончательном коммите**, без принятия результатов от прежних HEAD.

## Границы

Миграция меняет общеcистемные версии и workflow, поэтому должна проходить отдельную приемку от PR архива обновлений #2302. Нельзя ослаблять security gate, отключать `Shared Files Guard`, выпускать черновик #2300 или автоматически публиковать незавершенную редакционную статью. Исторические документы прежней миграции Node 22.23.1 остаются в репозитории как исторические свидетельства.

Для локальной проверки на Windows допускается **изолированный** бинарник Node 22.23.4 и соответствующий npm 10.9.9 без глобального переключения NVM, чтобы не мешать параллельным проектам. Перед продакшен-релизом toolchain на CI проверяется по каноническому реестру.
