# Контракт навигационной ткани сайта

Статус: **рабочий архитектурный владелец**  
Маршрут продукта: статьи → контекстные связи → `/map/`  
Дата фиксации: 2026-07-27

## 1. Назначение

Этот документ определяет единственную архитектуру смысловых связей между материалами сайта «Господь Бог — Сила Моя».

Система решает три разные задачи и не смешивает их:

1. **Навигация серии** — предыдущая/следующая часть, содержание и прогресс.
2. **Контекст статьи** — внешние материалы, которые помогают понять тему.
3. **Атлас исследований** — глобальное исследование библиотеки через карту и список.

## 2. Неприкосновенная граница серии

Существующий series engine является единственным владельцем:

- предыдущей части;
- следующей части;
- порядка частей;
- прогресса серии;
- оглавления серии;
- спутников, глав и вложенных материалов.

Новый блок связей **никогда** не повторяет:

- `seriesPrev`;
- `seriesNext`;
- другие части той же серии;
- хаб серии, если он уже видим в серийном chrome;
- спутники, уже показанные в рельсе или листе серии.

Правило продукта:

> Сначала существующая серия. Затем только полезные внешние связи.

## 3. Поверхности системы

### 3.1. Внутри самостоятельной статьи

Название блока: **«Продолжить исследование»**.

Блок отвечает на вопрос:

> Какие материалы естественно расширяют именно эту самостоятельную статью?

### 3.2. Внутри статьи серии

Название блока: **«Контекст и связи»**.

Блок отвечает на вопрос:

> Какие внешние материалы помогают понять эту часть, не дублируя маршрут серии?

### 3.3. Входящие упоминания

Название раскрытия: **«Где используется этот материал»**.

Это отдельный вторичный слой. Он не конкурирует с продолжением серии и не выводится двумя техническими блоками «исходящие/входящие».

### 3.4. Глобальная карта

Пользовательское название: **«Атлас исследований»**.  
Короткое название в навигации: **«Атлас»**.

Атлас отвечает на вопрос:

> Как текущий материал связан с темами, сериями, людьми, картами и соседними исследованиями?

## 4. Владение фактами

| Факт | Единственный владелец |
|---|---|
| Название, URL, описание, обложка | content collection / route registry |
| Порядок серии | series registry / shared series config |
| Реальная ссылка в теле статьи | автоматически извлечённый индекс |
| Редакционное объяснение связи | каталог редакционных отношений |
| Обратная связь | вычисляется |
| Карточки статьи | вычисляются |
| Узлы и статистика Атласа | вычисляются |
| Координаты карты | build artifact |

`data/links-graph.json` рассматривается как переходный источник и не должен оставаться ручным владельцем метаданных узлов.

## 5. Категории отношений

Публичный словарь должен быть коротким и человекочитаемым.

### Структурные

- входит в цикл;
- материал цикла;
- справочник цикла;
- карта цикла.

### Содержательные

- даёт исторический контекст;
- развивает аргумент;
- объясняет понятие;
- сравнивает толкования;
- применяет вывод;
- предлагает другой взгляд;
- разбирает тот же текст.

### Использование

- цитирует материал;
- использует вывод;
- упоминает исследование.

В публичном интерфейсе запрещены подписи `source`, `target`, `edge`, `incoming`, `outgoing`, `backlink` и «ссылается на» без пояснения пользы.

## 6. Переходная модель до типизированного графа

Пока отношения хранятся парами ID:

- зеркальные записи объединяются;
- один target показывается один раз;
- направление не превращается в два визуальных блока;
- внутренняя серия исключается;
- показываются максимум четыре наиболее полезных внешних материала;
- Атлас получает уникальные пары рёбер.

## 7. Требования к HTML

- Все переходы существуют как настоящие `<a href>`.
- Навигационный блок использует `<nav aria-labelledby>`.
- Раскрытие входящих упоминаний использует настоящий `<button>` с `aria-expanded`.
- Интерактивная карта имеет синхронное текстовое представление.
- WebGL/SVG не является единственным способом открыть материал.

## 8. Progressive enhancement

### Статья

Содержимое блока должно быть доступно без JavaScript после завершения build-time миграции.

Переходный runtime допускается только как временная ступень и обязан:

- удалять старые дублирующиеся `.gbx-backlinks`;
- не создавать layout shift после стабилизации;
- не ломать статью при ошибке загрузки графа;
- не вмешиваться в series navigation.

### Атлас

Сервер отдаёт:

- заголовок и описание;
- доступный список тем;
- список материалов;
- реальные ссылки.

JavaScript добавляет:

- панорамирование;
- масштабирование;
- focus mode;
- фильтры;
- semantic zoom;
- боковую панель.

## 9. Запрещённые решения

- повтор следующей части в related-блоке;
- две одинаковые коробки «ссылается / ссылаются»;
- ручные публичные счётчики;
- URL, построенные из ID догадкой;
- одинаковая generic-карточка во всех авторских сериях;
- постоянная физическая дрожь графа;
- центральное modal-окно, закрывающее карту;
- drag как единственный способ управления;
- мобильная версия как просто уменьшенный desktop.

## 10. Критерии приёмки

- 0 повторов `seriesPrev/seriesNext`.
- 0 зеркальных визуальных дублей.
- 0 guessed URL.
- 0 hardcoded публичных счётчиков.
- Все видимые ссылки доступны в списочном представлении.
- Focus URL восстанавливается после перезагрузки.
- Zoom, pan и центрирование работают мышью, touch и кнопками.
- `prefers-reduced-motion` соблюдается.
- Блок статьи выглядит как часть соответствующего визуального мира.

## 11. Этапы миграции

1. Премиальный переходный panel поверх текущего graph JSON.
2. Data-driven Атлас с уникальными рёбрами и реальными URL.
3. Типизированный каталог отношений.
4. Build-time projections для статей.
5. Удаление старого runtime injector и ручного графового SSOT.
6. Отдельная аудиторская карта для orphan/dead-end/unresolved diagnostics.
