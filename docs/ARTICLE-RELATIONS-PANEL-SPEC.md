# Спецификация блока связей внутри статьи

Статус: рабочая спецификация внедрения  
Компонент: `ArticleRelationsPanel` / переходный `relationship-panel.js`

## 1. Цель

Заменить технические блоки:

- «Эта статья ссылается на»;
- «На эту статью ссылаются»;

на один спокойный, премиальный и содержательный модуль.

## 2. Название

- Самостоятельная статья: **Продолжить исследование**.
- Статья серии: **Контекст и связи**.

Series engine остаётся единственным владельцем перехода к следующей части.

## 3. Порядок на странице

### Статья серии

1. основной текст;
2. существующая навигация серии;
3. блок «Контекст и связи»;
4. карточка автора и нижние служебные элементы.

### Самостоятельная статья

1. основной текст;
2. блок «Продолжить исследование»;
3. карточка автора / related navigation.

## 4. Состав первого экрана

На первом уровне показываются:

- заголовок;
- короткое объяснение;
- до трёх или четырёх уникальных материалов;
- одна ссылка «Открыть окружение в Атласе».

Каждый материал содержит:

- relation label;
- название;
- описание в одну–две строки;
- тип материала и время чтения при наличии;
- один цельный `<a>` без вложенной кнопки.

## 5. Визуальная модель

Это **одна поверхность**, а не контейнер с вложенными белыми карточками.

Требования:

- тонкая рамка;
- почти отсутствующая тень;
- типографическая иерархия вместо множества коробок;
- relation label маленький, uppercase, с увеличенным letter-spacing;
- serif для названия;
- sans-serif для метаданных;
- мягкие разделители между строками;
- один акцентный материал допускается, но без огромной обложки;
- светлая, тёмная и sepia темы;
- theme adapters через CSS variables.

## 6. Адаптивность

### Desktop

- ширина совпадает с колонкой статьи;
- первая связь может быть чуть крупнее;
- остальные идут компактными строками;
- ссылка в Атлас располагается в нижней полосе.

### Mobile

- одна колонка;
- весь row является touch target;
- описание ограничено двумя строками;
- никаких горизонтальных каруселей;
- метаданные переносятся без горизонтального overflow.

## 7. Фильтрация серии

Перед рендерингом исключаются:

- текущая статья;
- предыдущая часть;
- следующая часть;
- остальные элементы того же `series/group`;
- уже видимые спутники/главы;
- повторяющиеся target ID;
- неопубликованные и отсутствующие URL.

Если после фильтрации ничего полезного не осталось, блок не показывается.

## 8. Переходная логика ранжирования

До типизированного relation catalog:

1. внешний тематический материал;
2. справочник или карта;
3. каталог;
4. остальные уникальные связи.

Хабы и каталоги не должны автоматически вытеснять содержательную статью.

## 9. Входящие упоминания

До появления контекста цитирования входящие и исходящие рёбра не показываются отдельными секциями.

После build-time extraction появляется disclosure:

**Где используется этот материал · N публикаций**

В раскрытии показываются:

- название публикации;
- ближайший heading;
- короткий контекст упоминания;
- настоящий переход.

## 10. Поведение при ошибке

При ошибке загрузки данных:

- основной текст и series navigation не меняются;
- блок просто отсутствует;
- в production не выводится техническая ошибка;
- в development допускается `console.warn` с префиксом `[relations]`.

## 11. Доступность

- `<nav aria-labelledby="...">`;
- уникальный ID заголовка;
- описательные названия ссылок;
- видимый focus;
- touch target не меньше 44px в переходной реализации;
- reduced-motion убирает декоративное движение;
- визуальный мини-граф, если появится, дублируется списком.

## 12. Print

- навигационная ссылка в Атлас скрывается;
- декоративные элементы отключаются;
- содержательные названия связанных материалов могут сохраняться компактным списком;
- блок не должен разрывать страницу внутри одной строки.

## 13. Аналитика

Допустимые события:

- `relation_open`;
- `relation_atlas_open`;
- `relation_mentions_expand`.

Запрещено менять ranking персональными скрытыми профилями на первом этапе.
