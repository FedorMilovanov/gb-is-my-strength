## 0. ГЭПЫ ФАЗЫ 1 — каркас есть, душа не вся (чинить В ПЕРВУЮ ОЧЕРЕДЬ)

### 0.1 ❗ Прогресс серии: заменить зашитый на честный (КЛЮЧЕВОЕ)

Сейчас % серии = `data-gbs2-done-min` из разметки: читатель, открывший
часть 2 ПЕРВОЙ, видит «18% серии прочитано» — это ложь. Галочки
`.gbs2-check` в рельсе/шторке существуют в CSS (`.gbs2-part.gbs2-done`),
но JS НИКОГДА не ставит `gbs2-done` — мёртвый UI.

Требуемая модель (из эталона-макета):
- localStorage `gb-series-progress:<seriesKey>` = `{slug: percent}`;
  seriesKey брать из нового атрибута `data-gbs2-series="dzhon-gill"`
  на body (добавить на все 7 страниц);
- слушать скролл текущей части: percent = max(сохранённый, текущий);
  «прочитано» = percent ≥ 90;
- % серии = Σ(минуты части × min(percent,100)/100) / total — данные
  по частям уже есть в series.json (readingTime);
- галочка: ставить `gbs2-done` на `.gbs2-part`/`.gbs2-sheet-part`,
  чей slug в хранилище ≥90. Slug каждой ссылки определяется по href;
- частичный прогресс чужой части можно показать в title/aria-label;
- `data-gbs2-done-min` оставить как no-JS/первый-кадр фолбэк, но
  после init JS пересчитывает честно;
- кольцо при 100% серии: однократный пульс (transform scale,
  reduced-motion → нет) — «празднование» из утверждённого дизайна.

### 0.2 Тост «Продолжить с места, где остановились»

localStorage `gb-series-pos:<seriesKey>:<slug>` = `{y,pc,t}`.
Писать ТОЛЬКО после реального действия пользователя
(wheel/touchmove/клавиши-навигации) и y>120 — иначе нулевые
программные скроллы затирают позицию (баг, который мы уже ловили).
При заходе с y<200 и сохранённым y>500 — тост снизу:
«Вы остановились на NN% — Продолжить / ✕», автоскрытие ~9с,
Esc закрывает. На мобиле bottom выше капсулы gbs2-bbar.

### 0.3 «Осталось ~N мин»

- в рельсе под кольцом: остаток по ВСЕЙ серии (из честного прогресса);
- в мобильной капсуле: остаток по текущей части
  (`partMin × (100−pc)/100`, минимум 1 мин). Никаких «дочитаете к ЧЧ:ММ»
  — владелец ЯВНО отклонил (см. §4 анти-фичи).

### 0.4 Клавиатура ←/→

ArrowLeft/ArrowRight (без модификаторов, не в input/textarea) →
location.href соседней части. Переход заворачивать в
document.startViewTransition при поддержке (хук уже есть в site.js).
На краях серии — ничего (или мягкий тост «Это край серии»).

### 0.5 Свайп от края (тач) + peek-карточка + онбординг

Старт только от кромки 28px, порог 90px, вертикальный дрейф >70px =
отмена, обработчики passive. Peek-карточка соседней части
(обложка+номер+название) едет за пальцем (CSS-переменная сдвига).
Онбординг-подсказка «Свайп от края — соседняя часть» один раз,
localStorage `gbs2-swipe-tip-seen`, показывать через ~2.4с, прятать
через ~5с.

### 0.6 Автоскрытие мобильной шапки и капсулы при чтении

Вниз >40px накопленного дельты (аккумулятор, не сырой dy) — спрятать
`.gbs2-mobile-head` (translateY(-110%)) и `.gbs2-bbar` (translateY вниз);
любой скролл вверх — вернуть. Активировать только после реального
скролла пользователя и y>160. transition ~.3s cubic-bezier(.22,1,.36,1).

### 0.7 Дизайн-фолбэки ВСЕХ обложек (onerror)

Сейчас битая/незагруженная картинка = пустой блок. Требуется:
- миниатюры рельса/шторки: onerror → класс на контейнер → градиент
  в цвет серии + крупный номер части по центру;
- hero: onerror → «фронтиспис» — римская цифра по центру с
  орнаментными линиями, аспект блока снижается (21/6);
- next-карточки: постоянная цветная подложка + лёгкий узор под
  background-image (виден только если картинки нет).

### 0.8 Мини-сводка серии у next-карточек

Над `.gbs2-next`: строка точек частей (заполнена/наполовину/пустая
по честному прогрессу) + фраза «После этой части останется … —
вы почти у цели» / «…серия будет прочитана полностью».

## 1. ОБЩЕСАЙТОВЫЙ СЛОЙ (вне серий; владелец: «а обычные страницы??»)

Часть уже сделана фазой 1 (gbs-paper, text-wrap на h1–h3) — остальное:

1.1 **text-wrap: pretty** на абзацы статей (`.article-body p`) —
     одна строка, каскадный no-op для старых браузеров.

1.2 **TTS «Слушать статью»** — минималистичный sticky-плеер
     (утверждённый дизайн в макете article-sitewide):
     круглая кнопка ▶/⏸ с кольцом прогресса по абзацам, скорость
     1×/1.25×/1.5× (localStorage), подсветка читаемого абзаца
     (`.gbx-speaking`) + scrollIntoView center, пауза = продолжение
     с того же абзаца, speechSynthesis.cancel() на beforeunload.
     ru-RU. Если 'speechSynthesis' нет — кнопку не рендерить вовсе.
     Источник текста: p внутри article-body, исключая figcaption,
     quiz, sources, author-card.

1.3 **Крошка-прогресс в топнаве**: в существующий .article-topnav
     добавить «Раздел · {текущая H2}» (scroll-spy уже есть в GBS —
     переиспользовать механику) + aria-live=polite анонс смены раздела
     (визуально скрытый span) — это же закрывает A11y-требование.

1.4 **Skip-link** «К содержанию» первым фокусируемым элементом на
     страницах статей (если ещё нет) + focus-visible стили на
     все новые контролы (WCAG 2.4.11). Цель Lighthouse A11y ≥95.

1.5 **Эпиграф-зачин** (компонент по запросу): построчное проявление
     цитаты (овнер принял; применять там, где редактор разметит
     `.gbx-epi` — НЕ автоматом).

1.6 **Pull-quote с прорисовкой линии** (компонент по запросу,
     IntersectionObserver once, threshold .5).

1.7 **Scroll-driven animations (CSS)**: прогресс-бар чтения и
     reveal-эффекты перевести на animation-timeline там, где
     @supports — JS остаётся фолбэком (Chrome 115+; ваш контракт
     браузеров требует фолбэк, он уже есть).

1.8 **Сжимающийся hero** для обычных статей с обложкой
     (CSS animation-range 0–360px + JS-фолбэк).

1.9 **Параллельные места Писания**: `.gbx-verse` с data-verse →
     поповер с текстом стиха из ЛОКАЛЬНОГО data/verses.json
     (только используемые на сайте стихи, Синодальный). Без API.
     Разметка — только редакционная.

1.10 **Слово оригинала**: `.gbx-ow` с data-ow → карточка
     (оригинал ивр/греч — шрифты Noto уже в repo, транслит,
     серьёзное определение, источник HALOT/BDAG/TDOT).
     СТРОГО ручная разметка ОДНОГО важного вхождения; ключи без
     статьи в словаре data/original-words.json не активируются.
     Владелец: «застраховаться от лишних срабатываний».

1.11 **«Следующая по теме» с этичным отсчётом** (для одиночных
     статей; для серий — next-карточка уже есть): кольцо 8с
     ТОЛЬКО подсвечивает кнопку, переход исключительно по клику,
     Esc/«Остаться» отменяют, reduced-motion → без отсчёта.

## 2. УТВЕРЖДЁННЫЙ БЭКЛОГ ФИЧ (selected-pack; после §0–§1)

2.1 **Карта пути героя** (StoryMap-паттерн): SVG-силуэт Англии,
    маршрут Кеттеринг→Хайэм-Феррерс→Лондон, точки ↔ список остановок
    с синхронной подсветкой. Для биографий. Эталон — selected-pack.html.

2.2 **Шторка «тогда/сейчас»** (Juxtapose): pointer events,
    clip-path inset, ручка; для пар изображений (рукопись↔печать).

2.3 **Выдели-и-поделись v2**: тулбар над выделением с КНОПКАМИ
    СОЦСЕТЕЙ СРАЗУ (Telegram t.me/share/url, VK vk.com/share.php,
    WhatsApp wa.me/?text=) + копировать цитату + ссылка с Text
    Fragment (#:~:text=). Мини-превью цитаты в тулбаре. Владелец:
    системный share-диалог НЕ устраивает — соцсети должны быть
    в один клик. Интегрировать с существующим share-механизмом site.js.

2.4 **Обратные ссылки + карта связей** (стратегическая, 3 этапа):
    (а) build-скрипт собирает граф внутренних ссылок статей →
    data/links-graph.json; блок «На эту статью ссылаются / Эта статья
    ссылается на» внизу статей;
    (б) страница-карта связей сайта (2D SVG, hover подсвечивает рёбра);
    (в) 3D-страница на тех же данных (three.js) — отдельным решением
    владельца, НЕ сейчас. Сейчас строить (а), закладывая JSON-формат
    {nodes:[{id,title,url,group}],edges:[[a,b]]}.

2.5 **Сохранить серию офлайн**: кнопка в рельсе → SW (sw.js уже есть)
    прекеширует все части серии + обложки; состояние «✓ Доступно
    офлайн» в localStorage + проверка наличия в Cache API.

2.6 **Типограф на сборке**: scripts/typograf.js (запуск как
    cache-bust): «ёлочки»/„лапки“, тире, диапазоны через en-dash,
    неразрывные после коротких предлогов/союзов, …; НЕ трогать
    <code>, <pre>, атрибуты, JSON-LD. Сухой прогон с диффом перед
    первым реальным применением. Примечание: _audit-deep.js T3 уже
    ИЩЕТ дефис-вместо-тире — типограф будет ЧИНИТЬ.

2.7 **Ctrl+K секция «Вы читали»**: в command-palette первой секцией
    «Продолжить?» — до 3 недочитанных (из gb-series-progress + позиций
    одиночных статей, когда появятся), кольцо % + «осталось ~N мин».

2.8 **Нативный аккордеон**: FAQ/«Разбор заблуждений» перевести на
    <details name="…"> группы; плавная высота через
    @supports (interpolate-size: allow-keywords) — Chromium;
    остальным — мгновенно (норм деградация).

## 3. ИНВАРИАНТЫ ДИЗАЙНА (выстраданы итерациями; нарушение = регресс)

3.1 Все направляющие линии меряются ОТ РЕАЛЬНЫХ ЦЕНТРОВ элементов
    (getBoundingClientRect), никаких магических отступов/процентов.
    (Фаза 1 это уже соблюдает — не сломать.)
3.2 Заливка metro-линии TOC всегда заканчивается РОВНО на центре
    активной точки. Никакой интерполяции «к следующей станции».
    Плавность — CSS transition высоты заливки.
3.3 Scroll-spy: кэш позиций (rect+scrollY), инвалидация на
    resize/шрифт/ResizeObserver; низ страницы → последняя секция,
    верх → первая; гистерезис ~12px на стыках.
3.4 Автоподскролл активного пункта TOC — только scrollTop
    контейнера, НИКОГДА scrollIntoView (дёргает страницу).
3.5 Геометрия точек TOC фиксированная: состояния меняют только
    цвет/тень/scale.
3.6 Кинетическая цифра не делит пространство с текстом: резерв
    колонки на ≥1024px, скрыта ниже. Никаких масок-обрезок глифа.
3.7 View Transitions: view-transition-name НЕ в статическом CSS —
    только на время перехода (вешает и снимает JS).
3.8 Один rAF-тик на скролл на страницу; классы перекрашиваются
    только при смене активной секции, покадрово — только линия/бары.
3.9 Тосты/подсказки не перекрывают элементы управления (z-index
    ниже шторки; на мобиле bottom выше капсулы).
3.10 Resume-позиция пишется только после реального скролла
    пользователя (флаг по wheel/touchmove/клавишам) и y>120.
3.11 iOS: 100dvh парой к 100vh; лок скролла шторки —
    SiteUtils.lockScroll (body overflow:hidden в iOS НЕ работает);
    -webkit-overflow-scrolling:touch в скролл-зонах;
    touch-action:manipulation на кнопках; safe-area-inset снизу.
3.12 color-mix на критичных поверхностях — с простым значением
    строкой выше (Safari <16.2).
3.13 У КАЖДОЙ картинки интерфейса — дизайн-фолбэк (см. §0.7).
3.14 prefers-reduced-motion отключает: параллакс, кинетику, зерно,
    отсчёты, VT, автоанимации — функциональность остаётся.
