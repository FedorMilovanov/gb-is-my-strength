## 1. Что меняем в визуальной логике главы

Текущий `cover-07-vsehib.svg` — временный брендовый visual, а не исторический источник. Он может остаться только как fallback для навигационной системы серии до тех пор, пока не интегрированы архивные байты. Финальная глава должна открываться реальным историческим изображением и дальше чередовать людей, документы и институциональный контекст.

Нельзя заменять старый SVG другой абстрактной картинкой. Задача — **не редизайн ради редизайна, а визуальная доказательность**.

## 4. Идеальная последовательность изображений в странице

1. **Hero:** точное событие/место/участники октября 1944 (`HERO-01`) — без текста поверх фотографии.
2. **До совещания:** один документ 1943–1944 (`FIG-03`), показывающий военный и административный контекст.
3. **Люди:** президиум ВСЕХиБ 1945 (`FIG-02`) с нормальной идентификационной подписью.
4. **Первичный источник:** факсимиле страницы «Братского Вестника» №1, 1945 с протоколом/резолюцией/Положением — выбрать конкретную страницу после page-level проверки.
5. **Инфографика (не псевдофото):** карта географии 45 делегатов, только если данные списка нормализованы; это может быть SVG, созданный нами из проверенной географии, с пометой `редакционная карта`.
6. **1945:** факсимиле/документ о Дне единства или соглашении с ХВЕ из БВ №3, если визуально проверено.

## 5. Стандарт подписи

Каждая историческая иллюстрация должна иметь:

- **Что изображено** — без художественного домысла.
- **Кто** — только проверенные лица.
- **Где** — если известно.
- **Когда** — точная дата или честный диапазон/`ок.`.
- **Источник** — архив/издание/MASTER provenance.
- **Статус** — `оригинальная фотография`, `факсимиле`, `редакционная карта`.
- **Права/атрибуция** — отдельное поле или короткая строка, если режим использования установлен.

Пример структуры, не финальная подпись:

> Президиум Всесоюзного Совета евангельских христиан и баптистов, 1945. Идентификация участников по архивной подписи MASTER ARCHIVE CATALOG. Источник и режим использования — после проверки исходного файла.

До проверки исходного файла последнюю фразу нельзя скрывать и нельзя публиковать как окончательную подпись.

## 6. Техническая спецификация production images

После получения оригинальных байтов:

- сохранять master без destructive overwrite;
- web derivative: WebP/AVIF по существующему пайплайну сайта;
- hero target: не менее 1600 px по длинной стороне, если оригинал позволяет; не апскейлить слабый скан ради формального числа;
- article figure: responsive `srcset` при наличии инфраструктуры; иначе один качественный WebP + исходный master вне web-public при необходимости;
- не обрезать лица/документальные поля ради «киношного» кадра;
- для документов сохранять читаемые поля страницы;
- `alt` описывает содержание, `figcaption` даёт исторический контекст — это разные задачи;
- OG image может быть аккуратно кадрированной версией реального hero, но без подделки исторического кадра и без AI-дорисовки краёв.

Рекомендуемый web path после проверки:

`/images/baptisty-rossii/vsehib-1944/`

Имена без дат Telegram-экспорта:

- `vsehib-1944-conference.webp`
- `vsehib-1945-presidium.webp`
- `vsehib-1943-1944-military-appeal.webp`
- `bratskiy-vestnik-1945-01-<page>.webp`

Оригинальные архивные имена должны сохраняться в media manifest, чтобы не потерять цепочку происхождения.

## 7. Media manifest — обязательные поля

Перед интеграцией каждый файл получает запись:

```text
web_path
archive_photo_path
master_sheet_row
album_id
message_id
historical_date
caption_verified
visual_content_verified
source_file_verified
rights_status
crop_notes
used_as
```

Никакое изображение не получает `used_as=hero` только потому, что у него `Article ready=YES`. Требуются одновременно `visual_content_verified=true` и `source_file_verified=true`.

## 8. Текущий blocker — не маскировать

Каталог доступен и позволяет выбрать кандидатов, но некоторые старые `Source HTML`-ссылки из MASTER сейчас не разрешаются текущим Drive-доступом, а поиск по внутреннему Telegram basename не возвращает отдельный Drive object. Поэтому **байты ещё не скопированы в web repo**.

Это не повод брать внешнюю картинку или генерировать замену. Правильный следующий шаг — восстановить конкретные оригинальные байты из канонического фотоархива/Telegram export и только после этого сделать media commit.
